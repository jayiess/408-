# 3.1 内存管理概念

## KP1 内存管理的五大功能

**核心结论**：内存管理是 OS 对内存空间的**组织、分配、回收、地址映射**。原因是主存装不下所有进程及其数据，必须划分 + 动态分配。

五大功能（背这五条）：

| 功能    | 内容                             |
| ----- | ------------------------------ |
| 分配与回收 | 记录内存使用状态与空闲区，进程创建时分配、终止时回收     |
| 地址转换  | ==把用户程序的**逻辑地址**动态转成**物理地址**== |
| 空间扩充  | 用虚拟存储技术，让进程用上远大于物理内存的地址空间      |
| 内存共享  | 多进程安全访问同一块物理内存（共享库、进程通信）       |
| 存储保护  | 各进程只能访问自己被授权的区域，互不干扰           |

**易错点**：「内存空间的扩充」==是**逻辑上**扩充（虚拟存储==），不是真加内存条。

**易错点**：多道程序环境才是内存管理的必要性来源。单道程序把内存整块给唯一进程即可，几乎不需要管理。

## KP2 从源程序到执行：编译、链接、装入（真题）

**真题**：2011 考过编译、链接和装入阶段各自的工作内容。

**核心结论**：用户源程序变成内存中可执行的程序，走三步：

| 步骤 | 谁做 | 做什么 | 产物 |
| --- | --- | --- | --- |
| 编译 | 编译程序 | 翻译源代码 | 若干**目标模块** |
| 链接 | 链接程序 | 合并目标模块 + 所需库函数 | 一个完整的**装入模块** |
| 装入（加载） | 装入程序 | 把装入模块载入内存并启动 | 运行中的进程 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-1.jpg]]（图 3.1）

**易错点**：==**地址重定位不是编译阶段的事**。编译只管翻译，地址调整发生在链接（相对地址拼接）和装入（逻辑地址→物理地址）。==

**易错点**：库函数是在**链接**阶段合并进来的，不是编译阶段。

## KP3 逻辑地址与物理地址（真题）

**真题**：2023 考过进程虚拟地址空间的特点。

**核心结论**：

- **逻辑地址（相对地址 / 虚拟地址）**：每个目标模块编译后都从 0 号单元开始编址。链接时把各模块的相对地址依次拼成一个统一的、**从 0 开始**的逻辑地址空间。32 位系统的范围是 $0 \sim 2^{32}-1$。
- ==进程运行时用的**全是逻辑地址**==，程序员只关心逻辑地址，==底层内存管理对其**完全透明**。==
- **物理地址空间**：主存中所有物理存储单元的集合，是==地址转换的最终目标，取指和访存最终都得用它。==

两种转换时机：

| 时机    | 名称                   | 说明                   |
| ----- | -------------------- | -------------------- |
| 装入时转换 | 地址重定位                | 早期系统                 |
| 运行时转换 | ==由 **MMU** 硬件自动完成== | ==现代虚拟内存系统，查当前进程页表== |

**核心结论（易错重点）**：==**不同进程可以拥有完全相同的逻辑地址**==，因为各自有独立的逻辑地址空间，会被映射到主存的不同位置。

**易错点**：==逻辑地址空间的大小由**地址位数**决定==，与实际物理内存多大无关。32 位就是 4GB 逻辑空间，哪怕只插了 512MB 内存。

**易错点**：==MMU 是**硬件**部件==，不是操作系统的一段程序。==页表由 OS 建立和维护==，查表转换由 MMU 做。

## KP4 三种链接方式

**核心结论**：按链接发生的时机分三种。

| 方式      | 时机                                    | 特点                                |
| ------- | ------------------------------------- | --------------------------------- |
| 静态链接    | ==运行**之前**，一次性链成完整装入模块，此后不再拆分==       | 简单；改一个模块要重建整个装入模块，且无法共享           |
| 装入时动态链接 | ==**装入内存时**边装入边链接==，遇到外部调用就立刻找到并装入该模块 | 便于修改更新（只换被改的模块）；便于目标模块共享          |
| 运行时动态链接 | ==**执行过程中**==真正要调用某个未装入的模块时才装入并链接     | ==装入更快、更省内存；**用不到的模块根本不装入也不链接**== |

静态链接要完成两项关键操作：

1. **地址调整（相对地址修改）**：==各模块编译后都从 0 起址，链接时按其在装入模块中的实际位置统一加偏移量==。模块 A 长为 L，紧随其后的模块 B 内部所有地址都加 L。
2. **外部符号解析（变换外部调用符号）**：把模块间引用的外部符号换成确定地址。==`CALL B` 里的符号 B 被替换为模块 B 的起始地址 L。==

**易错点**：三种方式的**共享能力**差别是考点。静态链接每个程序都带一份完整副本，**无法共享**；两种动态链接才能让多个程序共享同一个目标模块。

**易错点**：运行时动态链接省内存的原因是==「**没用到的模块不装入**」==，不是「装入的模块更小」。

## KP5 三种装入方式与两种重定位（高频）

**核心结论**：

| 装入方式    | 适用环境            | 地址转换时机         | 重定位类型           | 能否在内存中移动 |
| ------- | --------------- | -------------- | --------------- | -------- |
| 绝对装入    | **==只适用单道程序==** | 编译/汇编时就用绝对地址   | 无需转换（逻辑地址=物理地址） | 不能       |
| 可重定位装入  | 多道程序            | **装入时**一次性全部转换 | ==**静态重定位**==   | **不能**   |
| 动态运行时装入 | 多道程序            | **指令真正执行时**才转换 | ==**动态重定位**==   | **能**    |

静态重定位（图 3.2a）的限制：

- 必须在装入前**一次性获得全部所需内存**，不足则装不进去。
- 装入后整个运行期间**不能移动位置，也不能动态申请额外内存**。

动态重定位（图 3.2b）的机制与优点：

- 靠一个**重定位寄存器**存放模块在内存中的起始物理地址，程序里保留的仍是逻辑地址，物理地址由硬件运行时算出。
- 优点：支持程序在内存中移动 → 便于 OS 做**紧凑**、**减少外部碎片**；内存分配更灵活，运行期可调整布局。

**易错点**：==静态 / 动态重定位的分水岭是「**转换发生在装入时还是执行时**」。判「能不能移动」「能不能做紧凑」一律看是不是动态重定位。==

**易错点**：绝对装入里==程序员也可以直接指定绝对地址==，==但通常是由编译器/汇编器把**符号地址**（变量名、函数名）转成绝对地址。==

**易错点**：可重定位装入要求分到一块**连续**内存区域，这是连续分配方式的共性约束。

## KP6 内存保护的两种硬件方法（真题）

**真题**：2009 考过分区分配的内存保护措施。

**核心结论**：目标是既防用户进程破坏 OS，又防用户进程互相干扰。两种做法：

1. **上、下限寄存器**：CPU 中设一对寄存器，存放进程在内存中的下限和上限地址。每次访存，硬件自动把地址与两者比较，判断是否越界。
2. **重定位寄存器 + 界地址寄存器**：先比后加。

方法 2 的判定顺序（记死）：

```
逻辑地址 < 界地址寄存器（限长）？
  ├─ 否 → 越界中断
  └─ 是 → 物理地址 = 逻辑地址 + 重定位寄存器（基址）→ 访存
```

==一句话口诀：**重定位寄存器用来「加」，界地址寄存器用来「比」**。==

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-3.jpg]]（图 3.3）

**核心结论（易错重点）**：==这两个寄存器的**加载必须用特权指令**==，仅内核有权限。==用户程序无法篡改，这才是保护有效的根本原因。==

**易错点**：别把两个寄存器的作用配反。==重定位寄存器 = 基地址寄存器==（起始物理地址）；==界地址寄存器 = 限长寄存器==（**地址空间长度**，不是结束地址）。

**易错点**：==越界检查在**加基址之前**做==，==比的是逻辑地址和长度==，不是物理地址和上限。

## KP7 内存共享与可重入代码（含计算）

**核心结论**：==**只有只读区域才可以共享**==。**可重入代码（纯代码）** 允许多进程同时访问但不允许任何进程修改；每个进程必须配 **独立的私有数据区**，写操作只落在私有数据区，共享代码段始终不变。

教材例题（会算就行）：40 用户同时运行同一文本编辑程序，代码区 160KB、数据区 40KB。

| 情形 | 内存需求 |
| --- | --- |
| 不共享代码 | $(160\text{KB}+40\text{KB}) \times 40 = 8000\text{KB}$ |
| 代码可共享 | $160\text{KB} + 40\text{KB} \times 40 = 1760\text{KB}$ |

**共享的实现开销对比**（这是分页 vs 分段的经典差别）：

| 系统         | 页面/段大小          | 共享代码需要的表项数                                  |
| ---------- | --------------- | ------------------------------------------- |
| 分页（页面 4KB） | 代码 40 页、数据 10 页 | 每个进程页表要 **40 个页表项**指向同一组共享页框，外加 10 个私有数据页表项 |
| 分段         | 代码段 160KB       | 每个进程段表只要 **1 个段表项**，记起始地址和段长                |

**易错点**：==分页**也能**共享，只是不方便（表项多）。别答成「分页不能共享」。==

**易错点**：共享的前提是代码不被修改，==所以共享段/共享页必须置为**只读**==。可修改的数据区一律私有。

## KP8 内存管理方式的演进脉络

**核心结论**：这条链子能串起整章，每一种方式都是为了克服前一种的不足。

```
单一连续分配（单道）
  → 固定分区分配（多道，但内部碎片 + 大作业装不进）
  → 动态分区分配（按需分配，但外部碎片）
  → 离散分配：分页（消除外部碎片，提高利用率）
  → 分段（为满足程序逻辑结构、段级共享与保护）
  → 段页式
```

两条不同的驱动力（别混）：

| 演进方向        | 驱动力                                  |
| ----------- | ------------------------------------ |
| 连续 → 离散（分页） | ==**提高内存利用率**==，消除外部碎片，站在系统角度        |
| 分页 → 分段     | ==满足**用户编程需求**==：逻辑结构、段级共享与保护，站在用户角度 |

**易错点**：分段不是为了提高内存利用率而生的，它是为方便编程、共享和保护。提高利用率是分页的目标。

## KP9 单一连续分配

**核心结论**：内存分**系统区**（低地址，只给 OS）和**用户区**（只放一道用户程序，独占整个用户区）。

| 优点 | 缺点 |
| --- | --- |
| 结构简单、**无外部碎片**、**无须内存保护**（内存里只有一道程序） | 只适用单用户单任务 OS；**有内部碎片**；内存利用率极低 |

**易错点**：单一连续分配是**唯一不需要内存保护机制**的方式，原因是内存中始终只有一道用户程序。

**易错点**：它有内部碎片（用户区没用满的部分），没有外部碎片。

## KP10 固定分区分配

**核心结论**：**最简单的多道程序存储管理方式**。把用户内存划成若干**大小固定**的分区，**每个分区只装一道作业**。

两种划分方法：

| 划分 | 问题 |
| --- | --- |
| 分区大小相等 | 程序过小浪费空间，过大装不进，缺乏灵活性 |
| 分区大小不等 | 多个小分区 + 适量中等 + 少量大分区，**适应性更好** |

管理数据结构：==**分区使用表**（通常按分区大小排序），表项含**始址、大小、状态（是否已分配）**。==

| 操作  | 做法                                     |
| --- | -------------------------------------- |
| 分配  | 检索表，找一个够大且未分配的分区，状态置「已分配」；找不到就**拒绝分配** |
| 回收  | 只需把对应表项状态置「未分配」                        |

两个固有问题：① ==作业大于所有分区则**无法装入**==；② 作业小于分区仍占整个分区，产生**内部碎片**。

**易错点**：==固定分区**无外部碎片、有内部碎片**。内存利用率低的原因是每个分区只能被一个作业独占，不能多进程共享同一分区。==

**易错点**：回收极简单（改个状态位），**不需要合并分区**。合并是动态分区才有的事。

> 固定大小的分区造成内部碎片，适应程序大小的分区造成外部碎片

## KP11 动态分区分配的原理、外部碎片与紧凑

**核心结论**：动态分区分配（= **可变分区分配**）==按进程实际需求分配一块**大小恰好匹配**的连续空间，==因此系统中**分区的数目和大小都随装入/释放动态变化**。

**外部碎片**：随着进程反复装入与释放，内存里积累大量分散的小空闲块，可用总量够但**没有足够大的连续块**，利用率下降。

| 碎片 | 出现在 | 定义 |
| --- | --- | --- |
| **内部碎片** | 固定分区、分页 | 分配给进程但**没用完**的空间 |
| **外部碎片** | 动态分区 | 分区**之间**那些太小、无法利用的空闲块 |

**紧凑（拼接）技术**：OS 周期性移动进程，把所有空闲块合并成一个连续区域。

- 前提：==必须支持**动态重定位**==（否则移动后地址就错了）。
- 代价：==**开销大**。==
- 类比：像 Windows 磁盘碎片整理，但**紧凑作用于主存，碎片整理作用于外存文件系统**。

**易错点**：内部/外部碎片的定义方向要背准。「分配出去没用完」是内部，「没分配出去但用不上」是外部。

**易错点**：==紧凑的前提是动态重定位，静态重定位的系统做不了紧凑。这是 KP5 和本条的联动考点。==

**易错点**：==三种连续分配方式的共同特点是**用户程序在主存中连续存放**。==

## KP12 动态分区的回收：四种合并情形（真题）

**真题**：2017 考过动态分区分配的内存回收方法。

==**核心结论**：系统维护一张**空闲分区链（表）**，通常**按起始地址排序**。==

分配时：找到够大的空闲分区，若尺寸大于所需就**分割**，剩余部分（不小于最小分配单位）仍留在链中。

回收时按起始地址找插入位置，看相邻情况分四种：

| 情形 | 处理 |
| --- | --- |
| ① 与**前**一空闲分区相邻 | 两者合并，**更新前一分区的大小** |
| ② 与**后**一空闲分区相邻 | 两者合并，**更新后一分区的起始地址和大小** |
| ③ **前后都**相邻 | 三者合并，更新前一分区大小，**删除后一分区的表项** |
| ④ **都不**相邻 | **新建一个表项**（记起始地址和大小）插入链中 |

**易错点**：情形 ② 一定要改**起始地址**（回收区在前面，新块的起点变小了）；情形 ① 只改大小不改起址。这一对最容易配反。

**易错点**：只有情形 ③ 会**减少**表项数，情形 ④ 会**增加**表项数，① ② 表项数不变。

**易错点**：分割剩余部分时，若剩余太小（小于最小分配单位）就不再单独保留，直接一并分出去。

## KP13 基于顺序搜索的四种分配算法（真题高频）

**真题**：2019、2024 考过各种动态分区分配算法的特点；2010 考过最佳适应算法的分配过程。

**核心结论**：四个算法，先记「链表按什么排序」，再记「从哪开始找」。

| 算法 | 空闲分区链排序 | 查找起点 | 每次选中的分区 |
| --- | --- | --- | --- |
| 首次适应 First Fit | **按地址递增** | 每次都从**链首** | 第一个够大的 |
| 邻近适应 Next Fit（循环首次适应） | 按地址递增 | 从**上次结束位置**继续循环 | 第一个够大的 |
| 最佳适应 Best Fit | **按容量递增** | 链首 | **最小的**可用分区 |
| 最坏适应 Worst Fit | **按容量递减** | 链首 | **最大的**可用分区 |

各自的问题：

| 算法   | 优点                                         | 缺点                                       |
| ---- | ------------------------------------------ | ---------------------------------------- |
| 首次适应 | 优先用低地址，**保留高地址大空闲区**，利于后续大作业；回收时**无须重新排序** | 低地址积累小碎片；每次从链首查找，开销增加                    |
| 邻近适应 | 减少对低地址的重复扫描                                | ==**大空闲区分布不均**，难支持大作业，整体性能**通常不如首次适应**== |
| 最佳适应 | 尽量保留大空闲区                                   | 每次留下**极小的剩余块**，产生大量**外部碎片**，实际性能较差       |
| 最坏适应 | 试图避免生成小碎片                                  | 总是切最大块，**很快无法满足大作业**，性能同样不佳              |

**核心结论（结论题背这句）**：==**综合性能最好的是首次适应算法**==——查找简单高效、回收无须重排序、能保留高地址大空闲区，在开销、碎片控制、大作业支持之间取得最好平衡。

**易错点**：「最佳适应」名字最好听但**性能通常较差**，因为剩下的小块没人用。「最坏适应」也不佳。考「哪个最好」一律答**首次适应**。

**易错点**：只有**最佳/最坏适应**按容量排序，所以每次回收后都要**重新排序**；首次适应按地址排序，回收合并后天然有序。

**易错点**：邻近适应是由首次适应改进而来的，但改进失败——性能反而下降。

## KP14 基于索引搜索的三种分配算法（真题）

**真题**：2024 考过伙伴关系的概念。

**核心结论**：系统规模大时空闲分区链很长，顺序搜索效率低。索引算法的思想是：==**按空闲分区大小分类，每类建一条独立的空闲分区链，再用一张索引表统一管理**。==分配时按请求大小在索引表中定位链表，取头指针拿分区。==适合**大中型系统**。==

| 算法                | 做法                                                  | 特点                                                 |
| ----------------- | --------------------------------------------------- | -------------------------------------------------- |
| 快速适应 Quick Fit    | 按进程常用空间大小预先划成若干固定尺寸类别；① 找能容纳它的**最小类别**链表 ② 取链首第一个分区 | 优点：查找效率高、**不产生内存碎片**；缺点：==**回收时难以合并**分区，算法复杂、开销大== |
| 伙伴系统 Buddy System | 所有分区大小均为 $2^k$                                      | 见下                                                 |
| 哈希算法              | 以**空闲分区大小为关键字**建哈希函数和哈希表，表项存对应空闲分区链的**头指针**         | 按大小算哈希，直接定位链表                                      |

**伙伴系统**（重点，2024 真题）：

- 分配：为大小 $n$ 的请求（满足 $2^{i-1} < n \leqslant 2^i$）先查 $2^i$ 的空闲链。有则直接分配；否则依次查 $2^{i+1}, 2^{i+2}, \cdots$，找到后**不断二分**直到得到所需大小，其余部分按大小挂进对应空闲链。
- **伙伴的定义**：每个大小为 $2^k$ 的分区有**唯一**的伙伴——**大小相同、地址相邻（首尾相接）**的另一个分区。
- 回收：若某空闲分区与其**伙伴也空闲**，合并成 $2^{k+1}$ 的分区，并**继续向上尝试合并**，直到合并不了为止。

**易错点**：==伙伴的判据是「**同样大 + 地址相邻**」两条同时满足。地址相邻但大小不同的不是伙伴，不能合并。==

**易错点**：分配时是「向上找更大的块，再逐次二分」，不是直接切一个大块。二分产生的碎块要挂回各自的空闲链。

**易错点**：快速适应「不产生碎片」是因为按预设尺寸整块分配，代价是**回收时合并困难**——效率和合并能力的取舍。

## KP15 为什么要非连续分配

**核心结论**：连续分配的致命问题——**即使有超过 1GB 的空闲内存，只要没有连续的 1GB，需要 1GB 的作业就装不进来**。这就是外部碎片造成的。

非连续分配：把进程地址空间划成多个单元，允许这些单元**分散装入内存中互不相邻的区域**，彻底摆脱对连续空间的依赖。

- 收益：能利用零散空闲内存，显著提高内存利用率。
- 代价：==必须**额外维护逻辑单元与物理位置的映射关系**（页表/段表）==，带来存储开销。

两个维度的分类（这张表要能默写）：

| 划分单元大小  | 一次性全部装入 | 支持按需动态装入 |
| ------- | ------- | -------- |
| **固定**  | 基本分页    | **请求分页** |
| **不固定** | 基本分段    | **请求分段** |

**易错点**：「基本」= 运行前一次性装入全部单元；「请求」= 按需动态装入，这才是虚拟内存。别把基本分页当成虚拟内存。

## KP16 分页的基本概念与页内碎片

**核心结论**：**页框（页帧、物理块）**= 物理内存划成的若干大小相等的固定单元；**页面（页）**= 进程逻辑地址空间划成的、与页框**大小相同**的单元。系统**以页框为单位**分配内存。

| 对象 | 单元名 | 编号 | 起始编号 |
| --- | --- | --- | --- |
| 物理内存 | 页框 / 页帧 / 物理块 | 页框号 / 物理块号 | **0** |
| 进程逻辑空间 | 页面 / 页 | 页号 | **0** |

**核心结论（易错重点）**：分页**不产生外部碎片**，但产生**页内碎片（内部碎片）**——进程最后一页装不满，对应页框剩下未用空间。**每个进程平均产生约半页**的页内碎片。

**易错点**：分页形式上像等长的固定分区，但本质不同：**固定分区按作业整体分配，分页把进程和内存都按固定单元划分，分配以页为单位**。所以分页没有外部碎片。

**易错点**：「平均半页」是**每个进程**一个，不是每页都有。$n$ 个进程的页内碎片总量约 $n \times$ 半页。

## KP17 页面大小的权衡

**核心结论**：页面大小通常取 **2 的整数次幂**，为的是让页号和页内偏移能直接由二进制地址的高位/低位截取，便于地址转换。

页面大小要适中，两头都有代价：

| 页面过小 | 页面过大 |
| --- | --- |
| 页面数量增多 → **页表过长**，占用大量内存 | **页内碎片增多** |
| 地址转换开销增加 | 内存利用率下降 |
| 页面换入/换出效率降低 | — |

**易错点**：页面小的坏处是**页表变大**，不是「碎片变多」。页面小恰恰减少内部碎片。两个方向别配反。

## KP18 分页的逻辑地址结构（真题超高频）

**真题**：2009、2010、2013、2015、2017、2024 反复考分页系统的逻辑地址结构。

**核心结论**：逻辑地址由两部分组成：**页号 P + 页内偏移量 W**。

32 位地址、页面大小 $2^{12}B$（4KB）为例：

| 位段 | 位数 | 含义 |
| --- | --- | --- |
| 第 31～12 位 | 高 **20** 位 | 页号 P，最多支持 $2^{20}$ 个页面 |
| 第 11～0 位 | 低 **12** 位 | 页内偏移量 W |

计算套路：

- 页内偏移位数 = $\log_2(\text{页面大小})$
- 页号位数 = 地址总位数 − 页内偏移位数
- 页面总数 = $2^{\text{页号位数}}$

**核心结论（易错重点）**：**分页的逻辑地址是一维的**。因为页面大小固定，给一个整数就能唯一确定位置，页号和偏移由硬件截取，对用户**透明**。

**易错点**：**逻辑地址结构 ≠ 页表项结构**。逻辑地址里有页号，==但**页表项里不存页号**==（页号是隐含索引）。这是本章最容易混的一对，全章反复出现。

**易错点**：页内偏移的位数由**页面大小**决定，与内存大小、页表项大小都无关。

## KP19 页表与页表项

**核心结论**：==**每个进程一张页表**==。页表是**按页号顺序排列的数组**，每个页表项记录该页所在的**物理页框号**，以及状态信息（有效位、访问位等）。页表的作用就是实现**页号 → 页框号**的映射。

**核心结论（易错重点）**：==页表项**按页号顺序连续存放**==，所以**页号是隐含的索引，无须在页表项中显式存储**。页表项里存的是块号。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-7.jpg]]（图 3.7 页表的作用）

**易错点**：==页表存放在**内存**中（所以才要两次访存，才要 TLB）。页表始址和长度进程不运行时保存在 **PCB** 里。==

**易错点**：==问「页表项内容」答**物理块号 + 标志位**==；问「逻辑地址内容」答**页号 + 页内偏移**。不要把页号写进页表项。

## ==KP20 基本地址变换机构（真题高频，必会算）==

**真题**：2013、2021、2024 考过页式系统的地址变换过程；2024 考过页表项地址的计算与分析。

**核心结论**：设**页表寄存器 PTR**，==存放页表在内存中的**始址 F** 和**页表长度 M**==。寄存器昂贵，单 CPU 系统通常**只设一个 PTR**；进程不执行时其页表始址和长度存在 **PCB** 中，被调度执行时由 OS 装入 PTR。

设页面大小 L，逻辑地址 A → 物理地址 E，四步（背这四步）：

| 步 | 操作 |
| --- | --- |
| ① 拆地址 | $P = \lfloor A/L \rfloor$，$W = A \bmod L$ |
| ② 查越界 | 若 $P \geqslant M$（页表长度）→ **越界中断**；否则继续 |
| ③ 查页表 | **页表项地址 = 页表始址 F + 页号 P × 页表项长度**，取出物理块号 b |
| ④ 拼地址 | $E = b \times L + W$，据此访存 |

例：L = 1KB，页号 2 对应块号 b = 8，A = 2500。
$P = 2500/1\text{K} = 2$，$W = 2500 \bmod 1\text{K} = 452$，$E = 8 \times 1024 + 452 = 8644$。

若逻辑地址给的是**二进制**，直接截高位得页号、截低位得偏移，不用除法。

**核心结论（易错重点）**：物理地址 = **页面在内存中的始址 + 页内偏移** = **块号 × 块大小 + 偏移**。别忘了块号要乘块大小。

**易错点**：==③ 里的**页表项地址**要乘「页表项长度」（如 4B），④ 里的**物理地址**要乘「页面大小」（如 4KB）。两个乘数完全不同，2024 真题专挑这个考。==

**易错点**：越界判断比的是**页号 P 和页表长度 M**（页表项个数），不是和页面大小比。

**易错点**：整个变换过程由 **MMU 硬件自动完成**，不是 OS 软件逐条算。

分页管理的两个遗留挑战（引出后面两节）：① 每次访存都要地址转换，慢 → **快表 TLB**；② 页表本身占内存，太大 → **多级页表**。

## KP21 页表项大小的确定（真题）

**真题**：2024 考过页表项地址的计算与分析。

**核心结论**：页表项必须**能表示所有可能的页框号**。

## KP22 快表 TLB（真题）

**真题**：2009 考过具有快表的地址变换的性能分析。

**核心结论**：页表全在内存时，每次访存**至少要两次访存**（先查页表拿块号，再按物理地址访问目标）。为此增设**快表 TLB**——一个**具有并行查找能力的高速缓冲存储器**，缓存当前活跃的若干页表项。主存中的完整页表相应称为**慢表**。

带快表的变换过程：

| 情况         | 过程                                                | 访存次数    |
| ---------- | ------------------------------------------------- | ------- |
| ==**命中**== | ==硬件提取页号，与快表中所有页号**并行比较**，直接取出块号拼物理地址==           | **1 次** |
| **未命中**    | 访问内存页表读页表项拿块号，拼地址访存；同时**把该页表项装入快表**，快表满则按置换算法淘汰旧项 | **2 次** |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-9.jpg]]（图 3.9）

**核心结论**：==在程序局部性良好的前提下，快表**命中率通常达 90% 以上**==，分页的性能开销可控制在 **10% 以内**。快表的有效性基础是**局部性原理**。

**易错点**：==TLB 是**硬件**（相联存储器）==，不是内存中的一张表。==它的查找是**并行比较**==，不是顺序查找，这才是「快」的来源。

**易错点**：TLB 缓存的是**页表项**（页号→块号的映射），不是数据。它和 Cache 缓存数据是两回事。

**易错点**：==未命中时是 **2 次**访存==，不是 3 次（单级页表）。命中时 **1 次**。带快表的多级页表要另算，见 KP24。

## KP23 两级页表：为什么要分级（真题）

**真题**：2014 考过多级页表的特点和优点；2010、2013、2015、2017—2019 考过两级页表的逻辑地址结构及相关分析。

**核心结论（问题的来源）**：32 位地址、页面 4KB、页表项 4B 时：

- 页内偏移 $\log_2 4\text{K} = 12$ 位，页号 20 位 → 每个进程页表最多 $2^{20}$ 个页表项
- 光页表就要 $2^{20} \times 4B / 4\text{KB} = 1\text{K}$ **个页（4MB）**，还要求**连续存放**，不切实际

**解决思路两条（都要答上）**：

1. ==**对页表本身采用离散分配**，不再要求连续存放==，用一张索引表（外层页表）记录各页表页的位置 → 消除对连续内存的需求。
2. **==只把当前活跃的部分页表项调入内存**==，其余留在磁盘按需调入（虚拟内存的思想）→ 缓解页表占内存过多。

本质：**为已离散化的页表再建一层页表，称为外层页表（页目录）**。

分级计算（这个数字要能自己推出来）：

| 量 | 计算 |
| --- | --- |
| 每个页表页能放多少页表项 | $4\text{KB}/4B = 1024 = 2^{10}$ |
| 需要多少个页表页 | $2^{20}/2^{10} = 2^{10} = 1024$ |
| 外层页表大小 | 1024 个表项，$1024 \times 4B = 4\text{KB}$，**恰好占一页** |

由此得到逻辑地址结构（图 3.10）：

| 一级页号（页目录号） | 二级页号（页号） | 页内偏移 |
| --- | --- | --- |
| **10 位** | **10 位** | **12 位** |

两张表里存的东西不同（高频考点）：

| 表 | 表项内容 |
| --- | --- |
| **内层页表**（页表） | 进程某页对应的**物理块号** |
| **外层页表**（页目录） | 某个**页表分页的物理起始地址（块号）** |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-11.jpg]]（图 3.11）

**核心结论（多级页表的根本目的）**：通过**按需分配页表页**，避免为未使用的地址空间预留大量无用页表项，从而显著节省内存。

**易错点**：==外层页表项存的是**页表页的地址**，内层页表项存的才是**数据页的块号**==。这两个别配反，2018、2021 直接考过。

**易错点**：==分级**不减少**页表项总数==（未用到的那部分才省），它省的是「==不必为没用到的区域建页表页==」+「==不必连续存放==」。

**易错点**：一级页号 10 位是**算出来的**（1 个页目录正好占 1 页），不是规定的。改页面大小或页表项大小，这个划分就变了。

## KP24 多级页表的地址变换与访存次数（真题）

**真题**：2018、2021 考过二级页表的页表基址寄存器中的内容；2015、2017 考过二级页表中的地址变换过程。

**核心结论**：==增设**外层页表寄存器（页目录基址寄存器）**==，存放**外层页表的起始地址**。变换三步：

| 步   | 操作                                      |
| --- | --------------------------------------- |
| ①   | 用**页目录号**索引外层页表，==得到对应**内层页表的物理起始地址**== |
| ②   | 用**二级页号**索引该页表，得到目标页面的**物理块号**          |
| ③   | 块号与**页内偏移**拼接成物理地址，据此访存                 |

访存次数（必背表）：

| 结构      | 无快表         | 快表命中 |
| ------- | ----------- | ---- |
| ==单级页表==    | ==**2 次**==     | ==1 次==  |
| ==二级页表==    | ==**3 次**==     | ==1 次==  |
| ==$n$ 级页表== | ==**$n+1$ 次**== | ==1 次==  |

**核心结论**：64 位地址空间下两级远远不够。若逻辑地址 64 位、页面 4KB，页号占 **52 位**；每页仍放 1024 个页表项时，需约 **6 级**页表。实际系统通常把虚拟地址**限制为 48 位**，用**三级或四级**页表即可，既够用又不让硬件过度复杂。

**易错点**：==页目录基址寄存器里存的是**外层页表（页目录）的起始地址**==，不是内层页表地址，也不是当前页的块号。

**易错点**：$n$ 级页表访存 $n+1$ 次 —— 前 $n$ 次查各级页表，最后 1 次取真正的数据。别漏最后那次。

**易错点**：多级页表的代价就是**访存次数增加、访存延迟上升**，靠 TLB 抵消。「多级页表更快」是错的。

## KP25 分段的思想与逻辑地址结构（真题）

**真题**：2009 考过分段系统的逻辑地址结构分析。

**核心结论（出发点的差别，必背）**：

|          | 分页           | 分段                         |
| -------- | ------------ | -------------------------- |
| 站在谁的角度设计 | **计算机（系统）**  | ==**用户和程序员**==             |
| 目标       | 提高内存利用率和系统性能 | ==方便编程、信息保护与共享、动态增长、动态链接== |
| 对用户      | **完全透明**     | **可见**，必须显式给出段号            |

分段：把逻辑地址空间划成若干**大小不等**的段（主程序段、子程序段、栈段、数据段……）。**每个段内部从 0 开始编址**，各占一段连续地址空间——**段内连续，段间不要求连续**。

逻辑地址结构（图 3.12）：**段号 S + 段内偏移量 W**。段号 16 位、偏移 16 位时：

| 量 | 值 |
| --- | --- |
| 最多段数 | $2^{16} = 65536$ 个 |
| 最大段长 | $2^{16}B = 64\text{KB}$ |

**核心结论（易错重点）**：**分段的逻辑地址空间是二维的**——==必须同时给出段号和段内偏移==。这项工作在高级语言中由**编译程序自动完成**。

**易错点**：「段号和段内偏移必须由用户显式提供」不等于「程序员要手写段号」。实际由编译器代劳，但地址空间在结构上仍是二维的。

**易错点**：段的长度**不固定**，由程序逻辑结构决定；页的大小固定，由系统决定。

## KP26 段表与段表项

**核心结论**：**每个进程一张段表**，每段一个段表项，记录该段的**基址（起始地址）+ 段长（长度）**。

| 段号（隐藏） | 段长  | 本段在主存的始址 |
| ------ | --- | -------- |

**核心结论（易错重点）**：==段表项**连续存放且长度相同**，所以**段号是隐含索引，无须额外存储**。（和页表同理）==

段表项大小的计算（教材例，套路同 KP21）：32 位分段系统，段号 16 位、段内偏移 16 位（段长字段 16 位，最大段长 64KB），物理地址 32 位（可寻址 4GB）：

- 段表项至少需 16（段长）+ 32（基址）= **48 位 = 6B**
- 段表首地址为 M 时，**第 K 号段的段表项地址 = $M + K \times 6$**

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-14.jpg]]（图 3.14）

**易错点**：==段表项要存**两个**字段（段长 + 基址），页表项只存**一个**（块号）。因为段长不固定，必须显式记录；页大小固定，不用记。==

**易错点**：段长字段的位数由**最大段长**（= 段内偏移位数）决定，基址字段的位数由**物理地址位数**决定。两个来源不同，别都用同一个位数。

## KP27 段式地址变换（真题）

**真题**：2016 考过段式系统的地址变换过程。

**核心结论**：设**段表寄存器**存放段表**始址 F** 和段表**长度 M**。四步，和分页的区别在于**要查两次界**：

| 步          | 操作                                                                       |
| ---------- | ------------------------------------------------------------------------ |
| ① 拆地址      | 从逻辑地址 A 中分离出段号 S 和段内偏移 W                                                 |
| ② **段号越界** | ==若 $S \geqslant M$（段表长度）→ **段号越界中断**；否则继续==                             |
| ③ **段内越界** | 段表项地址 = 段表始址 F + 段号 S × 段表项长度；取出段长 C，若 $W \geqslant C$ → **段内越界中断**；否则继续 |
| ④ 算地址      | 取出基址 b，$E = b + W$，据此访存                                                  |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-15.jpg]]（图 3.15）

**核心结论（分页 vs 分段的算法差别，最高频）**：

| | 分页 | 分段 |
| --- | --- | --- |
| 越界检查 | **1 次**（页号 vs 页表长度） | **2 次**（段号 vs 段表长度，偏移 vs 段长） |
| 物理地址 | $E = b \times L + W$（**要乘**块大小） | $E = b + W$（**直接加**） |

**易错点**：段式物理地址是**基址直接加偏移**，不乘任何东西——==因为段表里存的是**字节地址**==，不是块号。页式存的是块号，必须乘页面大小。这是最容易错的一对。

**易错点**：分段要检查段内偏移是否超过段长，因为**段长不固定**；分页不用，因为偏移位数天然限制在页面大小内，不可能越界。

## KP28 分页与分段的对比（必背三条）

**核心结论**：共同点——都是**非连续分配**，都需要**地址映射机构**实现地址变换。本质区别三条：

| 维度          | 页                                       | 段                                                |
| ----------- | --------------------------------------- | ------------------------------------------------ |
| **单位性质与目的** | **物理**单位，为提高**内存利用率**，完全由系统实现，对用户**透明** | **逻辑**单位，为满足**编程、共享、保护**需求，由编译器按程序结构划分，对用户**可见** |
| **大小**      | **固定**，由系统决定                            | **不固定**，取决于程序逻辑结构                                |
| **地址空间维度**  | **一维**，只需给单一线性地址                        | **二维**，必须给段名（段号）+ 段内偏移                           |

顺带记住的碎片结论：

| 方式  | 内部碎片          | 外部碎片  |
| --- | ------------- | ----- |
| 分页  | **有**（每进程约半页） | 无     |
| 分段  | 无             | **有** |

**易错点**：三条对比的关键词分别是「物理/逻辑」「固定/不固定」「一维/二维」。选择题常把「页是逻辑单位」这种配反的选项混进来。

**易错点**：分段有外部碎片，因为段长不等、要求段内连续，本质上退回了动态分区的问题。

## KP29 段的共享与保护（真题）

**真题**：2019、2023 考过页、段共享的原理和特点。

**核心结论（为什么分段共享更方便）**：一段共享代码占 N 个页框时，

| 系统  | 每个共享进程需要的表项                          |
| --- | ------------------------------------ |
| 分页  | 页表中要建 **N 个页表项**，分别指向那 N 个页框         |
| 分段  | ==段表中只需 **1 个段表项**指向该共享段，**无论段多大**== |

**共享段表**：每个共享段一个表项，记录**段号、段长、内存起始地址、存在位、外存起始地址、共享进程计数 count**。
 
- 进程不再使用该段时 **count 减 1**；**仅当 count = 0 时**才回收该段所占内存。

**核心结论（易错重点）**：**同一共享段在不同进程中可以有不同的段号**，各进程用自己的段号访问同一个物理段。

可重入代码（纯代码）的共享条件：置于**只读段**中；每个进程配**私有的局部数据区**存放可能变化的数据，从而避免对共享代码段的任何写操作。

分段的保护机制两类（和分页同理）：

| 类型 | 做法 |
| --- | --- |
| **地址越界保护** | 段号 $\geqslant$ 段表长度 → 越界中断；段内偏移 $\geqslant$ 段长 → 越界中断 |
| **存取控制保护** | 通过段表项中的**访问权限位**（读/写/执行）防止非法访问 |

**易错点**：count 减到 0 才回收，中途有进程退出**不能**回收。这条和第 2 章的引用计数一个道理。

**易错点**：共享段在各进程中段号可以不同 —— 常考「必须相同」这种错误说法。

## KP30 段页式存储管理

**核心结论**：**先分段，再分页**。进程地址空间先划成若干逻辑段（每段有唯一段号），每段再划成若干**大小固定**的页；内存仍按**分页**方式管理，划成同样大小的物理块，**分配以物理块为单位**。

逻辑地址三部分（图 3.17）：**段号 S + 页号 P + 页内偏移量 W**。

数据结构（这条注意事项必考）：

| 结构        | 数量             | 表项内容                                    |
| --------- | -------------- | --------------------------------------- |
| **段表**    | 每个进程**仅一张**    | 该段的**页表始址 + 页表长度**（段号作索引，不存）            |
| **页表**    | **每个段一张，可能多张** | 对应页的**物理块号**（页号作索引，不存）                  |
| **段表寄存器** | 1 个            | 当前进程段表的**起始地址 + 段表长度**（用于段表寻址 + 段号越界检查） |

地址变换三步：

| 步 | 操作 |
| --- | --- |
| ① | 用**段号 S** 经段表寄存器定位段表，查得该段**页表的起始地址** |
| ② | 用**页号 P** 访问该页表，取得**物理块号** |
| ③ | 物理块号与**页内偏移 W** 拼接成物理地址 |

访存次数：**无快表时每次访问需 3 次访存**（查段表、查页表、取数据）。引入快表后 1 次，快表表项的**关键字是（段号，页号）**，内容是物理块号和保护信息。

**核心结论（易错重点）**：段页式的地址空间是**二维的**——与分段一致，因为对用户而言程序仍按段组织，**页的划分由系统自动完成且完全透明**。

**易错点**：段表项存的是**页表始址和页表长度**，不是块号也不是段基址。这是段页式和纯分段最大的结构差别。

**易错点**：「一张段表、多张页表」——每个段一张页表。答成「一张页表」就错。

**易错点**：段页式是**二维**地址空间，不是三维。逻辑地址有三个字段，但用户只感知段号和段内地址。

**易错点**：段页式**没有外部碎片**（内存按页管理），但有**页内碎片**，且每个**段**的最后一页都可能不满，所以碎片比纯分页更多。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-18.jpg]]（图 3.18）

## KP31 本节小结：三个关键问题 + 总对比表

**核心结论（教材给的抓手，本节的方法论）**：无论段式、页式还是段页式，只需掌握三点：① **逻辑地址结构**，② **页（段）表项结构**，③ **寻址过程**。再次强调：**逻辑地址结构 ≠ 表项结构**。

按这三点默写下表，本节就过了：

| | 分页 | 分段 | 段页式 |
| --- | --- | --- | --- |
| ① 逻辑地址结构 | 页号 + 页内偏移（**一维**） | 段号 + 段内偏移（**二维**） | 段号 + 页号 + 页内偏移（**二维**） |
| ② 表项结构 | 页表项：**块号** | 段表项：**段长 + 基址** | 段表项：**页表始址 + 页表长度**；页表项：**块号** |
| ③ 越界检查次数 | 1 次 | 2 次 | 段号 1 次（+ 页表长度） |
| ③ 物理地址算法 | 块号 × 页面大小 + 偏移 | 基址 + 偏移 | 块号 × 页面大小 + 偏移 |
| 无快表访存次数 | 2 次（二级 3 次） | 2 次 | **3 次** |
| 表的数量 | 每进程 1 张页表 | 每进程 1 张段表 | 每进程 **1 张段表 + 多张页表** |
| 碎片 | 内部（约半页/进程） | 外部 | 内部（每段最后一页） |

**教材两问的答案**：

**1. 为什么要进行内存管理？** 单道程序时只需把全部内存（或固定分区）给当前进程，极简单。引入多道程序后多个进程并发执行、共享主存，若不管理，**不同进程的地址空间可能重叠或相互覆盖**，导致数据被意外修改、破坏程序正确性，严重影响并发可靠性。所以为支持多道程序安全高效并发，必须做内存管理。

**2. 多级页表解决了什么问题？又带来什么问题？**

| 解决 | 带来 |
| --- | --- |
| 逻辑地址空间大时**单级页表过长、占用内存过多**；分级后只需把当前使用的各级页表驻留内存，既减少内存占用，又**避免对大块连续内存的需求** | **性能开销**：无快表时一次地址变换要**逐级访问多级页表**，多次访存，增加访存延迟 |

# 3.2 虚拟内存管理

## KP32 传统存储管理的两个特征：一次性与驻留性

**核心结论**：3.1 的各种内存管理策略有两个共同特征，这正是虚拟内存要打掉的东西：

| 特征 | 含义 | 带来的问题 |
| --- | --- | --- |
| **一次性** | 作业必须**一次性全部装入内存**后才能开始运行 | ① 作业过大装不下就**无法运行**；② 内存容纳不了所有作业，只能少数先跑，**系统并发度下降** |
| **驻留性** | 作业一旦装入就**一直驻留**，任何部分都不换出，直至运行结束 | 进程常因等 I/O 被阻塞、长时间等待，**暂未使用的代码和数据仍占大量内存** |

结论：宝贵内存被「暂时不用」的部分占着，急需运行的作业却因内存不足装不进来，造成资源浪费。

**易错点**：一次性针对**空间**（要全部装入），驻留性针对**时间**（全程不走）。虚拟存储器用**多次性**破一次性、用**对换性**破驻留性，一一对应。

## KP33 局部性原理（真题）

**真题**：2012 考过页面置换算法的时间局部性分析。

**核心结论**：快表、页高速缓存、虚拟内存**都属于缓存技术**，共同依赖局部性原理。局部性对**程序结构**和**数据结构**都成立。

| 类型 | 表述 | 成因 | 靠什么利用 |
| --- | --- | --- | --- |
| **时间局部性** | 某条指令或某个数据项一旦被访问，**不久之后很可能再次被访问** | 程序中存在大量**循环和重复操作** | 把近期用过的指令和数据放进**高速缓存**，并借助**多级缓存层次**结构 |
| **空间局部性** | 访问了某个存储单元后，**其附近的存储单元也很可能被访问** | 指令**顺序存放、顺序执行**；数据（向量、数组、表）**连续或簇聚**存储 | 采用**较大容量的缓存**，并在缓存控制逻辑中集成**预取**机制 |

**跨科关联**：[[知识点/CO-01-计算机系统概述.md]] KP10（存储器的层次划分）；本章 KP22（快表 TLB 的有效性基础就是局部性）。

**易错点**：时间局部性配「多级缓存」，空间局部性配「大容量缓存 + 预取」，两组手段别配反。

**易错点**：虚拟内存正是基于局部性，把**外存作为内存的透明扩展**。若程序访问完全随机，虚拟内存只会疯狂缺页。

## KP34 虚拟存储器的定义与三个特征（真题）

**真题**：2012 考过虚拟存储器的特点。

**核心结论**：装入时只把当前运行所需的**少数页（段）**装入内存，其余暂留外存即可启动执行。运行中访问到不在内存的信息，OS 自动从外存调入，称**请求调页（请求调段）**；内存不足时把暂不用的信息换出外存腾空间，称**页面置换（段置换）**。两个机制协同，为用户提供一个**逻辑上远大于物理内存**的地址空间，即**虚拟存储器**。

叫「虚拟」是因为它**并非真实存在的物理实体**，而是 OS 通过**部分装入 + 请求调入 + 置换**（均对用户透明）构造出的**逻辑抽象**。

| 特征 | 含义 | 破的是 |
| --- | --- | --- |
| **多次性** | 作业无须运行前一次性全装入，可**分多次动态调入** | 一次性 |
| **对换性** | 运行中无须常驻内存，可把暂不使用的部分**换出到外存对换区**，需要时再换入 | 驻留性 |
| **虚拟性** | 从**用户视角**看，内存容量被逻辑扩充，呈现远大于实际物理内存的可用空间 | —— |

**核心结论（易错重点）**：**虚拟性是虚拟存储器的本质特征和根本目标，其实现依赖于多次性与对换性**。三者不是并列关系，有依赖顺序。

**易错点**：虚拟内存**不增加物理内存**，扩的只是逻辑容量。虚存空间大小由**虚拟地址位数**决定（KP60），不是「内存 + 外存」相加。

**易错点**：请求调页是「缺了才调」（被动），对换是「主动腾地方」。两个机制方向相反，缺一个都不叫虚拟存储器。

## KP35 虚拟内存的实现方式与硬件支持

**核心结论（易错重点）**：虚拟内存的实现**必须建立在离散分配之上**。若采用连续分配，作业分多次调入会让相当一部分内存处于暂时甚至「永久」空闲状态，既严重浪费内存，也**无法从逻辑上扩充内存容量**。

三种实现方式：**请求分页**存储管理、**请求分段**存储管理、**请求段页式**存储管理。

四类硬件支持（任何一种方式都需要）：

| 硬件支持 | 作用 |
| --- | --- |
| 足够容量的**内存和外存** | 分别存放程序的**当前部分**与**后备部分** |
| **页表机制（段表机制）** | 地址映射的关键数据结构 |
| **中断机构** | 访问到尚未调入内存的部分时，触发**缺页（缺段）中断** |
| **地址变换机构** | 运行过程中动态地把逻辑地址转换为物理地址 |

**易错点**：单一连续分配、固定分区、动态分区这些**连续分配方式都不能实现虚拟内存**。判断题常考。

## KP36 请求分页的页表机制：四个新增字段

**核心结论**：请求分页 = 基本分页 + **请求调页** + **页面置换**。只装入当前需要的一部分页面便可启动作业；运行中缺页就调入，内存不足就换出。因为换入换出的单位是**长度固定的页**，实现比以变长段为单位的请求分段更简单，所以请求分页是**目前最常用的虚拟存储器实现方式**。

OS 需要回答四个问题，页表项就相应多出四个字段：

| 要回答什么 | 字段 | 内容 |
| --- | --- | --- |
| 这页调入内存了吗 | **状态位 P（存在位）** | 标记是否已调入内存，地址变换时据此判断要不要触发缺页中断 |
| 置换时该淘汰谁 | **访问字段 A** | 记录本页在一段时间内的**访问次数**，或**自上次访问以来的时间间隔**，供置换算法参考 |
| 换出要不要写回 | **修改位 M（脏位）** | 标记该页调入后**是否被修改过**，决定换出时是否需写回外存 |
| 没调入的话它在哪 | **外存地址** | 该页在外存的存放位置（通常为物理块号），供调页时读入 |

完整页表项：`页号 | 物理块号 | 状态位 P | 访问字段 A | 修改位 M | 外存地址`

**易错点**：**基本分页的页表项只有块号**（KP19），这四个字段全是请求分页才加的。问「请求分页比基本分页多什么」，答这四个。

**易错点**：M = 0 的页换出时可**直接丢弃**、无须写回——这是改进型 CLOCK（KP50）和页面缓冲（KP54）省 I/O 的根据。

**易错点**：外存地址字段的意义是「没调入时去哪找它」，所以**每个页表项都有**，不是只有换出过的页才有。

## KP37 缺页中断机构与两个特点（真题超高频）

**真题**：2011、2013、2014、2020、2022 考过缺页处理的过程及效率分析；2023 考过缺页异常导致进程状态的变化。

**核心结论**：进程访问的页面尚未调入内存时，**硬件自动触发缺页中断**，由 OS 的缺页中断处理程序处理：

```
有空闲页框 → 分配一个页框 → 从外存装入所缺页面 → 更新页表相应表项
无空闲页框 → 置换算法选一页淘汰
             该页被修改过(M=1) → 必须写回外存
             未修改(M=0)       → 可直接丢弃
           → 装入所缺页面 → 更新页表项
```

调页涉及较长时间的**磁盘 I/O**，这期间**系统可能调度其他进程运行**；待页面调入完成后，**重新执行引发缺页的那条指令**。

**跨科关联**：[[知识点/OS-01-计算机系统概述.md]] KP26—KP28（中断 vs 异常、分类、返回地址差异）；[[知识点/OS-02-进程与线程.md]] KP7（缺页时进程由**运行态转阻塞态**，调页完成后由阻塞态转就绪态——2023 真题考法）。

缺页中断是**内中断**，处理过程同样要保护 CPU 现场、分析中断原因、转入处理程序、恢复现场，但有两个显著特点：

| 特点 | 说明 |
| --- | --- |
| 在**指令执行期间**触发 | 由当前指令的地址访问**直接引发**，而非在指令执行完毕之后 |
| 一条指令可能引发**多次**缺页 | 如执行 `copy A to B`，若指令本身及两个操作数**各跨两个页面**，最多引发 **6 次**缺页中断 |

**易错点**：外中断在**指令执行结束后**响应；缺页中断在**指令执行期间**触发，且返回后**重新执行该指令**（不是执行下一条）。这两条是缺页中断的核心区别。

**易错点**：6 这个数字来自「指令跨 2 页 + 操作数 A 跨 2 页 + 操作数 B 跨 2 页」，与 KP39 的最小页框数是同一个模型的两种问法。

**易错点**：缺页中断本身是**内中断（异常）**，由当前指令引起；但缺页**处理过程中**发起的磁盘 I/O 完成时会产生**外中断**。两者别混。

## KP38 请求分页的地址变换过程（真题高频）

**真题**：2009、2010、2014、2024 考过分页系统的地址变换过程及分析。

**核心结论**：请求分页的地址变换 = 基本分页的地址变换机构（KP20）+ **缺页中断触发机制**。四步：

| 步 | 情况 | 动作 |
| --- | --- | --- |
| ① | **先检索快表，命中** | 取出该页物理块号；**置访问位 A = 1**；若是**写操作，还需置修改位 M = 1** |
| ② | 快表未命中，**页在内存**（状态位 = 1） | 访问页表取出物理块号，并把该**页表项装入快表**；快表已满则按置换算法淘汰一项 |
| ③ | 快表未命中，**页不在内存** | 触发**缺页中断** → OS 从外存调入（必要时先换出一页）→ 更新**页表和快表** → **重新执行地址变换**获取块号 |
| ④ | —— | 物理块号与页内地址**拼接**成物理地址，用于访存 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-20.jpg]]（图 3.20 请求分页中的地址变换过程）

**易错点**：访问位和修改位在**快表命中时也要置**，不是只在访问页表时才置。

**易错点**：只有**写操作**才置 M = 1；读操作只置 A = 1。

**易错点**：缺页处理完成后是**重新执行地址变换**（乃至整条指令），不是接着往下拿块号。

## KP39 最小页框数（真题）

**真题**：2025 考过最小物理块数的确定原则。

**核心结论**：最小页框数（最小物理块数）= 保证进程正常运行所需的**最少页框数量**，分配少于此值进程**将无法执行**。它与**计算机的硬件结构**有关，具体取决于**指令的格式、功能和寻址方式**。

| 机器 / 寻址方式 | 最小页框数 | 分别放什么 |
| --- | --- | --- |
| 单地址指令 + **直接寻址** | **2** | 指令、数据 |
| 支持**间接寻址** | **3** | 指令、指针、数据 |
| 一条指令及其两个操作数**各跨两个页面** | **6** | 指令 2 页 + 操作数 A 2 页 + 操作数 B 2 页 |

**易错点**：最小页框数取决于**硬件（指令格式与寻址方式）**，**不取决于进程大小、也不取决于页面大小**。这是 2025 年的考法。

**易错点**：和 KP37「一条指令最多引发 6 次缺页」是同一个模型：**最坏情况下必须同时驻留的页数** = 最小页框数。

## KP40 驻留集大小的权衡

**核心结论**：进程启动时既不需要、也不可能把所有页面装入内存，OS 必须决定分配多少页框——这个集合就是该进程的**驻留集**。驻留集大小是**系统并发度**与**缺页开销**之间的权衡：

| 驻留集 | 好处 | 代价 |
| --- | --- | --- |
| **过小** | 内存可容纳的进程数增多，**多道程序并发度提高** | 每个进程页框太少，**缺页率显著升高**，CPU 耗费大量时间处理缺页中断 |
| **过大** | 缺页率低 | 超过某一阈值后**对缺页率的改善趋于平缓**，浪费内存资源，且可用页框总量减少，**降低系统整体并发能力** |

**易错点**：驻留集不是「进程的全部页面」，而是**当前分配到的页框集合**。它的下限参考**工作集**（KP53），小于工作集就会频繁缺页。

## KP41 三种分配置换策略组合（真题）

**真题**：2015 考过页面分配与置换策略的名称。

**核心结论（易错重点）**：分配有**固定/可变**两种，置换有**全局/局部**两种，理论上四种组合，但**固定分配与全局置换互斥**——固定分配要求进程页框数保持不变，而全局置换会导致页框数变化。因此**实际可行的策略只有三种**：

| 策略 | 分配 | 置换 | 特点 |
| --- | --- | --- | --- |
| **固定分配局部置换** | 每进程固定数量页框，运行期间**保持不变** | 只能从**该进程自身**已分配的页框中选一页换出，驻留集大小恒定 | 难点在初始分配量：太少则**频繁缺页**，太多则浪费内存并**减少并发进程数** |
| **可变分配全局置换** | 初始给一定数量，运行期间**动态调整** | 先从**空闲页框队列**取一个；空闲耗尽则从**内存所有页框**中选一个换出，**不论归属哪个进程** | 最灵活，能动态扩充驻留集适应需求；但缺乏调控时活跃进程的驻留集会**持续膨胀、抢占其他进程页框**，削弱并发能力 |
| **可变分配局部置换** | 初始给一定数量，并**按缺页率动态调整**：缺页率过高就增加页框，过低就回收部分（须保证不引发缺页率显著上升） | 只从**该进程自身**页框中选一页换出，**不影响其他进程** | 既抑制频繁调页又兼顾并发；实现复杂、开销大，但相比频繁换入换出耗掉的磁盘 I/O 与 CPU 资源，这个开销值得 |

教材提醒：2015 年统考选择题考的就是这三种策略的**名称**，不少考生当非重点一带而过而失分。

**易错点**：缺的那种组合是**固定分配 + 全局置换**，原因是二者对「页框数是否变化」的要求直接矛盾。

**易错点**：可变分配全局置换是「先取空闲、再抢别人」；可变分配局部置换是「只在自己家换 + 按缺页率调整驻留集」。区别在**换出页的来源范围**，不在分配是否可变。

## KP42 页框调入算法：固定分配时怎么分

**核心结论**：采用固定分配策略时，把空闲页框分给各进程的三种算法：

| 算法 | 做法 |
| --- | --- |
| **平均分配** | 所有可供分配的页框**平均**分给各进程 |
| **按比例分配** | 根据进程的**逻辑地址空间大小**按比例分配 |
| **优先权分配** | 给重要或紧迫的进程更多页框。通常做法：把可分配页框分成两部分，**一部分按比例**分给各进程，**另一部分按优先权**动态分配 |

**易错点**：按比例分配的依据是**进程大小**，不是优先级；优先权分配的典型实现是「比例 + 优先权」两部分合起来，不是纯按优先级分。

## KP43 调入页面的时机：预调页 vs 请求调页

**核心结论**：

| 策略 | 时机 | 做法与依据 | 优缺点 |
| --- | --- | --- | --- |
| **预调页** | 进程**运行前** | 按局部性原理**预测**近期可能访问的页面，一次调入若干**相邻**页面 | 一次调多页比逐页调入更高效；但**预测成功率仅约 50%**，调错就浪费内存。故**主要用于进程首次调入**，由**程序员显式指定**应优先加载的页面 |
| **请求调页** | 进程**运行期间** | 访问的页面不在内存就触发缺页中断，由系统调入 | 调入的页面**必然会被访问**，实现相对简单，**当前虚拟存储器大多采用**；缺点是每次仅调一页，**磁盘 I/O 开销大** |

**易错点**：预调页在**运行前**完成加载，请求调页在**运行期间**动态调入。这条时间线是判断题常考点。

**易错点**：预调页由**程序员**指定哪些页优先加载，不是 OS 全自动完成（OS 预测成功率不够）。

## KP44 从何处调入页面：文件区与对换区

**核心结论**：请求分页系统的外存分两部分——存放文件的**文件区**（**离散分配**）和存放换出页面的**对换区/交换区**（**连续分配**）。因为连续分配，**对换区的磁盘 I/O 速度通常快于文件区**。据此有三种情况：

| 情况 | 调入来源 | 做法 |
| --- | --- | --- |
| ① 对换区空间**足够** | 全部从**对换区**调入，提高调页速度 | 需在进程运行前，把与该进程相关的文件从**文件区复制到对换区** |
| ② 对换区空间**不足** | **不会被修改**的页 → 从**文件区**调入；**可能被修改**的页 → 换出时存到**对换区**，以后从对换区读 | 不会修改的页换出时因内容未变**无须写回磁盘**，兼顾效率与正确性 |
| ③ **UNIX 方式** | 相关文件**始终保留在文件区**。**未运行过**的页从**文件区**调入；**运行过但已换出**的页在**对换区**，从对换区读 | 多进程共享同一页面时，只要该页已在内存，其他进程**直接复用**，无须重复调入 |

**易错点**：对换区快是因为**连续分配**，不是因为介质不同——两者都在磁盘上。

**易错点**：情况②里「不会被修改的页」换出时**直接丢弃**，不写回文件区；只有可能被修改的页才写到对换区。

## KP45 缺页处理的完整流程与效率（真题高频）

**真题**：2011、2013、2014、2020、2022 考过缺页处理的过程及效率分析。

**核心结论**：页表项**存在位为 0** 时 CPU 触发缺页中断，转入缺页中断处理程序：

```
① 由页表项取得该页在外存中的地址
② 判断内存是否已满
   未满 → 分配一个空闲页框 → 发起磁盘 I/O 调入 → 更新页表项：填物理块号、置存在位 = 1
   已满 → 按置换算法选出一页准备换出
          修改位 M = 0 → 直接丢弃，释放页框
          修改位 M = 1 → 先写回对换区，再释放页框
        → 把所缺页面调入该页框 → 更新页表项，置存在位 = 1
③ 进程用更新后的页表生成正确的物理地址，重新执行引发缺页的指令
```

整个调入过程**对用户完全透明**，由 OS 自动完成。

**效率分析**：缺页开销 = 缺页中断处理时间 + 页面传入时间（+ 脏页写回时间）+ 进程重启时间，其中**磁盘 I/O 占绝对主导**。设缺页率为 $p$，则有效访问时间 $\text{EAT} = (1 - p) \times 访存时间 + p \times 缺页处理时间$，所以 $p$ 必须极小才可接受。

**易错点**：脏页要**先写回再调入**，一次缺页可能是**两次**磁盘 I/O。算有效访问时间时别漏掉写回那一次。

**易错点**：只有内存已满才需要置换算法；有空闲页框时**直接分配**，不淘汰任何页。

## KP46 最佳置换算法 OPT

**核心结论**：缺页时选择淘汰**以后永不使用、或在最长时间内不再被访问**的页面，**理论上缺页率最低**。但 OS 无法预知未来的页面访问序列，**实际系统中无法实现**，只作为**评价其他算法**的标尺。

判定套路：缺页时看内存中各页**下一次被访问的位置**，谁最晚（或再也不出现）就淘汰谁。

教材例题（3 个物理块，序列 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1）：

| 结果 | 数值 |
| --- | --- |
| 缺页中断次数 | **9 次** |
| 其中触发页面置换 | **6 次**（不算最初 3 页的装入） |

**易错点**：「缺页次数」≠「置换次数」：**最初装满物理块的那几次也算缺页但不算置换**，所以 9 和 6 差 3（= 物理块数）。题目问哪个要看清。

## KP47 先进先出 FIFO 与 Belady 异常（真题）

**真题**：2010 考过 FIFO 算法的应用分析。

**核心结论**：淘汰**最早进入内存**的页面。实现最简单——内存中的页按调入时间组织成队列，需换出时直接移除**队首**。但 FIFO **未利用局部性原理**，与进程实际运行规律不符，最早装入的页仍可能被频繁访问，所以**性能通常较差**。

同一例题（3 块）：缺页 **15 次**，其中置换 **12 次**（对比 OPT 的 9 次）。

**核心结论（易错重点）—— Belady 异常**：**为进程分配的物理块数增加时，缺页次数反而可能上升**。根本原因是 FIFO **仅依据调入时间决策，忽略了页面的实际使用情况**。

教材例题（序列 3,2,1,0,3,2,4,3,2,1,0,4）：

| 物理块数 | 缺页次数 |
| --- | --- |
| **3 块** | **9 次** |
| **4 块** | **10 次**（反而更多） |

**易错点**：**只有 FIFO 可能出现 Belady 异常**，OPT 和 LRU **永远不会**。必背的一句。

**易错点**：Belady 异常是「**可能**出现」，不是必然——FIFO 在多数序列上仍是块数越多缺页越少。

## KP48 最近最久未使用 LRU（真题高频）

**真题**：2009、2015、2019、2025 考过 LRU 算法的应用分析。

**核心结论**：淘汰**最近最长时间未使用**的页面。依据的假设是：某页过去一段时间未被使用，近期未来很可能也不会被访问。实现上需为每页设**访问字段**记录自上次被访问以来经历的时间，淘汰该值**最大**的页。

同一例题（3 块）见教材图 3.24。前 5 次缺页处理结果与 OPT 相同，但这**纯属巧合**，并无必然联系。

**核心结论（易错重点）**：LRU 根据页面**过去**的使用情况判断，是「**向前看**」；OPT 根据页面**未来**的使用情况判断，是「**向后看**」。页面过去与未来的走向之间**并无必然联系**。

三者定位：

| 算法 | 性能 | 实现 |
| --- | --- | --- |
| **OPT** | **最好** | **无法实现** |
| **FIFO** | **较差**（忽略局部性） | 最简单 |
| **LRU** | **接近 OPT**，实际效果良好 | 通常需**硬件支持**，开销较大 |

**易错点**：LRU 判的是「**最久没被访问**」（看时间），不是「访问次数最少」（那是 LFU）。

**易错点**：教材的说法是 **LRU 向前看（看历史）、OPT 向后看（看未来）**，方向最容易记反。

## KP49 简单 CLOCK 算法（NRU）（真题）

**真题**：2010 考过 CLOCK 算法的应用分析；2012 考过类 CLOCK 算法的过程分析。

**核心结论**：LRU 性能接近 OPT 但实现开销大，于是设计出一类**以较小开销逼近 LRU 性能**的算法，统称 CLOCK 算法及其变体。简单 CLOCK 的规则：

- 每个页面设一个**访问位**，页面**首次装入内存或被访问**时置为 1。
- 所有页框组成**循环队列**，维护一个**替换指针**指向当前检查位置。
- 缺页需置换时：指针所指页**访问位 = 0** → **直接淘汰**；**访问位 = 1** → **置为 0**，指针顺移到下一页，给它一次「宽恕」机会，待后续轮询再判。

指针在队列中循环移动形如时钟指针，故称 CLOCK；又因仅依据「**最近是否被使用**」这一粗略信息决策，也称**最近未用 NRU 算法**。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-25.jpg]]（图 3.25 CLOCK 算法的置换图）、[[王道教材/27 王道操作系统/pictures/fig-3-26.jpg]]（图 3.26 缺页时替换指针扫描示意图）

教材例题（序列 7,0,1,2,0,3,0,4,2,3,0,3,2,1,3,2，**4 个页框**，每框记录（页号，访问位））走查要点：

| 缺页 | 指针起点 | 情况 | 淘汰 |
| --- | --- | --- | --- |
| 第 5 次（访问 3） | 帧 1 | 所有页框访问位均为 1 → **完整扫一圈全部清零**，指针回到起点帧 1 | 帧 1 的页面 **7** |
| 第 6 次（访问 4） | 帧 2（上次替换位置的**下一帧**） | 帧 2 的 A=1 → 置 0 顺移；帧 3 的 A=0 | 帧 3 的页面 **2** |
| 第 7 次（访问 1） | 帧 4 | 所有 A=1 → 再扫一圈清零 | 帧 4 的页面 **2** |
| 第 8 次（访问 2） | 帧 1 | 帧 1 的 A=1 → 置 0 顺移；帧 2 的 A=0 | 帧 2 的页面 **0** |

**易错点**：置换后指针停在**被替换帧的下一帧**，下次从这里开始扫。忘记推进指针是做题最常见的错。

**易错点**：全部 A=1 时会扫一整圈把访问位清零、指针回到起点，然后淘汰**起点那一帧**——此时**退化成 FIFO**，不是「找不到就随便淘汰」。

**易错点**：页面命中（已在内存）时也要**把访问位置 1**，但**指针不动**。指针只在缺页置换时移动。

## KP50 改进型 CLOCK 算法（真题高频）

**真题**：2018 考过改进 CLOCK 算法的思想；2016、2021 考过改进 CLOCK 算法的应用分析。

**核心结论**：已修改的页换出要写回磁盘，**置换代价更高**。改进型在访问位 A 之外引入**修改位 M**，综合考虑**使用情况**与**置换代价**，优先淘汰**既未被访问又未被修改**的页。按 $(A, M)$ 分四类，每一页必属其一：

| 类 | $(A, M)$ | 含义 | 淘汰优先级 |
| --- | --- | --- | --- |
| **1 类** | (0, 0) | 最近未被访问，未被修改 | **最佳淘汰页** |
| **2 类** | (0, 1) | 最近未被访问，但已被修改 | **次佳淘汰页** |
| **3 类** | (1, 0) | 最近已被访问，但未被修改 | 可能再次被访问 |
| **4 类** | (1, 1) | 最近已被访问，且已被修改 | 可能再次被访问 |

扫描步骤（循环扫描机制同简单 CLOCK，区别是同时检查 A 和 M）：

```
① 第一轮：从当前指针位置起找 A=0, M=0 的 1 类页，第一个找到的即淘汰
   —— 本轮不修改任何访问位 A
② 若①失败，第二轮：找 A=0, M=1 的 2 类页，第一个找到的即淘汰
   —— 本轮把所经过页面的访问位 A 全部置 0
③ 若前两步均失败（说明所有页 A=1）：指针复位到起始位置、所有帧访问位清零，
   随后重复①；仍无 1 类页则执行② —— 此时必能找到可淘汰页面
```

**核心结论**：改进型优于简单 CLOCK 之处是**优先淘汰未修改页，降低磁盘 I/O 开销**；代价是为定位淘汰页**可能需多轮扫描**，算法自身运行开销增加。

置换算法的共同原则：**尽可能保留近期访问过的页面，优先淘汰未访问过的页面**。简单 CLOCK 只看「是否被访问过」；改进型进一步细化——「未访问过」的里面优先换**未修改**者，即使所有页都「被访问过」，仍优先选**未修改**者换出。

**易错点**：**第一轮不改 A，第二轮才把经过页面的 A 置 0**。两轮的副作用不同，这是应用分析题的关键。

**易错点**：优先级是 (0,0) → (0,1) → (1,0) → (1,1)，即**先比 A 再比 M**。2 类 (0,1) 优先于 3 类 (1,0)，别写成「先比 M」。

**易错点**：最多扫描 **4 轮**（①②再①②）必能找到淘汰页，不会死循环。

## KP51 置换算法总对比（必背）

**真题**：2014 考过各种页面置换算法的特点。

**核心结论**：一张表定五种算法。

| 算法 | 淘汰依据 | 缺页率 | 实现开销 | Belady 异常 |
| --- | --- | --- | --- | --- |
| **OPT** | 未来最长时间不被访问（向后看） | **最低（理论最优）** | **无法实现** | 不会 |
| **FIFO** | 最早进入内存（只看调入时间） | 最高 | 最小，队列即可 | **可能出现** |
| **LRU** | 最近最久未使用（向前看，看历史时间） | 接近 OPT | 大，需硬件支持 | 不会 |
| **简单 CLOCK / NRU** | 访问位 A（最近是否用过） | 介于 FIFO 与 LRU 之间 | 小 | —— |
| **改进型 CLOCK** | 先 A 后 M，优先淘汰 (0,0) | 优于简单 CLOCK（省写回 I/O） | 中，可能多轮扫描 | —— |

设计动机链：

```
OPT 最优但不可实现 → FIFO 可实现但忽略局部性 → LRU 逼近 OPT 但硬件开销大
  → 简单 CLOCK 用一个访问位近似 LRU → 改进型 CLOCK 再加修改位省磁盘写回
```

**易错点**：LRU 只是**通常**优于 FIFO，不保证在每个访问序列上都更优。说「LRU 缺页率一定不高于 FIFO」是错的。

## KP52 抖动（颠簸）（真题）

**真题**：2011 考过抖动的处理措施。

**核心结论**：最糟的情形是**刚换出的页面马上又要换入，刚换入的页面又立即被换出**，这种频繁的页面调度行为称为**抖动（颠簸）**。

**根本原因**：分配给进程的**物理块数过少**，无法满足正常运行的基本需求 → 频繁触发缺页中断 → 磁盘 I/O 频率急剧上升 → 进程大部分时间消耗在换入换出上、几乎无法完成有效计算 → **CPU 利用率急剧下降，甚至趋近于零**。

因为病根是驻留集过少，于是提出**工作集**概念来动态指导页框分配（KP53）。

**易错点**：抖动的根因是**页框分配过少**，不是「置换算法不好」也不是「内存总量太小」。答处理措施要落到**调整驻留集大小**（按工作集分配、必要时挂起部分进程降低并发度）。

**易错点**：抖动时 CPU 利用率**下降**。若此时误判「CPU 闲着，再多调进程进来」，会让抖动更严重——经典陷阱。

## KP53 工作集（真题）

**真题**：2016 考过工作集的应用分析。

**核心结论**：**工作集**是指在**某段时间间隔内进程实际访问过的页面集合**。工作集 $W$ 由时间 $t$ 和**工作集窗口尺寸 $\Delta$** 共同确定——即从 $t$ 往前数 $\Delta$ 次访问中出现过的页面（**去重**）。

教材例题（$\Delta = 5$），序列 `1, 4, 2, 3, 5, 3, 2, 2, 1, 1, 1, 3, 4, 5, 4, 4, 2, 1, 1, 3, 3`：

| 时刻 | 窗口内的 5 次访问 | 工作集 |
| --- | --- | --- |
| $t_1$ | 2, 3, 5, 3, 2 | $\{2, 3, 5\}$ |
| $t_2$ | 4, 2, 1, 1, 3 | $\{1, 2, 3, 4\}$ |

实际应用中窗口 $\Delta$ 通常设得较大；对**局部性良好**的程序，工作集大小一般**远小于** $\Delta$。

**核心结论（易错重点）**：工作集反映进程在随后一段时间内很可能频繁访问的页面集合，因此**驻留集大小不应小于工作集大小**，否则运行中将频繁发生缺页。

**易错点**：工作集大小 $\leqslant \Delta$（窗口内有重复访问就更小），不是等于 $\Delta$。局部性越好，工作集相对越小。

**易错点**：工作集是**去重的页面集合**，重复访问的页只记一次。

**易错点**：工作集是**过去实际访问过**的页（回顾历史），用来**指导**驻留集大小；它本身不等于驻留集。

## KP54 页面缓冲算法：两个链表

**核心结论**：页框回收是 2025 年大纲新增考点，主要内容就是**页面缓冲算法**。（2012 年真题第 45 题已涉及：「被系统回收的页框，放入**空闲页框链尾**，其中内容在**下一次分配之前不清空**」——这正是空闲页面链表的定义。）

影响页面换入/换出效率的三个因素：① **页面置换算法的选择**；② **已修改页面写回磁盘的频率**；③ **磁盘内容读入内存的频率**。

页面缓冲算法在原置换算法之上维护两个专用链表：

| 链表 | 什么时候挂进去 | 好处 |
| --- | --- | --- |
| **空闲页面链表**（空闲页框链表） | **未被修改**的页面要换出时，**不写回磁盘**，直接把其所在物理页框挂到链表**末尾**——页框中**仍保留原有数据** | 进程要读入页面时从链表**头部**取页框；若后续有进程访问相同页面，可**直接取下该页框复用**，避免从磁盘重新读入，**减少换入开销** |
| **修改页面链表** | **已修改**的页面要换出时，**不立即写回**磁盘，把其页框挂到链表末尾 | 积累足够数量的脏页后**批量写回**，既降低写回频率，也减少因数据缺失而重新读盘的次数 |

用链表管理物理页框、**延迟实际 I/O** 的机制，即为**页框回收**的过程。

优点：① 显著降低换入/换出频率，大幅减少磁盘 I/O 开销；② **即使采用简单的置换策略（如 FIFO）也能获得良好性能**，且**无须特殊硬件支持**，实现简单高效。

**易错点**：空闲链表里的页框**内容不清空**（2012 真题原话），所以能复用。取用规则是**头部取、尾部挂**。

**易错点**：页面缓冲**不是一种置换算法**，是加在置换算法之上的缓冲机制。它的价值恰恰是让廉价算法也能跑出好性能。

## KP55 页框回收：哪些能回收、谁来回收

**核心结论**：系统可分配内存不足时必须回收部分页框，但**并非所有页框都可回收**：

| 大多**可以**回收 | **不可**回收 |
| --- | --- |
| **进程使用**的页框：进程代码段、数据段、堆栈、访问文件时映射的**文件页**、进程间**共享内存**占用的页框 | **内核的大部分页框**：内核栈、内核代码段、内核数据段、大部分内核使用的页框 |

Linux 内核设置了负责页面换出的守护进程 **kswapd**，定期检查内存使用情况，当**空闲页框数量低于特定阈值**时便主动发起页框回收。

**核心结论（易错重点）**：为什么不能等空闲页框完全耗尽才回收？因为释放某些页框（如**脏页**）通常要先**写回磁盘**，而该 I/O 操作本身**往往需要临时页框作为缓冲区**。若此时已无空闲页框，则既分配不出 I/O 缓冲区、也完不成页面释放，可能导致内核陷入**内存分配死锁**，甚至引发系统崩溃。

**回收机制**：Linux 用**伙伴算法**（3.1.2 节）统计和管理不同长度的连续空闲页框。分配是「化整为零」会产生外部碎片，回收则是伙伴算法的**逆操作**：释放一个页框时先检查是否存在**大小相等的伙伴空闲块**，存在则合并为**大小翻倍**的新空闲块，随后继续向上检查能否与更高一级伙伴再合并，直至无法合并为止。

**跨科关联**：本章 KP14（伙伴系统的判据：**同样大 + 地址相邻**）。

**易错点**：kswapd 是**提前**回收（低于阈值就动手），不是等耗尽才回收。原因是「写回脏页自己也要吃页框」——2025 新增考点里最可能出简答的一句。

**易错点**：共享内存和文件映射页属于**可回收**的一类（进程使用的）；内核栈、内核代码段不可回收。

## KP56 内存映射文件（真题）

**真题**：2025 考过内存映射文件的原理与特点。

**核心结论**：内存映射文件是 OS 向应用程序提供的一种**系统调用机制**，在**磁盘文件**与**进程虚拟地址空间**之间建立直接映射关系。此后进程可**像访问内存一样读写文件**——把文件当作内存中的一个**大字符数组**来访问，**无须调用传统的文件 I/O 接口**。磁盘读写由 OS 负责，对进程**透明**。

三个时机：

| 阶段 | 行为 |
| --- | --- |
| **映射时** | **不会立即加载**文件内容 |
| **首次访问某页时** | 才按需**一页一页调入**内存（即靠缺页机制） |
| **进程退出或显式解除映射时** | 所有**被修改的页面**才写回磁盘文件 |

**用于共享内存**：把**同一文件映射到多个通信进程**的虚拟地址空间。各进程虚拟地址空间相互独立，但 OS 通过**页表把它们对应的虚拟页映射到相同的物理页**。因此一个进程在共享区域写入后，另一个进程读取**立即看到更新**——二者访问的是**同一块物理内存**，数据必然一致，无须额外的复制。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-3-27.jpg]]（图 3.27 采用内存映射 I/O 的共享内存）

**跨科关联**：[[知识点/OS-02-进程与线程.md]] KP11（进程通信的分类与共享存储）。

两个好处：① **编程更简单**，已建立映射的文件可直接按内存方式读写；② 便于**多个进程共享同一磁盘文件**。

**易错点**：映射建立时**不读入任何内容**，靠**缺页**按需调入；写回是在**解除映射或进程退出**时，不是每次修改都立刻写盘。

**易错点**：教材说的「无须额外的复制或同步机制」指的是**数据可见性不需要额外拷贝**（同一物理页），**不代表多进程并发写不需要互斥**。

## KP57 虚拟存储器性能的五个影响因素（真题）

**真题**：2020、2022 考过请求分页系统性能的影响因素分析。

**核心结论**：**缺页率是影响虚拟存储器性能的核心因素**。缺页率受五方面影响：

| 因素 | 怎么影响缺页率 | 权衡 / 代价 |
| --- | --- | --- |
| **页面大小** | 页面**大** → 单次装入覆盖更多局部访问区域 → 缺页率**低**；页面**小** → 缺页率**高** | 小页面：减少页内碎片、提高内存利用率，但页面数多、**页表过长**占内存；大页面：**页表短**，但**页内碎片大**。需在碎片控制与页表开销间平衡 |
| **分配的物理块数** | 越多缺页率越低 | 超过某阈值后**改善趋于平缓**：活跃页面已基本常驻，缺页主要由本就无须长期驻留的非活跃页引发，再加块**收益甚微、浪费内存**。只需保证活跃页常驻即可 |
| **页面置换算法** | 好算法优先保留可能再被访问的页，提升内存命中率（如 LRU、CLOCK） | —— |
| **写回磁盘的频率** | 「每换出一页即写回」频繁触发磁盘 I/O，效率极低 | 用**已修改换出页面链表**批量写回；且写回前若进程再次访问这些页，可**直接从链表复用**，进一步减少换入 I/O（即 KP54） |
| **程序的局部化程度** | 局部化程度越高，缺页率越低 | 典型例子：数组**按行存储**就应**按行访问**；按列访问破坏空间局部性，缺页率异常升高 |

**易错点**：页面大小对**缺页率**和对**页表长度**的影响方向相反，所以「页面越大越好」是错的。

**易错点**：物理块数增加到一定程度后缺页率**改善平缓**，不是继续线性下降，也不是反而上升（那是 FIFO 的 Belady 异常，另一回事）。

## KP58 地址翻译示例（一）：字段划分套路（必会算）

**核心结论**：本节是 OS 与 CO（Cache）的综合题模板。给定条件——字节编址、虚拟地址 **14 位**、物理地址 **12 位**、页面 **64B**、TLB **四路组相联共 16 个条目**、data Cache **物理寻址、直接映射、行大小 4B、共 16 组**。

划分套路（**先算偏移，再切索引，剩下的高位是标记**）：

```
页内偏移 = log2(页面大小 64B) = 6 位
虚拟页号 = 14 - 6 = 8 位          物理页号 = 12 - 6 = 6 位
TLB 组数 = 16 条目 / 4 路 = 4 组 → TLB 组索引 = log2 4 = 2 位
   → 取虚拟页号的低 2 位作组索引，高 6 位作 TLB 标记
Cache 块内偏移 = log2(行大小 4B) = 2 位
Cache 组索引   = log2(16 组) = 4 位
Cache 标记     = 12 - 4 - 2 = 6 位
```

| 地址 | 字段结构（高位 → 低位） |
| --- | --- |
| **虚拟地址（14 位）** | TLB 标记 6 位 \| TLB 组索引 2 位 \| 页内偏移 6 位（前 8 位合起来 = 虚拟页号） |
| **物理地址（12 位）** | Cache 标记 6 位 \| Cache 组索引 4 位 \| 块内偏移 2 位（前 6 位合起来 = 物理页号） |

**跨科关联**：本章 KP22（快表 TLB）；CO 第 3 章 Cache 的组相联映射与地址划分（该章暂无卡片，二轮补）。

**易错点**：组相联的**组数 = 条目总数 ÷ 路数**，别直接拿条目数取对数。四路 16 条目是 **4 组**，索引 **2 位**。

**易错点**：TLB 的索引取**虚拟页号的低位**、标记取**虚拟页号的高位**，**页内偏移不参与 TLB 查找**。

**易错点**：Cache 是**物理寻址**，字段从**物理地址**上切；TLB 用**虚拟页号**。两套划分互不相干，别混用位宽。

## KP59 地址翻译示例（二）：三个地址的走查与完整流程

**核心结论**：完整的地址翻译与数据访问流程——

```
虚拟地址 → 查 TLB
   命中   → 得物理页号
   未命中 → 查页表
             有效位 = 1 → 得物理页号（并回填 TLB）
             有效位 = 0 → 缺页中断，从外存调入该页
→ 物理页号拼页内偏移 = 物理地址 → 查 Cache
   命中   → 直接取数据
   未命中 → 从主存读取所需数据
```

三个虚拟地址的走查（先转二进制，按 KP58 切字段）：

| 虚拟地址 | 二进制（14 位） | TLB 标记 / 组索引 | TLB 结果 | 物理页号 | 物理地址 |
| --- | --- | --- | --- | --- | --- |
| **0x03d4** | 00 0011 1101 0100 | 标记 **0x03**，组 **3** | **命中**（第 3 组有标记 03 且有效位 1） | 0x0d = 001101 | **0x354** |
| **0x00f1** | 00 0000 1111 0001 | 标记 **0x00**，组 **3** | **未命中** → 查页表：虚页号 **0x03**，有效位 1 | 0x02 = 000010 | **0x0b1** |
| **0x0229** | 00 0010 0010 1001 | 标记 **0x02**，组 **0** | **未命中** → 查页表：虚页号 **0x08**，**有效位 0** | —— | **触发缺页中断** |

再用物理地址查 Cache：

| 物理地址 | Cache 标记 / 组索引 | 块内偏移 | 结果 |
| --- | --- | --- | --- |
| **0x354** | 标记 **0x0d**，组 **5** | 0（块 0） | **命中**（组 5 标记 0d、有效位 1）→ 数据为 **36H** |
| **0x0b1** | 标记 **0x02**，组 **0xc** | 1 | **未命中**（组 0xc 有效位 0）→ 需从主存读物理页号 0x2、偏移 0x31 处的数据 |

**易错点**：0x00f1 的**虚拟页号是 0x03**（高 8 位），而 **TLB 标记是 0x00**（高 6 位），两者不同。查页表用**虚拟页号**，查 TLB 用**标记 + 组索引**，别拿标记去查页表。

**易错点**：**TLB 未命中 ≠ 缺页**——还要查页表，只有**页表项有效位为 0** 才缺页。同理 **Cache 未命中 ≠ 缺页**，只是多访问一次主存。

**易错点**：物理地址 = 物理页号**拼接**页内偏移（偏移 6 位原样照抄），**不是相加**。

## KP60 本节小结：三个思考题 + 置换与调度的联系

**1. 为什么要引入虚拟内存？** 多道程序并发使进程共享处理器和内存。并发进程增加时，每个进程获得的处理器时间**相对平滑地减少**；但**内存需求急剧上升**，某进程拿不到足够内存时甚至无法被加载运行。物理内存扩展受限，就必须**在逻辑上扩充**内存容量——虚拟内存由此而来。

**2. 虚存空间的大小由什么决定？** 主要由**虚拟地址的位数**决定。如 32 位虚拟地址 + 按字节编址 → 虚存空间最大 $2^{32}\text{B} = 4\text{GB}$。系统定义超过 4GB 的虚拟地址空间也无用，32 位地址最多只能寻址 4GB，**超出部分无法被访问**。

**3. 虚拟内存怎么解决问题？带来什么问题？** 利用外存在逻辑上扩充内存容量，通过页面换入/换出，使系统能运行**总规模远超物理内存**的多个进程。代价：① 每次缺页都要访问外存，**平均访存时间增加**；② 采用不合适的置换算法还可能**引发频繁缺页**（乃至抖动），降低系统性能。

**核心结论（串线索）**：页面置换算法要与**处理机调度算法**区分开，但二者内在相通——都属**资源调度**机制，核心思想都是**依据某种准则，决定把有限资源分配给哪个请求者**：

| 调度类型 | 准则 |
| --- | --- |
| **处理机调度** | 优先级、响应比、时间片 |
| **页面置换** | 页面的**使用历史**：是否被访问过、近期是否经常使用 |

OS 中几乎每类资源都有相应的调度策略。以「调度」为线索串联各类算法，有助于建立对 OS 整体架构的系统性理解。

**易错点**：虚存大小的**上限**由虚拟地址位数定，实际可用还受外存容量约束；但绝不是「内存容量 + 外存容量」之和。

**易错点**：CPU 利用率的两段走向别混：并发度上升初期 CPU 利用率**上升**，一旦驻留集不足引发抖动则**急剧下降**。
