# 1.1 计算机发展历程

## KP1 计算机的四代变化：划代看逻辑元件

**核心结论**：1946 年 ENIAC 问世至今共四代，**划代的唯一标准是逻辑元件**。

| 代 | 年份 | 逻辑元件 |
| --- | --- | --- |
| 一 | 1946—1957 | 电子管 |
| 二 | 1958—1964 | 晶体管 |
| 三 | 1965—1971 | 中小规模集成电路 |
| 四 | 1972—至今 | 大规模、超大规模集成电路 |

**记忆锚**：电子管 → 晶体管 → 中小规模集成电路 → 超大规模集成电路。四个词背下来即可，年份只需记住大致断点。

**易错点**：不是按主存介质、不是按软件形态、也不是按运算速度划代。ENIAC 本身**不是**冯·诺依曼机（它不采用存储程序方式），冯·诺依曼的存储程序思想是在 EDVAC 上提出的。

## KP2 各代计算机的配套特征

**核心结论**：

- 第一代：**机器语言**编程；主存用延迟线或磁鼓，容量极小；体积庞大、成本高昂；速度每秒几千至几万次。
- 第二代：主存用**磁芯存储器**；出现**高级语言及其编译程序**，形成**操作系统雏形**；速度几万至几十万次。
- 第三代：**半导体存储器**逐步取代磁芯；高级语言迅速普及；操作系统成熟，出现**分时操作系统**。
- 第四代：**微处理器**诞生；**并行处理、流水线、高速缓存、虚拟存储器**广泛应用。

**易错点**：

- 「操作系统雏形」在第二代，「分时操作系统」在第三代，两者常被互换来出题。
- 半导体存储器取代磁芯是**第三代**的事；Cache 与虚拟存储器是**第四代**才广泛应用。

## KP3 摩尔定律

**核心结论**：价格不变的前提下，**集成电路上可容纳的晶体管数量约每 18 个月翻一番**，性能随之显著提升。即 18 个月后同样的钱能买到理论性能约两倍的处理器。

**易错点**：

- 主语是「可容纳的晶体管数量」，不是速度、不是容量、不是价格下降幅度。
- 周期是 **18 个月**，不是 1 年也不是 2 年。
- 它是对发展节奏的经验性总结，不是物理定律。

## KP4 元件更新换代与机器字长

**核心结论**：

- 半导体存储器：1970 年美国仙童半导体公司研制出第一个较大容量的半导体存储器，单芯片容量从 1KB 一路发展到 TB 级。
- 微处理器：1971 年 Intel 推出第一款微处理器 **Intel 4004**；之后 8008（8 位）、8086（16 位）、Pentium（32 位）、Core i7（64 位）。
- 所谓 32 位机、64 位机指的是**机器字长（字长）**，即 **CPU 通用寄存器的宽度**。它决定一次整数运算能处理的数据位数，以及可直接寻址的内存空间大小。

**易错点**：机器字长 = 通用寄存器位数（通常也等于 ALU 宽度），别和**存储字长**（一个存储单元的位数）、**指令字长**、**数据字长**混同，这几者不必相等。

另一条：「字长决定可直接寻址的内存空间大小」只是常见情形，**字长与地址位数不必相等**——本 KP 里的 8086 就是反例，字长 16 位但地址总线 20 位、可寻址 1MB。做题以题目给的地址位数为准。

## KP5 计算机软件的发展

**核心结论**：

- 语言演进：**机器语言 → 汇编语言（面向机器）→ 高级语言（接近人的表达方式）**。
- 代表性高级语言：FORTRAN（科学与工程计算）、Pascal（结构化程序设计）、C++（面向对象）、Java（跨平台）。
- 系统软件以操作系统为代表：Windows、UNIX、Linux。

**易错点**：汇编语言仍属于**低级语言**，它只是机器语言的符号化形式，紧密依赖机器结构，不要因为「有助记符、好读」就归到高级语言。

# 1.2 计算机系统层次结构

## KP6 计算机系统的组成与软/硬件功能划分

**核心结论**：完整的计算机系统 = **硬件 + 软件**。硬件是有形的物理装置；软件是运行在硬件上的**程序及其相关的数据与文档**。

系统实际性能很大程度上取决于软件对硬件资源的利用效率，而这个效率能达到多高又由硬件提供的能力决定。所以系统设计必须合理划分软/硬件的功能边界：**使用频繁且硬件实现成本较低的功能，宜由硬件实现**。

**易错点**：软件不只是「程序」，还包括数据和文档。

## KP7 冯·诺依曼机的五大特点（真题）

**真题**：2019 考过冯·诺依曼机的特点。

**核心结论**：冯·诺依曼在研究 **EDVAC** 时首次提出「**存储程序**」思想。基于该思想的计算机统称冯·诺依曼机，五大特点：

1. 采用「存储程序」工作方式：程序和初始数据**预先存入主存**，启动后能**自动、连续**地取指并执行，直至结束，**无须人工干预**。
2. 硬件由**运算器、控制器、存储器、输入设备、输出设备**五大部件组成。
3. 指令和数据**以同等地位、相同形式存放在存储器中**，仅凭内容无法区分，但计算机应能识别它们。
4. 指令和数据都用**二进制**编码表示。
5. 指令由**操作码 + 地址码**组成：操作码指明操作类型，地址码指出操作数的地址。

**记忆锚**：存储程序、五部件、同形不同用、二进制、操作码＋地址码。

**易错点**：

- 「仅凭内容无法区分指令和数据」是重点：区分靠**取用时机与来源**（取指周期取出的是指令，执行周期取出的是数据），不是靠某个标志位。
- 五大部件里没有「总线」，也没有「CPU」——CPU 是运算器＋控制器集成后的产物。

## KP8 从「五大部件」到现代计算机的部件构成

**核心结论**：现代计算机把**运算器、控制器和各类寄存器**高度集成在一块芯片上，称为**中央处理器（CPU）**。完整的硬件系统包含：

**CPU + 存储器 + 输入/输出控制器 + 外部设备 + 总线**（总线用于协调各部件协同工作）。

**常考对照**：早期冯·诺依曼机**以运算器为中心**，输入/输出设备与存储器之间的数据传送都要经过运算器；现代计算机改为**以存储器为中心**，使 I/O 操作能尽量与运算并行，运算器不再是数据流的必经中转站。

**易错点**：「五大部件」是逻辑功能划分，「CPU／存储器／I/O」是物理实现划分，两套说法都对，问哪套答哪套。

## KP9 CPU：数据通路与控制单元

**核心结论**：CPU 是负责**执行指令**的核心部件。传统上分为运算器和控制器，现代架构中这两部分被组织为**数据通路**与**控制单元**。

| 部分 | 组成 | 职责 |
| --- | --- | --- |
| 数据通路 | **ALU** + **通用寄存器组** + 多路选择器、内部互连通路 | 执行实际运算的硬件通路。ALU 完成全部算术与逻辑运算；通用寄存器组为 ALU 提供操作数并暂存结果，是高速数据访问的关键 |
| 控制单元 | — | 取指令、译码，按指令语义产生一系列控制信号，指挥数据通路各部件（选源寄存器、配置 ALU 功能、启动运算、在正确时序下写回结果） |

**记忆锚**：数据通路管「数据往哪走、怎么算」，控制单元管「什么时候发什么信号」。ISA 定义「做什么」由控制单元翻译，数据通路负责「算出来」。

**易错点**：多路选择器、内部互连通路也属于**数据通路**的组成部分，不要以为数据通路只有 ALU 和寄存器。

## KP10 存储器的层次划分

**核心结论**：按访问特性分**内存**与**外存**。

- 现代**内存 = 主存 + 高速缓存（Cache）**；但 Cache 是后期才引入的，传统语境下「内存」**仅指主存**。
- 冯·诺依曼结构中，**主存**是核心的工作存储器，存放待执行的程序和数据。
- 外存分两类：① 可与主存交换数据的磁盘、固态硬盘等；② 用于长期备份的海量存储设备，如磁带、光盘。

**易错点**：题目说「内存」时要看语境——传统题里等同主存，讲存储层次时才把 Cache 算进来。

## KP11 外部设备与设备控制器

**核心结论**：外部设备（外设、I/O 设备，I/O = Input/Output）通常由两部分组成，二者在功能或物理实现上往往**相互分离**：

- **物理功能部件**：打印头、鼠标滚轮、按键等，负责实际的输入/输出动作。
- **设备控制器**：负责与主机通信，并控制物理功能部件工作。

外设通过设备控制器接到主机上，各种设备控制器统称 **I/O 控制器**或 **I/O 接口**。例如键盘接口、显示控制器（显卡）、网络控制器（网卡）都是设备控制器。

**易错点**：显卡、网卡是**设备控制器 / I/O 接口**，不是「外设本身」，也不是 CPU 的一部分。

## KP12 总线与典型的多总线硬件系统

**核心结论**：总线是各部件之间传输信息的**公共通路**。CPU、主存、I/O 接口通过总线互连；CPU 和 I/O 接口内部都含寄存器，部分还集成了 Cache。

图 1.1 的连接关系：CPU（内含控制器、ALU、寄存器堆、总线接口部件）经**处理器总线**、通过 **I/O 桥接器**与主存和 I/O 设备通信；主存经**存储器总线**、通过 I/O 桥接器与 CPU 和 I/O 设备相连；各类 I/O 设备通过自己的控制器（USB 控制器、显示适配器等）接入 **I/O 总线**。

按功能给部件归类（常考）：

| 类别 | 成员 |
| --- | --- |
| 数据处理部件 | ALU |
| 存储部件 | 主存（临时存储）、磁盘（长期存储） |
| 互连结构 | 所有总线、桥接器、接口、控制器 |

## KP13 系统软件与应用软件

**核心结论**：

- **系统软件**：保障计算机系统高效、正确运行的基础软件，管理和调度系统资源，为用户及应用程序提供基础服务。典型成员：**操作系统、数据库管理系统（DBMS）、语言处理程序、网络与分布式软件系统、标准库程序、服务性程序**。
- **应用软件**：用户为解决特定应用领域问题而开发的程序，如科学计算、工程设计、数据统计与信息处理类软件。

**易错点**：**语言处理程序（编译器、汇编器、解释器）和标准库程序属于系统软件**，这是高频送分点；DBMS 也是系统软件，不是应用软件。

## KP14 软/硬件逻辑功能的等价性

**核心结论**：最基本的操作（算术、逻辑运算）通常由硬件直接实现，更复杂的功能可由软件完成。对某一特定功能，硬件实现和软件实现在**相同规范下逻辑功能等价**——这就是软/硬件逻辑功能的等价性。

例：浮点运算既可由专用浮点运算器硬件实现，也可用软件子程序模拟；在相同输入和数值规范（如 IEEE 754）下结果一致，但**硬件实现的效率通常远高于软件**。

意义：等价性是系统设计的重要依据，如何划分软/硬件功能边界是**计算机体系结构**的核心问题之一，要综合权衡设计目标、成本效益、技术可行性。

**易错点**：等价只是**逻辑功能等价**，性能、成本都不等价。别答成「软硬件完全一样」。

## KP15 计算机系统的多级层次结构

**核心结论**：计算机系统采用多级层次结构，用逐层抽象把复杂的硬件实现与高层应用需求隔开。**每层向上提供简洁的接口，向下依赖更底层的功能实现。**

好处：明确软/硬件的职责边界，使系统开发和维护能并行高效地进行。

## KP16 三种编程语言的特点（真题）

**真题**：2015、2024 都考过三种编程语言的特点。

**核心结论**：编程语言分**高级语言**与**低级语言**。高级语言独立于底层硬件结构；低级语言紧密依赖机器结构，特指**机器语言及其符号化形式——汇编语言**。

| 语言 | 形式 | 能否被硬件直接执行 | 说明 |
| --- | --- | --- | --- |
| 机器语言 | 0/1 指令序列（二进制代码语言） | **能，且是唯一能被直接识别执行的** | 程序员需熟记每条指令的二进制编码 |
| 汇编语言 | 英文助记符（mov、add）或其缩写 | **不能**，必须经**汇编程序**翻译成机器语言 | 可读性、记忆性大幅提升 |
| 高级语言 | C、C++、Java 等，接近自然语言 | 不能，需经**编译程序**处理 | 或先编译成汇编再汇编成机器语言，或直接编译成目标机器语言 |

**记忆锚**：只有机器语言能直接跑；汇编要汇编器；高级语言要编译器（可能中途落一次汇编）。

**易错点**：

- 「汇编语言可以被 CPU 直接执行」是错的；「汇编语言是低级语言」是对的。
- 高级语言的编译产物不一定是机器语言，也可能是汇编语言（再交给汇编器）。

## KP17 三类翻译程序（真题）

**真题**：2016 考过各种翻译程序的概念。

**核心结论**：把源程序转换为机器语言程序的系统软件叫**翻译程序**，转换后生成的程序叫**目标程序**。三类：

| 翻译程序 | 输入 → 输出 | 是否生成独立目标程序 |
| --- | --- | --- |
| **汇编程序（汇编器）** | 汇编语言源程序 → 机器语言目标程序 | 是 |
| **解释程序（解释器）** | 高级语言语句 → 逐条翻译并**立即执行** | **否** |
| **编译程序（编译器）** | 高级语言源程序 → **一次性**翻译为汇编语言或机器语言目标程序 | 是 |

**记忆锚**：编译器「先全译后跑」，解释器「边译边跑不留产物」，汇编器只处理汇编语言。

**易错点**：解释程序**不产生目标程序**，这是它与编译程序最本质的区别；不要答成「解释器速度慢」这类表面差异。

## KP18 操作系统在层次中的位置

## KP19 指令集体系结构 ISA

**核心结论**：**ISA（Instruction Set Architecture）是计算机软/硬件之间的关键接口**，从程序员和编译器的视角完整定义了**软件可直接使用的硬件功能**，主要包括：

- 指令格式
- 操作类型
- 寻址方式
- 可访问的寄存器等硬件资源

因此 ISA 就是软件所能「感知」到的计算机功能视图，也称**软件可见部分**。机器语言程序本质上是一串严格遵循该 ISA 规范的指令序列；硬件执行程序的过程就是逐条解释并完成这些指令所规定操作的过程。

**易错点**：ISA 规定「有哪些指令、能用哪些寄存器」，**不规定**这些指令用几级流水线、多大 Cache 去实现——那是微体系结构的事。

## KP20 微体系结构

**核心结论**：微体系结构（微架构）是**处理器内部的硬件组织方式**，用于实现 ISA 定义的功能。**ISA 定义「做什么」，微架构决定「怎么做」。**

核心设计内容：数据通路组织、控制单元实现、**流水线级数**、**缓存层次结构**、**分支预测机制**等。

关键关系：**同一套 ISA 可以对应多种不同的微架构**。例如 Intel x86 的 Core、Skylake、Alder Lake 各代处理器都遵循同一 ISA，但内部组织差异显著；又如加法既可用串行进位加法器、也可用超前进位加法器甚至专用 SIMD 单元实现，这些都属于微架构范畴。

**易错点**：Cache 容量、流水线级数、加法器类型都是**微架构**层面的东西，属于对软件透明的实现细节；寄存器数量、寻址方式属于 **ISA**。

## KP21 四类用户与「透明性」

**核心结论**：按使用计算机完成任务的性质分四类用户，各自工作在不同抽象层级：

| 用户 | 做什么 | 工作层次 |
| --- | --- | --- |
| **最终用户** | 直接操作应用程序完成任务（办公、浏览网页），无须了解底层细节 | 应用程序层（最上层） |
| **系统管理员** | 配置、管理、维护系统：装软/硬件、管账户、备份数据、升级系统 | 操作系统层 |
| **应用程序员** | 用高级语言开发应用软件 | 高级语言层 |
| **系统程序员** | 开发操作系统、编译器、DBMS 等核心系统软件 | 机器语言层，直接面向 ISA |

同一个人在不同场景可承担多种角色：网上购物是最终用户，管磁盘、备份数据是系统管理员，写程序作业是应用程序员，参与 OS 开发是系统程序员。

图 1.3 的关键结构：**ISA 位于软/硬件交界处**。ISA 以下是硬件层（CPU、主存、I/O 设备），ISA 以上是软件层（系统软件与应用软件）。

教材图示（图 1.3 计算机系统的层次与各层用户）：[[王道教材/27 王道计算机组成原理/pictures/ffe4fa9bcdc89d756e33e1157b4c78274262aa2d78e5d37a8f42a6b606131b0a.jpg]]

**透明性**：下层机器的结构特性对上层用户通常是「**透明**」的。例如 ISA 之下的硬件实现细节对高级语言程序员是透明的。

**易错点**：计算机领域的「透明」= **看不见、不必知道**，和日常「透明＝公开」相反，这是高频陷阱。

## KP22 「存储程序」工作方式与 PC 的更新

**核心结论**：程序执行前，必须把它的**指令和数据预先加载到主存**；一旦启动，计算机**无须人工干预**，自动逐条取出并执行指令。程序执行就是一个周而复始的指令执行过程，每条指令通常包括：

**取指令（地址由 PC 提供）→ 指令译码 → 取操作数 → 执行操作 → 结果写回存储器**

PC 的更新规则（在每条指令执行的最后阶段完成）：

- **顺序指令**：下一条指令地址 = 当前 PC 值 + 指令长度
- **跳转指令**：下一条指令地址 = 指令中指定的目标地址

程序开始执行前，先把第一条指令的地址存入 PC；取指令时 CPU 用 PC 的内容作地址访问主存；更新 PC 后再取下一条，从而实现指令流的自动连续执行。

教材图示（图 1.4 程序执行过程）：[[王道教材/27 王道计算机组成原理/pictures/5f498e4f3fc21645b68fb2e61f8f6875d2379ce87efdf7dbd37720cf123ad11f.jpg]]

**易错点**：

- PC 的更新发生在**指令执行的最后阶段**（教材此处的表述），不要死记「取指后立即 +1」——这两种说法在不同教材/题目里都出现过，看题目给的时序描述作答。
- 「+ 指令长度」不等于「+1」，只有按字编址且指令定长为一个字时才是 +1。

## KP23 从源程序到可执行文件的四个阶段（真题）

**真题**：2022 考过翻译过程的四个阶段。

**核心结论**：以 UNIX 下 GCC 处理 hello.c 为例，四阶段生成可执行文件 hello：

| 阶段 | 工具 | 输入 → 输出 | 做什么 |
| --- | --- | --- | --- |
| 1 预处理 | **预处理器 cpp** | hello.c → **hello.i** | 处理以 # 开头的预处理指令，如把 `#include<stdio.h>` 替换为头文件的完整内容 |
| 2 编译 | **编译器 cc1** | hello.i → **hello.s** | 翻译为汇编程序，每条语句以文本形式描述一条低级机器指令 |
| 3 汇编 | **汇编器 as** | hello.s → **hello.o** | 转换为机器语言指令，生成**可重定位目标文件**（二进制格式，含代码、数据及符号信息） |
| 4 链接 | **链接器 ld** | hello.o + 标准 C 库 → **hello** | 链接所需库函数（如 printf），解析外部符号引用，生成完整可执行文件存到磁盘 |

**记忆锚**：`.c → .i → .s → .o → 可执行`，对应 cpp、cc1、as、ld。

教材图示（图 1.5 源程序转换为可执行文件的过程）：[[王道教材/27 王道计算机组成原理/pictures/eeab0da27dbd68333d9bbcfe0c0a848e23b3c041caef16f2647342b025813276.jpg]]

**易错点**：

- **.o 是可重定位目标文件，不能直接执行**；能执行的只有链接后的可执行目标文件。
- printf 的代码不在 hello.o 里，是**链接阶段**才从标准 C 库并入的。
- 编译阶段的产物是**汇编程序（文本）**，不是二进制。

## KP24 指令执行过程的抽象模型

**核心结论**：可执行文件的代码段由一条条机器指令构成，每条指令是一串二进制编码，指示 CPU 完成一个特定的基本操作。指令执行可建模为经典的「**取指 — 译码 — 执行**」三阶段循环。

这个循环在硬件上如何一步步实现（控制器工作原理、数据通路结构、时序信号控制），是第 5 章「中央处理器」的内容。

**易错点**：KP22 给的是含取操作数、写回的五步细化流程，本条给的是三阶段抽象模型，两者是同一件事的不同粒度，别当成两套矛盾的说法。

## KP25 本节小结：1.1—1.2 的骨架

**核心结论**：

- **1.1 讲「变」**：逻辑元件四代变化 + 摩尔定律 + 字长（通用寄存器宽度）+ 语言与系统软件演进。
- **1.2 讲「分层」**：一切围绕两条主线——
  - **纵向分层**：应用问题 → 算法 → 高级语言 → 操作系统 → **ISA（软/硬件分界）** → 微体系结构 → 物理器件。四类用户各站一层，下层对上层**透明**。
  - **横向划分**：硬件（CPU = 数据通路 + 控制单元；存储器；I/O 接口 + 外设；总线）与软件（系统软件 / 应用软件），边界由**软/硬件逻辑功能等价性**加成本效益权衡来定。
- **1.2.6 讲「怎么跑起来」**：存储程序方式（PC 驱动的自动连续执行）+ 源程序四阶段翻译（cpp/cc1/as/ld）+ 取指—译码—执行循环。

**易错点**：本章的分数几乎全在**概念归属**上：某个东西属于系统软件还是应用软件、属于 ISA 还是微架构、属于数据通路还是控制单元、属于第几代。做题时先定「问的是哪条边界」。
