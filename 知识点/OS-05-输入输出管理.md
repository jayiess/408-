# 5.1 I/O 管理概述

## KP1 I/O 设备的两部分组成

**核心结论**：一个 I/O 设备 = **设备本身** + **设备控制器**。

| 部分 | 是什么 | 干什么 |
| --- | --- | --- |
| 设备本身 | 执行输入/输出的物理装置（磁盘的盘片与磁头） | 真正的机械/电子动作 |
| 设备控制器 | 挂在**系统总线**上的专用电路（接口芯片） | 把 OS 的抽象命令（「读第 x 个扇区」）翻译成设备认的电信号，协调主机与设备的数据传输 |

**核心结论**：I/O 管理的核心手段是**软硬件协作屏蔽物理差异**，让应用程序用统一方式使用各类设备。

**易错点**：设备控制器是**连到系统总线上**的，不是长在设备内部的附属品。它面向总线一侧和面向设备一侧是两套不同的接口（见 KP6）。

## KP2 按信息交换单位分类：块设备与字符设备

**核心结论**：

| 类型 | 交换单位 | 传输速率 | 可否寻址 | 常用控制方式 | 例子 |
| --- | --- | --- | --- | --- | --- |
| 块设备 | 固定大小的**数据块** | 较高 | **可寻址**（支持随机访问） | DMA | 磁盘 |
| 字符设备 | **字符/字节** | 较低 | **不可寻址**（只能顺序存取） | 中断 | 键盘、终端、打印机 |

**易错点**：「可寻址」= 能对任意数据块直接读/写。字符设备不可寻址，所以接口层要给它配**字符缓冲区**，靠 get/put 顺序存取（见 KP33）。

**易错点**：块设备用 DMA、字符设备用中断，是**因为交换单位不同**（块 vs 字节），不是因为速度快慢。中断方式按字节干预，用在块设备上极其低效（见 KP15）。

## KP3 按传输速率分类

**核心结论**：

| 档 | 速率 | 例子 |
| --- | --- | --- |
| 低速设备 | 每秒几字节 ~ 数百字节 | 键盘、鼠标 |
| 中速设备 | 每秒数千字节 ~ 数十千字节 | 激光打印机 |
| 高速设备 | 每秒数百千字节 ~ 数百兆字节 | 磁盘 |

**易错点**：激光打印机是**中速**设备，不是低速。但它同时是**独占**设备（见 KP5）——速率分类和共享属性分类是两套独立维度，别混。

## KP5 按共享属性分类：独占、共享、虚拟设备

**核心结论**：

| 类型 | 并发性 | 机制 | 例子 |
| --- | --- | --- | --- |
| 独占设备 | 任一时刻**仅一个**进程使用，分配后独占到释放 | 互斥分配 | 打印机（典型独占设备多为低速设备） |
| 共享设备 | 多个进程**逻辑上并发**访问，分时交替使用 | 物理访问仍需调度协调 | 磁盘 |
| 虚拟设备 | 一台独占设备改造成多个逻辑设备，多进程并发使用 | **SPOOLing 技术** | 用磁盘做缓冲的打印机 |

**核心结论（易错重点）**：虚拟设备的实质是**拿高速共享设备（磁盘）当缓冲区**，把独占设备变成逻辑上可共享。

**易错点**：共享设备是「逻辑上并发」，**物理上仍然要排队调度**。说磁盘「可以同时被多个进程读写」是错的。

**易错点**：虚拟设备不是新增了硬件，是 SPOOLing 软件营造出的假象。原来的独占设备本身还是独占的。

## KP6 I/O 接口（设备控制器）的三部分组成

**核心结论**：I/O 接口就是设备控制器，是 CPU 与设备之间的桥梁，让 CPU 从琐碎的设备控制里解脱。三部分组成：

| 部分 | 内容 | 作用 |
| --- | --- | --- |
| 与 CPU 的接口 | **数据线 + 地址线 + 控制线** | 数据线传数据/控制/状态信息；地址线指定接口内**寄存器编号**；控制线传读/写控制信号 |
| 与设备的接口 | 一个或多个设备接口 | 一个控制器可连多个设备，每个接口传数据、控制、状态三类信号 |
| I/O 逻辑 | 命令译码 + 地址识别 | 通过控制线与 CPU 交互，对 I/O 命令译码，按目标地址识别相应设备 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-1.jpg]]（图 5.1 设备控制器的组成）

**易错点**：地址线送来的地址是**接口内寄存器的编号（端口号）**，不是内存地址、也不是磁盘扇区地址。

**易错点**：CPU 启动设备时只发「启动命令 + 目标地址」，具体挑哪台设备是 **I/O 逻辑**解析出来的，CPU 不管。

## KP7 设备控制器的六项功能

**核心结论**：① 接收并识别命令（磁盘控制器响应读、写、寻道）；② 完成数据交换（CPU↔控制器、控制器↔设备）；③ 标识并报告设备状态供 CPU 查询；④ 地址识别；⑤ 数据缓冲；⑥ 差错控制。

**核心结论**：以磁盘控制器为例——收到「读第 11408 个扇区」后，它**自己**把线性扇区号换算成柱面号、盘面号、扇区号，控制磁头定位、等旋转延迟、读数据、传到内存。OS 只发命令，不碰硬件细节。

**易错点**：**线性扇区号→柱面/盘面/扇区**这个换算，教材在两处都提过：这里说是磁盘控制器做，KP26 说是磁盘驱动程序做。区分——**驱动程序**把「读逻辑块 5」这种逻辑请求转成物理参数写进控制器寄存器，**控制器**再据此做机械定位。考试问「谁把逻辑地址转成物理地址」时看题干是软件层还是硬件层。

**易错点**：数据缓冲是控制器的功能之一，目的是**匹配 CPU 与设备的速度差**，不是为了提高设备本身速度。

## KP8 I/O 接口的四种分类

**核心结论**：

| 分类角度 | 类型 |
| --- | --- |
| 数据传送方式（设备侧） | **并行接口**（一个字节/字的所有位同时传）、**串行接口**（一位一位有序传） |
| 主机控制方式 | 程序查询接口、中断接口、DMA 接口 |
| 功能灵活性 | 可编程接口（编程改变功能）、不可编程接口 |
| 设备类型 | 字符设备接口、块设备接口、网络设备接口 |

**易错点**：接口必须完成**并/串或串/并格式转换**——主机侧总是并行的，设备侧可能串行，转换责任在接口。

## KP9 I/O 端口：三类寄存器

**核心结论**：I/O 端口 = 设备控制器中**可被 CPU 访问的寄存器**。三类：

| 寄存器 | 方向 | 内容 |
| --- | --- | --- |
| 数据寄存器 | 双向 | 缓存设备送来的输入数据，或暂存 CPU 发出的输出数据 |
| 状态寄存器 | CPU **读** | 设备的状态或执行结果 |
| 控制寄存器 | CPU **写** | 启动操作、设置设备工作模式 |

**易错点**：状态寄存器只读、控制寄存器只写，方向别写反。驱动程序「检查设备是否就绪」读的是**状态**寄存器，「发启动信号」写的是**控制/命令**寄存器（见 KP26）。

**易错点**：「端口」在这里指**寄存器**，不是网络端口。每个端口要有唯一的端口地址，所以需要编址（见 KP10、KP11）。

## KP10 独立编址（I/O 映射方式）

**核心结论**：给 I/O 端口开一个**独立于主存**的地址空间。端口地址与内存地址逻辑上完全分离，**地址值可以相同也不冲突**。CPU 用**专用 I/O 指令**（x86 的 IN / OUT）访问，指令的地址字段给端口号。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-2.jpg]]（图 5.2 独立编址 I/O 和内存映射 I/O）

| | 内容 |
| --- | --- |
| 优点 | 端口数远少于内存单元 → 地址线少、译码电路简单、寻址快；专用 I/O 指令使程序里的 I/O 操作**清晰可辨**,便于阅读调试 |
| 缺点 | I/O 指令功能有限（通常只支持简单数据传输），编程灵活性差；CPU 要同时提供**存储器读/写和 I/O 读/写两组控制信号**,控制逻辑变复杂 |

**易错点**：独立编址的地址值和内存地址相同**不会冲突**,因为分属两个地址空间，靠指令类型（I/O 指令 vs 访存指令）区分，不靠地址范围。

## KP11 统一编址（内存映射方式）

**核心结论**：把**一部分主存地址空间**划给 I/O 端口，端口与内存单元共享同一地址空间。靠**地址范围**区分访问目标（如高地址段映射到 I/O），所以**无须专用 I/O 指令**,普通的 load/store 访存指令就能访问端口。

| | 内容 |
| --- | --- |
| 优点 | 无须专用 I/O 指令，编程灵活；I/O 端口可获得较大编址空间；I/O 访问的**保护机制可由虚拟存储管理系统统一实现**,无须额外硬件 |
| 缺点 | 端口占用主存地址空间，**减少可用内存容量**；需按完整地址判断是否为 I/O 区域，译码电路复杂，通常**降低译码速度** |

**核心结论（易错重点）**：两种编址方式的判据是「**靠什么区分是访存还是访 I/O**」——独立编址靠**指令类型**,统一编址靠**地址范围**。

**易错点**：统一编址的译码**更慢、更复杂**,别按直觉写成「省了专用指令所以更快」。它省的是指令种类，付出的是译码代价和内存空间。

**易错点**：「保护机制由虚存管理统一实现」是统一编址**独有**的优点——因为端口在主存地址空间里，现成的页保护机制直接生效。

## KP12 I/O 控制方式的总宗旨

**核心结论**：I/O 控制 = 控制**设备与主机之间的数据传送**。四种方式的演化贯穿一个宗旨：**尽量减少 CPU 对 I/O 控制的干预**，把 CPU 从繁杂的 I/O 事务里解脱出来去算题。

**核心结论**：每种方式的优点，都是在解决前一种方式的主要缺点。

```
程序直接控制  → CPU 轮询等待，串行
   ↓ 加中断机制
中断驱动      → 并行了，但按字节干预、必经 CPU 寄存器
   ↓ 加 DMA 控制器
DMA          → 按块传、不经 CPU，但参数要 CPU 预设、一控制器一设备
   ↓ 加通道（专用处理机）
通道控制      → 执行通道程序自主决定参数，一通道管多设备
```

**易错点**：宗旨是减少**干预频率**，不是减少「CPU 参与」到零。即使通道方式，CPU 也要发 I/O 指令、也要响应结束中断。

## KP13 程序直接控制方式（程序轮询）

**核心结论**：CPU 发一条 I/O 指令，从设备读**一个字（节）**，然后不断**循环测试设备状态（轮询）**，直到确认该字（节）已在控制器的数据寄存器中；CPU 再把数据取出送入内存指定单元。一个字（节）的 I/O 就此完成。

| 项 | 内容 |
| --- | --- |
| 干预粒度 | 一个字（节） |
| 并行性 | **CPU 与设备只能串行工作** |
| 数据路径 | 设备 → 控制器数据寄存器 → CPU → 内存 |
| 优点 | 简单、易实现 |
| 缺点 | CPU 绝大部分时间耗在循环测试上，因两者速度差异巨大，**CPU 利用率极低** |

**核心结论（易错重点）**：CPU 之所以必须不断轮询，根因是**CPU 中未采用中断机制**，设备没法主动报告「我这个字节读完了」。

**易错点**：轮询方式下 CPU **没有闲着**，它在忙等（busy waiting），是「有效工作率低」而不是「空闲」。

## KP14 中断驱动方式：从设备控制器角度看

**核心结论**：中断驱动的思想是**允许 I/O 设备主动打断 CPU 并请求服务**，CPU 发出 I/O 指令后可以去干别的活。

控制器一侧的流程：

```
收 CPU 读命令 → 从设备读数据 → 数据入控制器数据寄存器
→ 经控制线向 CPU 发中断信号（表示数据已就绪）
→ 等 CPU 来请求数据 → 把数据放上数据总线，传到 CPU 寄存器
→ 本次 I/O 完成，可开始下一次
```

**易错点**：控制器发中断后**不是立刻送数**，而是**等 CPU 发来取数请求**才把数据放上总线。中断信号只是通知，不是传数据。

## KP15 中断驱动方式：从 CPU 角度看 + 两大缺陷（真题）

**真题**：2017、2023 考过中断处理程序执行时请求进程的状态。

**核心结论**：CPU 一侧的流程：

```
运行进程发读命令 → 该进程被阻塞 → 保存其上下文，转去执行其他程序
→ 每个指令周期末尾检查中断信号
→ 有中断 → 保存当前运行进程的上下文 → 执行中断处理程序
→ 中断处理程序从控制器数据寄存器读一个字节（字），写入内核缓冲区
→ 处理完，解除原 I/O 请求进程的阻塞状态，恢复相应进程上下文继续执行
```

**核心结论（易错重点）**：中断处理程序执行期间，**发出 I/O 请求的那个进程处于阻塞态**，且它此时并未在 CPU 上运行；被中断打断的是**另一个**正在运行的进程。

| 缺陷 | 说明 |
| --- | --- |
| ① 数据必经 CPU | 设备与内存之间的数据交换都要过 **CPU 中的寄存器** |
| ② 干预粒度太细 | CPU 以**字（节）**为单位干预，用于块设备 I/O 极其低效 |

**易错点**：中断检查发生在**每个指令周期的末尾**，不是随时打断指令中间。

**易错点**：中断处理程序把数据写入的是**内核缓冲区**，不是直接给用户空间。

**易错点**：I/O 完成后是「解除阻塞」，进程进入**就绪态**，不是直接回到运行态。

## KP16 DMA 方式的三个特点与四类寄存器（真题）

**真题**：2017 考过 DMA 方式的工作流程。

**核心结论**：DMA（直接存储器存取）的核心思想是在**设备与内存之间建立直接数据通路**。三个特点：

| 特点 | 内容 |
| --- | --- |
| ① 传送单位 | **数据块**，不再是字（节） |
| ② 数据路径 | 数据**直接在设备与内存之间**传输，不再经过 CPU |
| ③ 干预时机 | 仅在数据块传送的**开始和结束**时需要 CPU 干预 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-4.jpg]]（图 5.4 DMA 控制器的组成）

DMA 控制器的四类寄存器：

| 寄存器 | 全称 | 存什么 |
| --- | --- | --- |
| CR | 命令/状态寄存器 | 暂存 CPU 发来的 I/O 命令或设备状态 |
| MAR | 内存地址寄存器 | 数据在内存中的**起始地址**。输入（设备→内存）时是写入目标地址；输出（内存→设备）时是读取源地址 |
| DR | 数据寄存器 | 暂存**单次传输**的数据单元（如一个字） |
| DC | 数据计数器 | 本次需传送的字（节）**总数** |

**易错点**：DMA 控制器里**仍有数据寄存器 DR**——「不经过 CPU」指不经过 **CPU 的寄存器**，不是不经过任何寄存器。数据是一个字一个字过 DR 的，只是整块传完才通知 CPU。

**易错点**：MAR 的含义随方向翻转，考题喜欢在这里设「输入时 MAR 存源地址」的错项。

## KP17 DMA 的工作过程与优点（真题）

**真题**：2017 考过 DMA 方式的工作流程。

**核心结论**：

```
CPU 收到设备的 DMA 请求
→ 向 DMA 控制器发启动命令，设置 MAR 和 DC 的初值
→ 启动 DMA 控制器，把 I/O 控制权交出，CPU 转去执行其他任务
→ DMA 控制器接管总线，以突发方式把整块数据在设备与内存间直接传输（无 CPU 干预）
→ 传输结束，DMA 控制器向 CPU 发中断信号
```

| 优点 | 相比谁 |
| --- | --- |
| 数据以「块」为单位传输，CPU **干预频率进一步降低** | 相比中断方式 |
| 数据不再经过 CPU 寄存器，CPU 与设备**并行程度进一步提升** | 相比中断方式 |

**易错点**：MAR 和 DC 的初值是 **CPU 设置**的，这正是 DMA 与通道方式的分界（见 KP19）。

**易错点**：DMA 控制器要**接管总线**才能传数据，此期间 CPU 不能用总线访存。所以「CPU 完全不受影响」是错的，它受总线争用影响。

## KP18 通道控制方式

**核心结论**：I/O 通道是一种**专用处理机**，能执行存放在**主存**中的通道程序（由一系列专用通道指令组成）。

```
CPU 只发一条 I/O 指令 → 指明目标设备 + 通道程序在内存中的起始地址
→ 通道自主执行通道程序，完成全部 I/O 操作
→ 结束后向 CPU 发中断请求
```

**核心结论**：设置通道后，**CPU、通道、I/O 设备三者可高效并行**。

**易错点**：通道程序放在**主机内存**里，不在通道自己的存储器里——通道**没有独立的主存储器**。

## KP19 通道 vs 通用处理机 vs DMA

**核心结论（易错重点）**：

| 对比 | 差异点 |
| --- | --- |
| 通道 vs 通用处理机 | 通道指令集**专用于 I/O 控制**，功能单一；通道**无独立主存储器**，通道程序和数据都在主机内存中；所有**访存操作均受 CPU 控制** |
| 通道 vs DMA | DMA 需 **CPU 预设**数据块大小、内存始址等参数；通道**通过执行程序动态确定参数**，能自主完成涉及多台设备、多个阶段的复杂 I/O 任务 |
| 服务设备数 | 一个 DMA 控制器通常**只服务一台设备**；一个通道可**同时管理多台设备**与内存的数据交换 |

**易错点**：通道虽是处理机，但它的访存仍**受 CPU 控制**，不是完全独立自治的第二个 CPU。

**易错点**：区分 DMA 与通道的两个判据要一起记——**参数谁定**（CPU 预设 vs 程序动态）和**管几台设备**（一对一 vs 一对多）。

## KP20 四种 I/O 控制方式总表 + 裁缝店类比

**核心结论**：

| 方式 | 干预粒度 | 数据是否经 CPU 寄存器 | 并行性 | 关键新增硬件 |
| --- | --- | --- | --- | --- |
| 程序直接控制 | 一个字（节），全程忙等 | 是 | 无（串行） | 无 |
| 中断驱动 | 一个字（节），完成时中断 | **是** | 设备准备数据期间并行 | 中断机制 |
| DMA | 一个**数据块**，首尾干预 | **否** | 整块传输期间并行 | DMA 控制器 |
| 通道 | 一组通道程序（可跨多设备多阶段） | 否 | CPU / 通道 / 设备三者并行 | I/O 通道（专用处理机） |

裁缝店类比（客户 = CPU，裁缝 = 设备）：

| 方式 | 类比 |
| --- | --- |
| 程序直接控制 | 裁缝没客户电话，客户每隔一会儿亲自跑去店里看做好没 |
| 中断驱动 | 裁缝有电话了，每做完**一件**就打电话叫客户来取，还是每件跑一趟 |
| DMA | 客户雇了秘书，衣服暂存指定仓库，秘书直接对接裁缝，**每 100 件**才向客户汇报一次 |
| 通道 | 客户给秘书一份**办事清单（通道程序）**，秘书自主决定存放位置和汇报时机（100 件还是 10000 件自己判断），且**一个秘书能协调多位裁缝** |

**易错点**：中断驱动和 DMA 都在「完成时发中断」，区别在**中断的频率**——中断驱动每字节一次，DMA 每块一次。

## KP21 I/O 软件层次化设计的理由与四层划分（真题高频）

**真题**：2011、2012、2013 考过 I/O 子系统各层次的功能及分析。

**核心结论**：I/O 软件向下与硬件密切相关，向上与虚拟存储器系统、文件系统及用户直接交互。分层的目的是获得**清晰的结构、良好的可移植性和适应性**。

**核心结论（易错重点）**：分层原则——**每层利用其下层提供的服务**，完成 I/O 功能中的特定子任务，并**屏蔽其实现细节**，向上层提供统一接口。只要层间接口不变，任一层的修改都不影响其他层；**仅最低层涉及硬件的具体特性**。

自上而下四层：

```
用户层软件         ← 库函数、与用户交互，必须通过系统调用获取 OS 服务
设备独立性软件      ← 所有设备的公共操作 + 逻辑设备名→物理设备名
设备驱动程序        ← 每类设备一个，抽象请求→具体指令
中断处理程序        ← 最底层，直接与硬件打交道
--------------------
硬件
```

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-5.jpg]]（图 5.5 I/O 层次结构）

**易错点**：**中断处理程序是最底层**（最接近硬件），不是最上层。层次图从上往下是「用户层 → 设备独立性 → 驱动 → 中断处理 → 硬件」，考题常把驱动和中断处理的上下顺序写反。

**易错点**：「仅最低层涉及硬件具体特性」——严格说驱动程序也与硬件相关，但硬件**特性差异**的最终收口在最低层。四层里**用户层的一部分在用户空间**，其余三层都在内核。

## KP22 用户层软件

**核心结论**：实现与用户的交互接口。用户可直接调用用户层提供的 **I/O 库函数**（与 I/O 操作相关的标准库函数）操作设备。

**核心结论**：大部分 I/O 软件位于**操作系统内核**，但仍有一小部分驻留在**用户层**，例如与用户程序链接的库函数。用户层 I/O 软件必须**通过系统调用**获取操作系统服务。

**易错点**：库函数（如 `printf`）属于**用户层**，`write` 系统调用才进内核。别把标准库当成内核的一部分。

## KP23 设备独立性：逻辑设备名与两个优势（真题）

**真题**：2020 考过设备独立性所涵盖的内容。

**核心结论**：设备独立性（设备无关性）= 应用程序使用 I/O 设备时，**无须依赖具体的物理设备**。实现手段：引入**逻辑设备**与**物理设备**概念——应用程序用**逻辑设备名**请求某类设备，系统**在运行时**把逻辑设备名映射为实际的物理设备名。

| 优势 | 说明 |
| --- | --- |
| ① 提高设备分配的**灵活性** | 同类设备哪台空闲就分配哪台 |
| ② 易于实现 **I/O 重定向** | 用于 I/O 操作的设备可以更换，**而不必修改应用程序** |

**易错点**：映射发生在**运行时**，不是编译时或链接时。这正是灵活性的来源。

**易错点**：I/O 重定向的定义要抠住「**不修改应用程序**」这个限定，只说「设备可以更换」不完整。

## KP24 设备独立性软件层的两大功能（真题）

**真题**：2020 考过设备独立性所涵盖的内容。

**核心结论**：为实现设备独立性，需在**设备驱动程序之上**设置一层设备独立性软件。两大功能：

**① 执行所有设备的公共操作**：

| 公共操作 | 内容 |
| --- | --- |
| 设备的分配与回收 | — |
| 逻辑设备名→物理设备名的映射 | — |
| 设备保护 | **禁止用户直接访问硬件** |
| 缓冲管理 | — |
| 差错控制 | — |
| 提供统一大小的逻辑块 | 屏蔽不同设备在**信息交换单位**和**传输速率**上的差异 |

**② 向用户层（或文件系统）提供统一的接口**：无论底层设备类型如何，应用程序均可用统一的系统调用（`read` / `write`）访问，显著增强可移植性与可维护性。

**易错点**：设备分配与回收、缓冲管理、差错控制都在**设备独立性层**，不在驱动层。驱动层是「每类设备一个」的私活，公共事务归独立性层。

**易错点**：「提供统一大小的逻辑块」屏蔽的是**交换单位 + 传输速率**两项差异，只答一项不完整。

## KP25 设备驱动程序的定位与职责（真题）

**真题**：2025 考过设备驱动程序的功能。

**核心结论**：设备驱动程序**与硬件直接相关**，**每类设备都需要配置一个专用的驱动程序**。它是 I/O 子系统与设备控制器之间的**通信桥梁**，向上提供统一操作接口，屏蔽不同设备控制器的差异。

**核心结论**：主要任务——接收上层（设备独立性层）发来的**抽象 I/O 请求**（`read` / `write`），转换成**设备控制器能识别的具体指令**，启动设备执行，并把控制器返回的状态信息或数据传回上层。

**核心结论**：此外还负责设备的**初始化、状态维护、错误处理，以及与中断处理的配合**。

**易错点**：是「**每类**设备一个驱动程序」，不是每台设备一个。三块同型号磁盘共用一个磁盘驱动。

## KP26 设备驱动程序的五步工作流程（真题）

**真题**：2025 考过设备驱动程序的功能。

**核心结论**：

| 步 | 做什么 | 细节 |
| --- | --- | --- |
| 1 | 将抽象请求转换为具体操作 | 上层请求是逻辑性的（「读逻辑块 5」），控制器只能处理物理操作。磁盘驱动把逻辑扇区号转成**柱面号、盘面号、扇区号** |
| 2 | 校验请求的合法性 | 禁止从只写设备（打印机）读，禁止向只读方式打开的设备写。非法则向上层返回错误 |
| 3 | 检查设备状态 | 读控制器的**状态寄存器**确认是否就绪。写操作要求设备处于「接收就绪」状态，否则进程等待 |
| 4 | 传递参数 | 向控制器**相应寄存器**写入命令、数据缓冲区地址、传输长度等。磁盘等复杂设备参数更多 |
| 5 | 启动设备并处理后续 | 向**命令寄存器**发启动信号；多道程序系统中当前进程随即**被阻塞**，CPU 转去执行其他就绪进程；设备完成并发中断后，由**中断处理程序将其唤醒** |

**易错点**：合法性校验在**第 2 步**、状态检查在**第 3 步**——先看这个操作允不允许，再看设备现在行不行，顺序别倒。

**易错点**：阻塞发生在**驱动程序启动设备之后**，不是发出请求时立刻阻塞。唤醒是**中断处理程序**做的，不是驱动程序自己。

## KP27 中断处理程序的五步流程

**核心结论**：

| 步 | 做什么 | 谁做 |
| --- | --- | --- |
| 1 | 检测并响应中断 | 设备完成一个数据单位传输后控制器发中断请求；CPU 在**指令周期末**检测到即暂停当前进程 |
| 2 | 保护被中断进程的 CPU 现场 | **硬件自动**把 PC 和 PSW 压入中断栈；**操作系统软件**再把其他 CPU 寄存器内容保存至该栈 |
| 3 | 转入相应设备的中断处理程序 | CPU 识别中断源，跳转到对应处理程序 |
| 4 | 处理中断 | 读控制器**状态寄存器**判断是否正常完成：成功则把**设备数据寄存器**内容传到**内存缓冲区**；异常则错误处理 |
| 5 | 恢复现场并返回 | 从中断栈恢复所有寄存器，CPU 从**被中断指令的下一条**继续执行原进程 |

**核心结论（易错重点）**：现场保护是**硬件 + 软件分工**：PC 和 PSW 由**硬件自动**压栈，其余通用寄存器由**操作系统软件**保存。

**易错点**：返回点是「被中断指令的**下一条**」——中断是在一条指令执行完后才响应的，那条指令已经完成。

## KP28 中断处理程序自身的管理：注册、处理、注销

**核心结论**：

| 环节 | 时机 | 内容 |
| --- | --- | --- |
| 注册中断 | 驱动程序**初始化**时 | 向内核注册**中断号 + 处理函数入口地址**，建立硬件中断信号与服务代码的映射 |
| 处理中断 | 中断发生时 | ① 确认中断**是否由本设备产生**；② **清除控制器中的中断标志**防止重复触发；③ 执行必要的硬件操作（读/写数据） |
| 注销中断 | 驱动程序**被卸载或设备停用**时 | 释放资源 |

**核心结论（易错重点）**：注销时看中断请求线是否共享：

| 中断线类型 | 注销后果 |
| --- | --- |
| **独占** | 内核**立即禁用**该线 |
| **共享** | 仅移除本设备的处理例程；该中断线要等**所有关联设备均注销后**才最终禁用 |

**核心结论**：中断处理程序运行在**中断上下文**中，必须**快速、非阻塞**，**不得调用可能引起进程睡眠或调度的函数**。

**易错点**：「清除中断标志」是**必做**的一步，漏了会重复触发中断。这也是 KP31 里 Linux 流程中中断服务程序的固定动作。

**易错点**：中断处理程序里不能睡眠、不能调度——这是它必须「短」的根本原因，长活要甩给下半部/内核线程。

## KP29 一次 write 请求穿越四层的过程（真题）

**真题**：2010、2024 考过键盘 I/O 过程的分析。

**核心结论**：以用户发起一次 `write` 为例，五步：

| 步 | 所在层 | 做什么 |
| --- | --- | --- |
| ① | 用户层软件 | 用户通过 OS 提供的 `write` 命令接口发起请求，请求首先进入用户层 |
| ② | 设备独立性软件 | OS 向上提供的是**统一的通用接口**（大多数设备都支持的标准命令），请求先由该层解析，再传给下一层 |
| ③ | 设备驱动程序 | 不同设备对 `write` 的处理方式不同（磁盘 vs 打印机差异显著），由驱动层把**通用 write 转换为设备特定指令** |
| ④ | 设备控制器 → 中断 | 驱动把指令发给控制器，启动实际写操作；完成后控制器向 CPU 发中断信号 |
| ⑤ | 中断处理程序 | 确认写操作完成，**清除中断标志**，**唤醒等待该操作的进程**，结果逐层返回用户程序 |

**易错点**：「通用命令→设备特定指令」的转换在**驱动层**，不在设备独立性层。独立性层只做解析和公共操作。

**易错点**：唤醒进程是**中断处理程序**的活（步骤⑤），不是驱动程序也不是调度程序主动发现的。

## KP30 Linux 中 write 系统调用的执行流程（真题）

**真题**：2010、2024 考过键盘 I/O 过程的分析。

**核心结论**：

```
用户空间：printf() → 标准库封装 → write() 封装函数
  → 传送指令把系统调用号和 I/O 参数（文件描述符、缓冲区地址、字节数）写入寄存器（如 eax）
  → 执行陷阱指令（IA-32 的 int $0x80）→ 受控软中断，硬件自动完成用户态→内核态切换
内核空间：system_call() 统一入口
  → 按 eax 中的系统调用号，通过跳转表分派到 sys_write()
  → sys_write() 先做与设备无关的公共操作（参数合法性检查、内核缓冲区分配管理）
  → 按文件描述符定位目标设备，调用对应的设备驱动程序
驱动程序：初始化 I/O 接口、设置传输参数、启动设备传输
  → 把当前进程置为阻塞态，主动调用调度程序让出 CPU
传输完成：控制器发中断请求 → CPU 响应，转入中断服务程序
  → 读设备状态确认成功、清除中断标志、唤醒等待 I/O 的进程
  → 内核沿调用栈逐级返回 → system_call() 末尾执行 iret 等特权指令
  → CPU 切回用户态，在陷阱指令的下一条指令处恢复执行
```

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-6.jpg]]（图 5.6 Linux 系统中 write 调用的执行流程）

**易错点**：系统调用号和参数是在**执行陷阱指令之前**由传送指令写入寄存器的，不是陷阱指令自己带的。

**易错点**：`sys_write()` 做的是**与设备无关的公共操作**——对应四层里的**设备独立性软件**层，别以为它是驱动。

**易错点**：让出 CPU 是驱动程序**主动调用调度程序**，属于自愿的进程切换。

## KP31 陷阱指令与中断：两种态切换机制（真题）

**真题**：2010、2024 考过键盘 I/O 过程的分析。

**核心结论（易错重点）**：一次完整的 I/O 请求依次穿越**用户层软件 → 系统调用接口 → 设备独立性软件 → 设备驱动程序 → 中断处理程序**。其中：

| 机制 | 角色 |
| --- | --- |
| **陷阱指令** | 从用户态进入内核态的**唯一合法入口** |
| **中断** | 设备通知操作完成、**触发进程状态转换**的核心机制 |

二者共同实现用户态与内核态之间的**安全切换**。

**易错点**：陷阱（trap）是**程序主动发起**的、受控的内中断；设备中断是**外部异步**的。别把两者都叫「中断」混答。

**易错点**：「唯一合法入口」这个限定要记住，考题会给「用户程序可以直接跳转到内核代码」这类错项。

## KP32 应用程序 I/O 接口的两个目的与三类抽象

**核心结论**：应用程序 I/O 接口 = OS 为统一管理各类 I/O 设备设计的一套软件架构与编程规范。两个目的：

| 目的 | 内容 |
| --- | --- |
| ① 对上 | 让应用程序（如打开文件）**无须关心底层硬件实现细节** |
| ② 对下 | 使新设备能以**模块化**方式方便加入系统，**无须改动内核代码** |

**核心结论**：OS 把物理设备抽象为三种通用类型——**字符设备、块设备、网络设备**，每类提供标准接口，设备间的具体差异由相应的**驱动程序**封装。

**易错点**：「新设备加入无须改内核」靠的是驱动程序模块化，接口规范不变。这是分层设计的直接收益。

## KP33 字符设备接口

**核心结论**：字符设备 = 数据存取和传输以**字符**为单位的设备（键盘、打印机）。特征：**传输速率较低、不可寻址**，I/O 通常采用**中断驱动**方式。

| 接口成分 | 内容 |
| --- | --- |
| get / put 操作 | 因不可寻址、只能顺序存取，系统为其设**字符缓冲区**。`get` 从缓冲区**读**字符，`put` 向缓冲区**写**字符 |
| in-control 指令 | 一种**通用**指令（含多个参数），用于指定与具体设备相关的**特定功能** |
| 打开 / 关闭操作 | 大部分字符设备属**独占设备**，需要打开和关闭来实现**互斥共享** |

**易错点**：`get` / `put` 操作的对象是**字符缓冲区**，不是设备本身。

**易错点**：in-control 是**一条通用指令覆盖多种设备特有功能**（靠参数区分），不是「每种设备一条专用指令」。

## KP34 块设备接口

**核心结论**：块设备 = 数据存取和传输以**数据块**为单位的设备，典型是磁盘。特征：**传输速率较高、可寻址**，磁盘 I/O 常采用 **DMA** 方式。

**核心结论（易错重点）**：块设备接口**隐藏了磁盘的物理二维结构**（原本块地址用磁道号 + 扇区号表示），把所有扇区从 0 到 $n-1$ 依次编号，**把二维结构变为线性地址空间**。

**核心结论**：常用命令 `read()`、`write()`、`seek()`，其中 **`seek()` 用来指定下一个传输块**。这三个命令描述了块设备的基本行为，使应用程序不必关注低层差别。

**易错点**：`seek()` 的作用是**指定下一个传输块**，不是「移动磁头」——磁头移动是驱动和控制器的事，接口层只表达意图。

**易错点**：二维→线性的转换在**接口层**（对上屏蔽）；线性→柱面/盘面/扇区的反向换算在**驱动/控制器**（对下落实）。两个方向别搞混。

## KP36 阻塞 I/O 与非阻塞 I/O

**核心结论**：

| | 阻塞 I/O | 非阻塞 I/O |
| --- | --- | --- |
| 是否默认 | **多数 OS 默认采用**（编程模型简单、逻辑直观） | 否 |
| 数据未就绪时 | 进程**立即被阻塞**，移入等待队列，期间不能干别的 | **系统调用立即返回**，返回「暂无数据」错误状态（如 -1） |
| 完成后 | 内核把进程移回**就绪队列**；再获得 CPU 时系统调用返回结果 | 进程自行**重试**；某次重试时数据已就绪，内核把数据从**内核缓冲区复制到用户空间**，返回实际成功传输的字节数 |
| 优点 | 实现简单，适用于顺序处理或**低并发**场景 | 等待期间不被阻塞可执行其他任务，适合**高并发或高响应性**应用 |
| 缺点 | 等待期间进程完全阻塞，**CPU 闲置**，系统利用率低 | **轮询**方式频繁检查 I/O 状态，**浪费 CPU** |

咖啡店类比：阻塞 = 点单后原地干等；非阻塞 = 点单后去逛商场，每隔一会儿回来问「好了吗？」。

**核心结论（易错重点）**：两者**都有浪费**，只是浪费的位置不同——阻塞浪费在进程干等（CPU 闲置），非阻塞浪费在轮询（CPU 空转）。

**易错点**：非阻塞返回 -1 表示「**暂无数据**」，不是出错失败。真正成功时返回的是**实际传输的字节数**，可能少于请求量。

**易错点**：非阻塞 I/O 的轮询是**进程主动重试**，和 KP13 的程序直接控制方式（CPU 硬件级忙等）不是一回事，只是思路相似。

## KP38 设备独立性软件的定位与五项公共功能

**核心结论**：设备独立性软件（也称与设备无关的软件）位于**设备驱动程序之上**，是**内核 I/O 子系统的最高层**。==核心职责是实现各类设备的**公共操作**==，向上提供统一、抽象的 I/O 接口。五项公共功能：

| 功能            | 干什么                                                |
| ------------- | -------------------------------------------------- |
| ① 提供统一的驱动程序接口 | 把**抽象设备名映射到具体物理设备**，定位对应驱动程序的入口；确保 I/O 走内核受控路径     |
| ② 缓冲管理        | 用单缓冲、双缓冲、环形缓冲、缓冲池缓解 CPU 与外设的速度差                    |
| ③ 差错控制        | 处理驱动程序解决不了的错误，维护坏块表                                |
| ④ 独占设备的分配与回收  | 设备空闲则分配，忙则阻塞进程入等待队列；释放时唤醒队首或置「空闲」                  |
| ⑤ 提供统一的逻辑数据块  | 屏蔽字符设备（按字节）与块设备（按块，且块长可能不一）的粒度差异，向上给**大小统一**的逻辑数据块 |

**易错点**：这一层与驱动程序的**界限不是固定的**。某些通常由设备独立性软件实现的功能，会被下放到驱动程序里，差异源于对性能、代码复用性、驱动效率的权衡。所以真题问「某功能属于哪一层」时，按教材主流划分答，别死抠。

**易错点**：「统一的逻辑数据块」屏蔽的是**数据交换单位**的差异，不是速度差异——缓解速度差是缓冲管理干的。两条别串。

## KP39 差错控制：暂时性错误与持久性错误

**核心结论**：I/O 设备含机械与电气部件，故障率高，错误分两类，处理方式完全不同：

| 类型 | 例子 | 怎么处理 | 谁处理 |
| --- | --- | --- | --- |
| 暂时性错误 | 网络丢包 | **重试**即可纠正；**连续失败**后才升格为持久性错误 | 主要由**驱动程序**处理，设备无关层只在驱动搞不定时才介入 |
| 持久性错误 | 磁盘划痕 | 记入**坏块表**，后续 I/O 自动绕过 | 操作系统 |

**易错点**：暂时性错误的第一责任人是**驱动程序**，不是设备独立性软件。设备无关层是「兜底」的，不是「首发」的。

**易错点**：持久性错误的处理是**绕过**（坏块表），不是换整盘——这正是坏块表存在的意义。

## KP40 磁盘高速缓存（真题）

**真题**：2015 考过设置磁盘缓冲区的目的。

**核心结论**：磁盘高速缓存（Disk Cache）指**利用内存中的存储空间暂存从磁盘读取的盘块数据**。这些数据逻辑上是磁盘内容的副本，物理上驻留在内存中。两种组织形式：

| 形式 | 说明 |
| --- | --- |
| 专用缓存区 | 在内存中开辟**固定大小**的专用区域 |
| 动态缓冲池 | 把**系统空闲内存**作为缓冲池，供请求分页系统和磁盘 I/O 子系统**共享** |

**易错点（关键区分）**：磁盘高速缓存**不是**位于 CPU 与主存之间的那个硬件 Cache。它是**内存中的一片区域**，是软件层面的概念，缓存的对象是磁盘盘块，不是主存单元。

## KP41 引入缓冲区的四个目的与两种实现方法

**核心结论**：在设备管理子系统中引入缓冲区，四个目的：

| 目的 | 说明 |
| --- | --- |
| ① 缓和速度不匹配 | CPU 与 I/O 设备速度差距大 |
| ② 减少对 CPU 的中断频率 | 顺带**放宽对中断响应时间的限制** |
| ③ 解决数据粒度不匹配 | 基本数据单元大小不同（字节 vs 块） |
| ④ 提高并行性 | CPU 与 I/O 设备可并行工作 |

实现方法两种：**硬件缓冲器**（成本高，除关键部位一般不采用）、**内存作缓冲区**（教材讨论的就是这种）。

**易错点**：目的②是**两句话**——减少中断次数 + 放宽中断响应时间限制，答题只写前半句会漏点。

**易错点**：按缓冲区**数量**分四种：单缓冲、双缓冲、循环缓冲、缓冲池。只有单缓冲和双缓冲要做定量的时间计算，循环缓冲和缓冲池只考工作机制。

## KP42 单缓冲：Max(T, C) + M（真题高频，必会算）

**真题**：2011、2013 两年考过单缓冲的工作时间理解与计算。

**核心结论**：三个时间量先记死——

| 符号 | 含义 |
| --- | --- |
| $T$ | 设备把**一块数据送入缓冲区**的时间 |
| $M$ | 操作系统把**缓冲区数据传送到用户工作区**的时间 |
| $C$ | CPU **处理该块数据**的时间 |

对块设备，必须**等整块装满缓冲区**后才能传送到工作区。单缓冲中，设备写缓冲区的时间 $T$ 可与 CPU 处理**前一块**数据的时间 $C$ 并行，于是处理每块数据的时间为

$$\text{Max}(T,\ C) + M$$

分情形复算：

| 情形 | 谁在等 | 每块时间 |
| --- | --- | --- |
| $T > C$ | CPU 处理完当前块后，等设备把下一块**装满** | $T + M$ |
| $T < C$ | 缓冲区一装满设备就写不动了，等 CPU 处理完工作区数据腾出缓冲区 | $C + M$ |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-7.jpg]]（图 5.7 单缓冲工作示意图）

**易错点（关键）**：$M$ **永远在括号外**，不参与取 Max。因为单缓冲区是**共享资源**，设备与 CPU 对它的访问必须**互斥**——传送数据到工作区的这段 $M$ 期间，设备没法往缓冲区写，所以 $M$ 无法与 $T$ 并行。

**易错点**：并行的是 $T$ 与**前一块**的 $C$，不是同一块的 $T$ 与 $C$。同一块必须先装满再处理，天然串行。

## KP43 双缓冲：Max(T, C + M)（真题，必会算）

**真题**：2011 考过双缓冲的工作时间理解与计算。

**核心结论**：双缓冲（也称**缓冲对换**）设两个缓冲区轮换：设备装满缓冲区 1 后转去写缓冲区 2，同时操作系统从缓冲区 1 取数据送工作区并由 CPU 处理。于是设备写一个缓冲区的时间 $T$ 可与**传送加处理的总时间 $C+M$** 并行：

$$\text{Max}(T,\ C+M)$$

分情形复算：

| 情形 | 谁在等 | 每块时间 |
| --- | --- | --- |
| $T > C+M$ | 处理完一块后缓冲区尚未装满，系统等装满 | $T$（**设备可连续工作**） |
| $T < C+M$ | 缓冲区很快装满，但要等上一块处理完才能切换 | $C + M$ |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-8.jpg]]（图 5.8 双缓冲工作示意图）

**易错点（单双缓冲对照，最容易混）**：单缓冲 $\text{Max}(T,C)+M$，双缓冲 $\text{Max}(T,C+M)$。区别就在 $M$ **进不进括号**：双缓冲有两个缓冲区，传送 $M$ 的时候设备可以往**另一个**缓冲区写，所以 $M$ 能与 $T$ 并行，被收进 Max 里；单缓冲只有一个缓冲区，$M$ 期间设备被堵住，只能加在外面。

**易错点**：$T > C+M$ 时每块时间是 $T$ 而**不是** $T+M$。设备连续工作，$M$ 完全被 $T$ 掩盖掉了。

## KP45 循环缓冲：in / out 指针与两种同步情形

**核心结论**：双缓冲在输入输出速度**基本匹配**时效果好，速率相差较大时就不够用，于是引入多缓冲并组织成**循环缓冲区**——若干个大小相等的缓冲区，各带一个链接指针指向下一个，最后一个指回第一个，构成**循环队列**。

系统维护两个指针：

| 指针 | 指向 | 谁推进 |
| --- | --- | --- |
| in | 下一个待写入的**空**缓冲区 | 输入进程 |
| out | 下一个待读取的**满**缓冲区 | 计算进程 |

两种同步情形（**名字容易反，重点记**）：

| 情形 | 含义 | 谁阻塞 | 术语 |
| --- | --- | --- | --- |
| **in 追上 out** | 输入快于计算，所有缓冲区都满，无空缓冲区可写 | **输入进程**阻塞，待计算进程取走数据后唤醒 | 系统受**计算**限制 |
| **out 追上 in** | 计算快于输入，所有缓冲区都空，无数据可处理 | **计算进程**阻塞，待输入进程写入数据后唤醒 | 系统受 **I/O** 限制 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-10.jpg]]（图 5.10 循环缓冲工作示意图，灰色为满、白色为空）

**易错点（术语反直觉）**：in 追上 out 是输入**快**，瓶颈在计算，所以叫「受计算限制」；out 追上 in 是计算**快**，瓶颈在 I/O，所以叫「受 I/O 限制」。**限制的名字指的是瓶颈方（慢的那方），不是跑得快的那方**。

## KP46 缓冲池：三个队列与四种工作方式

**核心结论**：缓冲池不只是一块内存——它是一种**包含管理数据结构和操作函数的软件机制**，统一管理多个缓冲区并支持多进程共享。按使用状态组织成三个队列：

| 队列 | 由什么链成 |
| --- | --- |
| ① 空缓冲队列 | 空缓冲区 |
| ② 输入队列 | 装满**输入**数据的缓冲区 |
| ③ 输出队列 | 装满**输出**数据的缓冲区 |

缓冲区可动态扮演四种角色，对应四种工作方式：

| 方式 | 谁发起 | 从哪摘 | 干什么 | 挂到哪 |
| --- | --- | --- | --- | --- |
| 收容输入（hin） | 输入进程 | 空缓冲队列**队首** | 写入输入数据 | 输入队列**队尾** |
| 提取输入（sin） | 计算进程 | 输入队列**队首** | 读出输入数据 | 空缓冲队列**队尾** |
| 收容输出（hout） | 计算进程 | 空缓冲队列**队首** | 写入输出数据 | 输出队列**队尾** |
| 提取输出（sout） | 输出进程 | 输出队列**队首** | 读出输出数据 | 空缓冲队列**队尾** |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-11.jpg]]（图 5.11 缓冲池的 4 种工作方式）

**易错点**：规律是**一律从队首摘、一律挂到队尾**，四种方式全都如此，别记成有的从队尾摘。

**易错点**：区分「缓冲区」和「缓冲池」——单个缓冲区**仅是一块内存区域**，缓冲池是**软件机制**（数据结构 + 操作函数）。这是概念题的常见落点。

## KP47 高速缓存与缓冲区的对比

**核心结论（易错重点）**：两者**相同点**是都位于高速设备和低速设备之间、用于缓解速度差异。区别在存放的数据和目的：

| | 高速缓存（Cache） | 缓冲区（Buffer） |
| --- | --- | --- |
| 存放数据 | 已存在于慢速设备上的数据**副本**；可**长期驻留**，直至被替换 | **正在传输过程中**的数据；传输完成后通常**立即释放** |
| 目的 | 提高**重复访问**的效率：命中就不用访问低速设备 | 提高**数据传输**的效率与并行性：协调速度差、降低中断频率、匹配数据粒度 |

教材表格：表 5.1

**易错点**：判据抓两个词——**副本**和**重复访问**。Cache 存的是「别处也有的数据的一份拷贝」，价值在下次还要读它；Buffer 存的是「正在路上的数据」，用完就没了。所以 Cache 讲命中率，Buffer 讲并行度。

## KP48 设备分配的四张数据结构表

**核心结论**：系统中可能有多个通道，一个通道连多个控制器，一个控制器连多个物理设备。四张表就是为了体现这种**从属关系**：

| 表 | 全称 | 数量 | 关键指针 |
| --- | --- | --- | --- |
| DCT | 设备控制表 | **每个物理设备一张** | 指向**控制器表**的指针 |
| COCT | 控制器控制表 | **每个控制器一张** | 与控制器连接的**通道表**指针 |
| CHCT | 通道控制表 | **每个通道一张** | 与通道连接的**控制器表首址** |
| SDT | 系统设备表 | **整个系统仅一张** | 所有物理设备的**全局索引**，每个表目对应一个设备 |

DCT 的主要字段：设备类型、**设备标识符**（即物理设备名，系统内唯一）、设备状态（忙/闲）、指向控制器表的指针、**重复执行次数或时间**（超过则判定 I/O 失败）、**设备队列的队首指针**（指向因请求该设备而阻塞的 PCB 队列队首）。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-12.jpg]]（图 5.12 DCT）、[[王道教材/27 王道操作系统/pictures/5-2-image-013.jpg]]（图 5.13 COCT、CHCT 和 SDT）

**易错点**：**只有 SDT 是全系统一张**，其余三张都是「每个×一张」。这是最容易反的一处。

**易错点**：设备回收就是——进程释放设备且**无其他进程等待**时，把 DCT 中的设备状态置为**空闲**。若有等待则唤醒队首进程，此时状态不改成空闲。

## KP49 设备分配需要考虑的因素（真题）

**真题**：2023 考过设备分配需要考虑的因素。

**核心结论**：总体原则是**在充分发挥设备使用效率（尽可能忙碌）的同时，避免因分配策略不当引发进程死锁**。要考虑四个因素：**设备的固有属性、分配算法、分配的安全性、设备的独立性**。

其中固有属性分三类，分配策略不同：

| 类型 | 特点 |
| --- | --- |
| 独占设备 | 分配后由该进程**独占**，直至主动释放或终止 |
| 共享设备 | 可同时供多个进程使用，需调度机制协调访问顺序（如磁盘） |
| 虚拟设备 | 对独占设备虚拟化（如 SPOOLing），逻辑上表现为可共享，允许多进程**并发提交** I/O 请求 |

分配算法两种：**FCFS**（按请求先后排队，分给队首）、**最高优先级优先**（高优先级排前，同优先级按 FCFS）。

**易错点**：**及时性不是**设备分配要考虑的因素（5.1 节习题第 12 题的落点）。及时性是与系统性能和用户需求相关的因素，设备分配关心的是「安全、正确前提下合理分配」。四个因素背死：固有属性、分配算法、安全性、独立性。

## KP50 设备分配中的安全性：安全分配与不安全分配

**核心结论**：所谓安全性就是**分配过程中避免死锁**，两种方式各有取舍：

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 安全分配方式 | 进程一发出 I/O 请求就**立即进入阻塞态**，直到 I/O 完成才唤醒；期间**不再请求任何其他资源** | 安全性高，**不会死锁** | CPU 与 I/O 设备**串行**工作，系统效率低 |
| 不安全分配方式 | 发出 I/O 请求后**仍继续运行**，需要时可再发第二、第三个请求；只有所请求的设备已被占用时才阻塞 | 单进程可同时使用多个设备，推进迅速 | 可能因**循环等待**造成死锁 |

**易错点**：安全分配之所以不死锁，根子在于「破坏了请求并保持条件」——进程一次只占一个设备且立即阻塞，不会边持有边申请。把这条挂回第 2 章死锁的四个必要条件上答，才算答透。

## KP51 设备分配的三步：设备 → 控制器 → 通道

**核心结论**：以独占设备为例，按**物理设备名**分配走三步，每步的判断逻辑完全同构：

```
① 分配设备：查 SDT → 找到该设备的 DCT → 看设备状态
      忙  → 进程 PCB 挂入「设备」等待队列
      空闲 → 分配给该进程，进入②
② 分配控制器：由 DCT → 找到 COCT → 看控制器状态
      忙  → 进程 PCB 挂入「控制器」等待队列
      空闲 → 分配给该进程，进入③
③ 分配通道：由 COCT → 找到 CHCT → 看通道状态
      忙  → 进程 PCB 挂入「通道」等待队列
      空闲 → 分配给该进程
只有设备、控制器、通道三者全部分配成功，本次分配才算完成，随后启动设备传送数据
```

**易错点**：**三者必须全部到手**才算分配完成，缺一样都启动不了设备。这是「为什么设备分配可能死锁」的来源。

**易错点**：上述流程用的是**物理设备名**，一旦指定设备被占用就分配失败，说明该方案**缺乏设备独立性**。改用**逻辑设备名**后：系统从 SDT 中**依次查找该类设备的 DCT**，只要有一台空闲就继续后续分配；**仅当所有同类设备都忙**时，才把进程挂入该类设备的**公共等待队列**。

## KP52 逻辑设备表 LUT：逻辑设备名到物理设备名的映射（真题）

**真题**：2009 考过逻辑设备名和物理设备名的使用。

**核心结论**：进程用**逻辑设备名**请求某类设备，但系统只认**物理设备名**，因此需配置一张**逻辑设备表（LUT）**建立映射。LUT 每个表项含三项：**逻辑设备名、物理设备名、驱动程序入口地址**。进程首次用逻辑设备名请求时，系统分配一台空闲物理设备并在 LUT 中建表目；此后该进程的所有 I/O 请求都通过该表项找到物理设备及其驱动程序。

两种设置方式：

| 方式 | 特点 | 适用 |
| --- | --- | --- |
| 整个系统仅一张 LUT | 所有进程的分配情况记在同一张表里，**所有用户不能使用相同的逻辑设备名** | 单用户系统 |
| 每个用户一张 LUT | 系统仍维护全局 SDT；**不同用户可用相同的逻辑设备名**，互不干扰 | 多用户系统 |

教材表格：图 5.14（(a) 整个系统的 LUT / (b) 每个用户一张 LUT，教材以表格给出）

**易错点**：LUT 表项里有**驱动程序入口地址**这一项，不只是名字对名字的映射。漏了这项就答不出「为什么有了 LUT 就能定位到驱动」。

**易错点**：设备独立性的三个好处（小结里的答案）：① 简化编程、屏蔽硬件细节；② 提高**可移植性**，同一程序能在不同硬件配置上跑；③ 支持 **I/O 重定向**与设备动态绑定。

## KP53 SPOOLing 的来由：从脱机 I/O 到假脱机

**核心结论**：SPOOLing 即**假脱机技术**，目的是缓和 CPU 高速性与 I/O 设备低速性的矛盾。理解它要先理解「脱机」：

| 阶段 | 靠什么 | 怎么做 |
| --- | --- | --- |
| 早期**脱机** I/O | **专用外围控制机**（物理设备） | 输入时外围机先把纸带机数据读入高速磁盘；输出时 CPU 先把结果写磁盘，再由外围机送往打印机。整个 I/O **脱离主机控制**，故称「脱机」 |
| **假脱机** SPOOLing | **软件**：专门的输入进程与输出进程 | 不再需要物理外围机，在主机**直接控制下**模拟外围机功能：输入进程把数据提前读入磁盘**输入井**，输出进程把结果暂存磁盘**输出井**再逐步送往设备 |

**易错点（名字的两个字分开解释）**：「**脱机**」承袭自早期脱机 I/O 的思想（数据先落磁盘，不让主机直接等慢设备）；「**假**」体现在用**多道程序和磁盘空间替代了外围机**——其实主机全程参与，只是逻辑上像脱机。

**易错点**：SPOOLing 是**软件**技术（5.1 习题第 7 题的落点），通道才是硬件。别因为它涉及磁盘就当硬件。

## KP54 SPOOLing 系统的四个组成部分

**核心结论**：两个在磁盘上、两个在内存里，加一个管理程序：

| 组成 | 在哪 | 干什么 |
| --- | --- | --- |
| 输入井 / 输出井 | **磁盘**上的专用存储区 | 输入井模拟脱机输入的磁盘，暂存输入设备的数据；输出井模拟脱机输出的磁盘，暂存用户程序的输出数据。每个进程的数据以文件形式保存（称**井文件**），所有文件顺序链接成输入队列或输出队列 |
| 输入缓冲区 / 输出缓冲区 | **内存**中 | 输入缓冲区暂存输入设备送来的数据，再传到输入井；输出缓冲区暂存从输出井读出的数据，再传到输出设备 |
| 输入进程 / 输出进程 | 软件 | 分别模拟脱机输入/输出的外围控制机。CPU 需要输入数据时**直接从输入井读取**；输出进程在**输出设备空闲时**经输出缓冲区把数据送到设备 |
| 井管理程序 | 软件 | 控制作业与磁盘井之间的信息交换 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-15.jpg]]（图 5.15 SPOOLing 系统的组成）

**易错点（最容易混的一处）**：**井在磁盘上，缓冲区在内存里**。「输入井」和「输入缓冲区」是两个不同层次的东西，数据流向是：输入设备 → 内存输入缓冲区 → 磁盘输入井 → CPU；输出反之。答题写错位置就全错。

## KP55 SPOOLing 共享打印机的实现过程

**核心结论**：打印机是典型独占设备，SPOOLing 把它改造成可共享的虚拟设备。多个用户进程请求打印时，输出进程为每个进程做**两件事**：

```
① 在磁盘输出井中分配一个空闲盘块，把待打印数据写进去
② 申请一张「用户请求打印表」记录打印要求，挂到假脱机打印队列上
        ↓
用户进程此时就认为打印已完成，继续执行后续代码（真实打印尚未开始，对用户透明）
        ↓
后台假脱机打印进程：打印机空闲时检查假脱机打印队列
        队列非空 → 取队首请求表 → 按表中信息把输出数据从输出井读入内存缓冲区 → 送物理打印机
        队列为空 → 进程进入等待态，待新请求将其唤醒
```

**易错点**：用户进程「认为打印完成」时，数据只是写进了**磁盘输出井**，物理打印还没开始。这个「假」正是假脱机的名字来源。

**易错点**：系统为每个请求在输出井中分配**独立的存储区域**，所以各进程都以为自己独占了一台打印机——这就是「虚拟设备」的实现方式。

## KP56 SPOOLing 的三个特点与「以空间换时间」（真题）

**真题**：2016 考过 SPOOLing 技术的特点。

**核心结论**：三个特点：

| 特点 | 说明 |
| --- | --- |
| ① 提高了 I/O 速度 | 把对低速设备的操作转化为对磁盘输出井中数据的存取，缓和了 CPU 与低速设备的速度矛盾 |
| ② 将独占设备改造为共享设备 | 在假脱机打印机系统中，**实际上并未把物理设备分配给任何进程** |
| ③ 实现了虚拟设备功能 | 每个进程都认为自己独占了一台设备 |

SPOOLing 是一种**以空间换时间**的技术：牺牲磁盘空间（输入井、输出井），换取时间上的节省。理由是磁盘与内存交换数据的速度**远高于**打印机等低速设备，CPU 把数据快速写入磁盘输出井后即可继续干别的，无须等打印完成，从而实现 CPU 与 I/O 并行。

**易错点（特点②的措辞）**：注意是「**并未将物理设备分配给任何进程**」。真题喜欢改成「把打印机分配给了多个进程」来设错——物理打印机始终由假脱机打印进程独占使用，用户进程拿到的只是输出井里的一块空间。

**易错点**：「以空间换时间」里换掉的空间是**磁盘空间**，不是内存空间。

## KP57 设备驱动程序的四项功能（真题高频）

**真题**：2013、2019、2023 三年考过设备驱动程序的功能。

**核心结论**：驱动程序是 **I/O 系统上层与设备控制器之间的通信桥梁**。主要任务是接收上层的抽象 I/O 请求（如 read/write），转换为设备可识别的具体命令发给设备控制器，同时把控制器返回的状态和中断信息反馈给上层。四项功能：

| 功能 | 说明 |
| --- | --- |
| ① 转换 | 接收上层命令和参数，把抽象 I/O 请求转为与具体设备相关的操作指令。例如**把逻辑盘块号转换为磁盘的盘面号、磁道号和扇区号** |
| ② 检查与设置 | 检查用户 I/O 请求的**合法性**，查询设备当前状态，传递参数，设置工作方式 |
| ③ 发出 I/O 命令 | 设备空闲则立即启动；设备忙则把请求进程的 **PCB 挂到该设备的等待队列**上 |
| ④ 响应中断 | 及时响应设备控制器发出的中断请求，按中断类型调用相应的中断处理程序 |

**易错点（真题最爱考的一句）**：**逻辑盘块号 → 盘面号/磁道号/扇区号**的转换是**驱动程序**干的。这是「抽象转具体」最典型的例子，记住这个例子就能反推整条功能①。

**易错点**：功能①是「翻译成**设备相关的操作指令**」，而把**系统调用参数**翻译成设备操作命令是上一层（设备无关软件层）的活。两句话很像，区别在「系统调用参数」和「抽象 I/O 请求」的层次不同——5.1 习题第 16、17 题正是拿这一点设的坑。

## KP58 设备驱动程序的五个特点（真题）

**真题**：2022 考过设备驱动程序的特点。

**核心结论**：相比普通应用程序和系统程序，驱动程序有五个特点：

| 特点 | 说明 |
| --- | --- |
| ① 双向转换 | 在抽象 I/O 请求与具体设备操作之间**双向**转换，并把设备状态及完成情况反馈给请求进程 |
| ② 与 I/O 控制方式紧密相关 | 实现方式取决于设备采用中断驱动还是 DMA 等 |
| ③ 一类设备一个专用驱动 | 直接操作硬件，**不同类型的设备必须配备相应的专用驱动程序** |
| ④ 部分功能可能在固件/ROM 中 | 部分底层驱动功能由设备固件或系统 ROM 提供 |
| ⑤ 应设计为**可重入**的 | 以支持多个进程对同一设备的**并发调用** |

统一驱动接口的三点要求：① 所有驱动与内核之间遵循**相同或相近的接口规范**；② 通过设备管理模块把**逻辑设备名映射为物理设备名**并定位驱动入口；③ 对设备访问实施**权限控制**，防止未授权使用。

**易错点**：**按设备类型配驱动，不是按设备台数**（5.1 习题第 15 题：2 台绘图机 + 3 台打印机只需 **2** 个驱动程序）。特点③的「不同类型」三个字是考点。

**易错点**：**可重入**是驱动程序的必备属性，理由是多进程可能并发调用同一设备的驱动。这条常被漏掉。

## KP59 内核缓冲区与用户缓冲区

**核心结论**：两个地址空间**相互隔离**——内核空间存放操作系统代码和数据、供所有进程共享；用户程序运行在用户空间。由于系统调用在**内核态**执行，数据必须走两跳：

```
I/O 设备 →（第一跳）→ 内核缓冲区 →（第二跳，系统调用返回前）→ 用户缓冲区
```

**易错点（真题落点）**：两跳分别由**不同层次**完成：

| 跳 | 谁做 | 为什么 |
| --- | --- | --- |
| I/O 端口 → 内核缓冲区 | **设备驱动程序** | 需要**直接操作 I/O 端口**，与硬件相关 |
| 内核缓冲区 → 用户缓冲区 | **设备无关的 I/O 软件层** | **不依赖具体硬件** |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-18.jpg]]（图 5.18 数据的流向）

**易错点**：数据**不能**从 I/O 设备直接进用户缓冲区。原因就是系统调用运行在内核态，必须先落内核缓冲区。

## KP60 scanf 的两阶段执行过程

**核心结论**：以 `scanf("%c", &d)` 为例，分两个阶段：

**第一阶段（在 C 标准库中，用户空间）**：

```
① 检查与 scanf() 关联的用户缓冲区 buf
      buf 中已有数据 → 直接读取，不进内核
      buf 为空       → 触发 read 系统调用，从内核缓冲区读数据
② 执行 read 系统调用，在 trap 指令前传入三个参数：
      fd    ：文件描述符，标识输入设备（此处为标准输入）
      buf   ：用户空间缓冲区，接收从内核复制来的数据
      count ：期望读取的最大字节数
```

**第二阶段（系统调用，在内核中）**：read 通过一段含**陷阱指令**的代码使 CPU 从用户态陷入内核态，执行系统调用服务例程。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-16.jpg]]（图 5.16 系统调用的大致过程）

**易错点**：`buf` 是 **C 标准库在用户空间管理**的缓冲区，不是内核缓冲区。库缓冲区里有数据时**根本不发系统调用**——这就是为什么 scanf 不是每次都陷入内核。

## KP61 中断驱动方式下系统调用服务例程的七步

**核心结论**：进入内核态后，服务例程访问内核缓冲区并转至驱动层，七步走完：

```
① 设置 I/O 参数后，发起 I/O 的进程 P 进入阻塞态，CPU 调度其他进程运行
② 用户敲键盘，字符送入键盘 I/O 接口的数据端口
③ 键盘 I/O 接口向 CPU 发出中断请求
④ CPU 响应中断，执行键盘中断处理程序，读取字符并从 I/O 端口送入内核缓冲区
⑤ 进程 P 被唤醒，加入就绪队列，等待调度
⑥ 进程 P 再次获得 CPU 后，服务例程把字符从内核缓冲区复制到用户缓冲区
⑦ 进程 P 从系统调用返回，scanf() 解析缓冲区字符，最终存入变量 d
```

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-17.jpg]]（图 5.17 整个 I/O 操作的工作流程）

**易错点**：第⑤步唤醒后进入的是**就绪态**，不是直接运行——还要**等调度**（第⑥步）。真题常在「唤醒后立即继续执行」上设错。

**易错点**：第⑥步的复制发生在进程 P **重新拿到 CPU 之后**，因为这段复制是在进程 P 的上下文里、由系统调用服务例程完成的，不是中断处理程序干的。中断处理程序只负责第④步（端口 → 内核缓冲区）。

## KP62 本节小结：缓冲技术与设备独立性

**核心结论**：本节开头两个思考题的答案：

**1）处理机与外设速度差距大怎么解决？** 采用**缓冲技术**——在主存中设立一片缓冲区，外设与 CPU 的输入/输出都经过该缓冲区，减少相互等待，提高系统效率。

**2）什么是设备独立性？好处是什么？** 设备独立性指**应用程序使用逻辑设备名进行 I/O，无须指定具体物理设备**，由操作系统在运行时把逻辑设备名**动态映射**到实际可用的物理设备。三个好处：

| 好处 | 说明 |
| --- | --- |
| ① 简化编程 | 屏蔽底层硬件细节 |
| ② 提高可移植性 | 同一程序能在不同硬件配置的系统上运行 |
| ③ 提升灵活性 | 支持 **I/O 重定向**与设备动态绑定，提高资源利用率 |

**易错点**：设备独立性的关键词是「**逻辑设备名 + 运行时动态映射**」，落地机制是 **LUT**（KP52）。答题时把「概念 + 好处 + 实现机制」三层都带上才完整。

## KP63 磁道与扇区：磁盘寻址的最小物理单位

**核心结论**：磁盘用**磁头**（一个导体线圈）读/写数据，读/写时盘片高速旋转、磁头沿径向移动定位。

| 概念 | 说明 |
| --- | --- |
| 磁道 | 盘面上的一组**同心圆**，宽度与磁头相当，一个盘面上千个磁道 |
| 扇区 | 磁道再划分成数百个扇区，每个扇区大小固定（如 1KB），是**磁盘寻址的最小物理单位** |
| 间隙 | 相邻磁道之间、相邻扇区之间都留有间隙，避免读/写干扰 |

**核心结论（易错重点）**：传统设计里**每个磁道的扇区数相同**，外道周长大，所以外道的**线性存储密度低于内道**，整块磁盘的存储能力被**最内道的最大存储密度**卡住。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-19.jpg]]（图 5.19 磁盘盘片）

**易错点**：最小**寻址**单位是扇区，不是字节也不是簇。簇是文件系统的**分配**单位（KP70），两者别混。

**易错点**：「外道密度低」不等于「外道存的少」。传统磁盘外道扇区数与内道一样多，所以外道存的**一样多**，只是密度低、浪费了外圈空间。

## KP64 区域记录（ZBR）技术

**核心结论**：为了不浪费外层磁道，现代磁盘用**区域记录（ZBR）**：把盘面划成若干**环带**，同一环带内所有磁道扇区数相同，**外层环带的磁道扇区数多于内层环带**。

**易错点**：ZBR 是「分环带、环带内相同、环带间不同」，不是「每个磁道都不同」。

**易错点**：一旦题目说采用 ZBR，「每磁道扇区数」就不再是常量，容量不能再用「柱面数 × 盘面数 × 每道扇区数」一把乘完。

## KP65 柱面、盘组与磁盘容量的计算（真题）

**真题**：2019 考过磁盘容量的计算。

**核心结论**：多个盘片垂直堆叠成**盘组**，每个盘面对应一个磁头，所有磁头装在**同一磁头臂**上、**同步径向移动**；所有盘片上**半径相同**的磁道构成一个**柱面**。

```
柱面数   = 每个盘面的磁道数
磁头数   = 盘面数
容量 = 柱面数 × 盘面数 × 每磁道扇区数 × 扇区大小
```

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-20.jpg]]（图 5.20 磁盘的结构）

**易错点**：**柱面数 = 单面磁道数**，不是「磁道总数」。总磁道数 = 柱面数 × 盘面数。

**易错点**：一个盘片有**两个**盘面，题目给「盘片数」时盘面数要乘 2（除非明确说单面可用）。

**易错点**：所有磁头**同步移动**，不能各自去不同柱面。这是「同柱面优先存放」能省寻道时间的根因（KP90）。

## KP66 磁盘地址与读/写一个数据块的三步（真题）

**真题**：2019 考过把簇号转化为磁盘物理地址的过程。

**核心结论**：磁盘地址表示为「**柱面号 · 盘面号 · 扇区号**」。读/写一个数据块分三步：

| 步 | 动作 | 对应时间 |
| --- | --- | --- |
| ① 按**柱面号**移动磁头臂，把磁头定位到目标柱面 | 机械移动 | 寻道时间 $T_s$ |
| ② 按**盘面号**激活对应盘面的磁头 | 电子切换 | 几乎为 0 |
| ③ 等目标**扇区**随盘片转到磁头下方，完成读/写 | 旋转 + 传输 | $T_r + T_t$ |

**核心结论（易错重点）**：地址三段的顺序**柱面号在最前**，正是因为换柱面最贵、换盘面几乎免费。所以连续数据应「先填满一个柱面的所有盘面，再换柱面」。

**易错点**：第 ② 步**不移动磁头臂**，只是选中哪个磁头，不产生寻道时间。很多人误以为换盘面也要寻道。

**易错点**：地址不是「盘面号 · 柱面号 · 扇区号」。写反了整道大题的地址换算全错。

## KP67 磁盘的四种分类与温彻斯特磁盘

**核心结论**：按结构分四类，两两成对：

| 分类维度 | 类型 | 特征 |
| --- | --- | --- |
| 磁头能否移动 | 固定头磁盘 | **每个磁道一个磁头**，磁头位置固定，不需寻道 |
| | 活动头磁盘 | 磁头沿径向移动，靠磁头臂定位到目标磁道 |
| 盘片能否更换 | 固定盘磁盘 | 盘片永久密封在驱动器内，不可拆卸 |
| | 可换盘磁盘 | 盘片可拆卸、可更换 |

**核心结论**：**温彻斯特磁盘（温盘）** = IBM 1973 年推出 = **活动磁头 + 固定盘片**，是现代机械硬盘的雏形。

**易错点**：温盘是「活动头 + 固定盘」，不是「固定头」。名字里的「固定」指**盘片固定**。

**易错点**：只有**活动头**磁盘才有寻道时间。固定头磁盘每道一个磁头，$T_s = 0$。

## KP68 低级格式化（物理格式化）（真题）

**真题**：2017、2021 考过物理格式化的内容。

**核心结论**：新磁盘只是涂了磁性材料的空白盘，必须先**划分扇区**，磁盘控制器才能读/写，这一步叫**低级格式化（物理格式化）**。每个扇区被格式化成三段：

| 段 | 内容 |
| --- | --- |
| 头部 | 磁盘控制器用的信息，含**磁道号、磁头号、扇区号**（标志一个扇区） |
| 数据区域 | 真正存数据，大小可在物理格式化时指定，常见 256B / 512B / 4KB |
| 尾部 | 含 **CRC 校验字段**，对扇区做校验 |

**核心结论**：大多数磁盘**出厂时已完成低级格式化**，厂商借此测试磁盘，并建立**逻辑块地址到物理扇区的初始映射**。

**易错点**：**划分扇区 + 写头/尾 + CRC 是物理格式化；建立文件系统是逻辑格式化**。这是 2017、2021 的送分/送命点。

**易错点**：扇区数据区大小是**物理格式化**时定的，不是逻辑格式化时定的。逻辑格式化只是把若干扇区凑成簇。

## KP69 分区与逻辑格式化（高级格式化）（真题）

**真题**：2017、2021 考过逻辑格式化的内容。

**核心结论**：物理格式化之后，存文件前还要两步：

| 步 | 名称 | 做什么 |
| --- | --- | --- |
| 第一步 | **分区** | 把磁盘划成若干逻辑区域（C 盘、D 盘），每个分区的**起始位置和大小记在 MBR 的分区表**里 |
| 第二步 | **逻辑格式化（高级格式化）** | 在分区上**建立文件系统**：初始化根目录、创建管理空闲与已分配空间的数据结构、把初始目录置空 |

**易错点**：逻辑格式化的三件事——**根目录、空闲空间管理数据结构（位示图/空闲链表等）、目录置空**——都是「建文件系统」，一个都不涉及划扇区。

**易错点**：分区表在 **MBR** 里，不在每个分区的引导扇区里。引导扇区是分区自己的第一个扇区（KP72）。

## KP70 簇：为什么以簇为分配单位

**核心结论**：扇区太小，为提高 I/O 效率，操作系统把**多个连续扇区**组合成一**簇**（文件系统中也称**块**）。为简化管理，通常**一簇只分配给一个文件**。

**核心结论（易错重点）**：因此文件占用空间是**簇的整数倍**；即使文件只有 1 字节、**甚至 0 字节，也要占一整簇**。

**易错点**：「文件大小」和「文件占用空间」是两个数。求磁盘浪费/内部碎片时用的是后者。

**易错点**：以簇为单位分配还能**降低磁头平均移动距离**（KP85 第 5 条），不只是为了减少表项数量。

## KP71 引导块与自举程序

**核心结论**：开机要先跑一个初始化程序，叫**自举程序**：初始化 CPU、寄存器、设备控制器和内存，然后**定位磁盘上的内核 → 载入内存 → 跳转到入口地址**，操作系统开始执行。

**核心结论（易错重点）**：自举程序的存放采用**两级**结构：

```
ROM 中：只放一个小型自举装入程序（bootstrap loader）
          ↓ 指示磁盘控制器把引导块读入内存并执行
磁盘固定位置的引导块：放功能完整的引导程序
          ↓
从指定位置加载操作系统内核并启动
```

**核心结论**：这样设计的原因是——**改自举代码不必换 ROM 硬件**。含有引导块的磁盘称为**启动磁盘**或**系统磁盘**。

**易错点**：ROM 里放的是**小型**装入程序，完整引导程序在**磁盘引导块**里。答「自举程序全在 ROM 中」是错的。

**易错点**：引导块位于磁盘的**固定位置**，不能像普通文件那样靠目录查找——因为此时文件系统还没起来。

## KP72 Windows 的引导过程：MBR 与引导扇区

**核心结论**：以 Windows 为例，磁盘可分多个分区，其中**活动分区（引导分区）**含操作系统核心文件。

```
上电 → ROM 中代码读磁盘第 0 号扇区，即 MBR（主引导记录）
        MBR = 引导代码 + 分区表 + 一个标志位（指明从哪个分区引导）
     → 读该分区的首扇区（称引导扇区）
     → 继续后续引导：加载系统服务与驱动程序
```

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-21.jpg]]（图 5.21 Windows 磁盘的引导）

**易错点**：MBR 在**整个磁盘的 0 号扇区**（全盘唯一）；**引导扇区在活动分区的第一个扇区**（每分区一个）。两者层级不同，别答成同一个。

**易错点**：MBR 里那个**标志位**的作用是指明「从哪个分区引导」，不是校验位。

## KP73 坏块的两种处理方式

**核心结论**：磁盘有机械部件、容错弱，容易出坏扇区，有的**出厂就有**。按磁盘/控制器能力分两种处理：

| 方式 | 谁处理 | 何时发现 | 做法 | 对 OS 是否透明 |
| --- | --- | --- | --- | --- |
| **软件标记** | 操作系统 | **逻辑格式化**时检测 | 如 MS-DOS 的 Format 命令识别坏扇区，在 **FAT 表中标记为不可用** | 不透明，OS 知道 |
| **扇区备用**（硬件重映射） | 磁盘控制器 | 出厂低级格式化时初始化坏块列表，使用中动态更新 | 低级格式化预留**备用扇区**，发现坏块自动映射过去 | **对操作系统透明** |

**核心结论**：坏块处理的核心思想一句话——**通过软件标记或硬件重映射，确保系统不会使用坏块**。

**易错点**：扇区备用**对操作系统透明**，所以 OS 看到的容量不变、逻辑地址不变，是控制器偷偷换的。

**易错点**：IDE 这类简单磁盘由 **OS** 管坏块；现代复杂磁盘由**控制器**管。问「谁维护坏块列表」答控制器。

## KP74 一次磁盘存取时间的三部分与公式（真题高频，必会算）

**核心结论（易错重点）**：一次磁盘读/写时间 = **寻道时间 + 旋转延迟 + 传输时间**。

| 部分 | 公式 | 含义与典型值 |
| --- | --- | --- |
| 寻道时间 $T_s$ | $T_s = mn + s$ | 磁头移到目标磁道。$m$ = 跨一条磁道时间（约 0.2ms），$n$ = 跨越磁道数，$s$ = 磁头臂启动时间（约 2ms） |
| 旋转延迟 $T_r$ | $T_r = 1/(2r)$ | 目标扇区转到磁头下方的**平均**等待时间，即**半圈**。5400 转/分 → 一圈 11.1ms → $T_r \approx 5.56$ms |
| 传输时间 $T_t$ | $T_t = b/(rN)$ | 读/写 $b$ 字节。$N$ = 每磁道字节数，$r$ = 每秒转数 |

$$T_a = T_s + \frac{1}{2r} + \frac{b}{rN}$$

**核心结论**：**寻道时间占主导**，且直接受调度算法影响；旋转延迟与传输时间都与**转速成反比**，属硬件参数，操作系统层面优化不了。**所以磁盘调度的主要目标是减少平均寻道时间**。

**易错点**：$T_r$ 里的 $1/2$ 是「平均转半圈」。题目若给「转一圈 10ms」，平均旋转延迟是 **5ms** 不是 10ms。

**易错点**：$r$ 在公式里是**每秒**转数。题目给「5400 转/分」要先除 60。

**易错点**：$T_t = b/(rN)$ 里 $rN$ 是**每秒传输的字节数**（传输速率）。所以传输时间 = 数据量 ÷ 传输率，别去乘转速。

**易错点**：$T_s$ 别忘了**启动时间 $s$**。只算 $mn$ 是常见丢分点。

## KP75 FCFS 算法

**核心结论**：按进程**请求访问磁盘的先后顺序**调度，最简单。优点是**公平**；请求少且扇区位置聚集时性能尚可；大量进程竞争时磁头**频繁长距离移动**，效率低。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-22.jpg]]（图 5.22 FCFS 算法）

**教材例题**：请求队列 55, 58, 39, 18, 90, 160, 150, 38, 184，磁头初始在 100。

| 项 | 值 |
| --- | --- |
| 访问顺序 | 100 → 55 → 58 → 39 → 18 → 90 → 160 → 150 → 38 → 184 |
| 逐段移动 | 45 + 3 + 19 + 21 + 72 + 70 + 10 + 112 + 146 |
| 总移动磁道数 | **498** |
| 平均寻道长度 | 498 / 9 = **55.3** |

**易错点**：平均寻道长度的分母是**请求数 9**，不是访问序列的 10 个点、也不是移动段数以外的别的数。

## KP76 SSTF 算法（真题）

**真题**：2019、2021 考过 SSTF 算法的应用。

**核心结论**：每次选**距离当前磁头位置最近**的请求，使**单次寻道时间最短**。性能通常优于 FCFS，但**不能保证平均寻道时间最小**，且可能**饥饿**。

**核心结论**：饥饿场景——磁头在 18 号磁道附近，若附近持续来新请求，磁头就长期在 18 附近来回，远处（如 184）长时间得不到服务。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-23.jpg]]（图 5.23 SSTF 算法）

**教材例题**：同一队列，磁头在 100。

| 项 | 值 |
| --- | --- |
| 访问顺序 | 100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184 |
| 逐段移动 | 10 + 32 + 3 + 16 + 1 + 20 + 132 + 10 + 24 |
| 总移动磁道数 | **248** |
| 平均寻道长度 | 248 / 9 = **27.5** |

**易错点**：SSTF **只保证每一步最短，不保证全程最短**。「SSTF 使平均寻道时间最短」是错的。

**易错点**：SSTF 与 SCAN 的区别在**有没有方向约束**。SSTF 可以随时折返（例题中 18 之后直接跳 150），SCAN 不行。

## KP77 SCAN 算法（真题高频）

**真题**：2009、2010、2015 考过 SCAN 算法的应用。

**核心结论**：在 SSTF 基础上**加方向约束**：磁头**到达最外侧磁道后才转向内侧**，**到达最内侧磁道后才转向外侧**。行为像电梯，故又称**电梯调度算法**。

| 优点 | 缺点 |
| --- | --- |
| 寻道性能好，**避免饥饿** | 对**刚扫描过**的区域不公平，访问局部性方面不如 FCFS 和 SSTF |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-24.jpg]]（图 5.24 SCAN 算法）

**教材例题**：同一队列，磁头在 100，**沿磁道号增大方向**移动（磁盘共 200 道）。

| 项 | 值 |
| --- | --- |
| 访问顺序 | 100, 150, 160, 184, **200**, 90, 58, 55, 39, 38, 18 |
| 逐段移动 | 50 + 10 + 24 + 16 + 110 + 32 + 3 + 16 + 1 + 20 |
| 总移动磁道数 | **282** |
| 平均寻道长度 | 282 / 9 = **31.33** |

**易错点**：**用 SCAN 必须先知道磁头移动方向**，题目没说就得讨论/按题意假定。方向反了答案全变。

**易错点**：严格 SCAN 要**走到物理端点 200（或 0）**才折返，所以 184 → 200 → 90 这段 110 个磁道要算进去。只走到 184 就折返的是 **LOOK**（KP79）。

## KP78 C-SCAN 算法（真题）

**真题**：2024 考过 C-SCAN 算法的应用。

**核心结论**：在 SCAN 基础上规定：**只沿单一方向移动并提供服务**，返回时**快速移到起始端且不处理任何请求**。

**核心结论**：动机——SCAN 倾向于优先服务靠近最内/最外侧的请求，导致**中间区域响应延迟大**；C-SCAN 把回扫变成**非服务性的快速跳转**，循环均匀处理所有请求，**消除了对两端磁道请求的不公平性**。

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-25.jpg]]（图 5.25 C-SCAN 算法）

**教材例题**：同一队列，磁头在 100，沿磁道号增大方向。

| 项 | 值 |
| --- | --- |
| 访问顺序 | 100, 150, 160, 184, **200, 0**, 18, 38, 39, 55, 58, 90 |
| 逐段移动 | 50 + 10 + 24 + 16 + **200** + 18 + 20 + 1 + 16 + 3 + 32 |
| 总移动磁道数 | **390** |
| 平均寻道长度 | 390 / 9 = **43.33** |

**易错点**：那段 **200 → 0 的回扫要计入总移动磁道数**，只是路上不服务任何请求。漏掉这 200 是最常见的算错。

**易错点**：C-SCAN 的总移动距离**通常大于** SCAN（390 > 282），它换来的是公平性，不是效率。

## KP80 同一请求序列下四种算法的对比（必会算）

**核心结论**：教材四个例题用的是**同一组数据**，横着背下来能直接判断选项合理性。队列 55, 58, 39, 18, 90, 160, 150, 38, 184，磁头初始 100，磁盘 0～200 道，方向为磁道号增大。

## KP81 四种磁盘调度算法的优缺点（真题）

**真题**：2010、2018 考过各种磁盘调度算法的比较。

**核心结论**：表 5.2：

| --- | --- | --- |

## KP82 磁臂黏着：NStepSCAN 与 FSCAN

**核心结论**：**磁臂黏着**——当一个或多个进程**频繁发出对某个磁道**的 I/O 请求时，磁头长期滞留该区域，其他进程难以获得服务。**SSTF、SCAN、C-SCAN 在特定情况下都可能出现**。

| 算法 | 做法 | 关键点 |
| --- | --- | --- |
| **NStepSCAN** | 把请求队列分成若干长度为 $N$ 的子队列；**子队列之间按 FCFS**、**子队列内部按 SCAN** | 处理某子队列期间**新到的请求放入尚未处理的其他子队列**，绝不插入当前正在服务的子队列 |
| **FSCAN** | NStepSCAN 的简化：**固定分成两个**子队列——① 当前服务队列（调度开始时已存在的请求，按 SCAN 处理）；② 新请求队列（本轮新到的全部暂存，推迟到下一轮扫描） | 「冻结当前、延后新请求」，实现简单、开销低 |

**核心结论（易错重点）**：NStepSCAN 的两个端点行为：$N$ **很大** → 趋近 **SCAN**；$N = 1$ → 每个子队列只含一个请求，**退化为 FCFS**。

**易错点**：避免磁臂黏着的关键机制是「**新请求不许插进当前正在服务的队列**」，不是「限制磁头方向」。

**易错点**：$N=1$ 退化成 **FCFS**，不是 SSTF。记反了是常见坑。

## KP83 减少旋转延迟之一：扇区的交替编号

**核心结论**：磁盘连续旋转，磁头读完一个扇区后系统需要**处理时间**才能读下一个。若逻辑相邻的块**物理上也紧邻**，处理期间下一个目标扇区已转过磁头，只能**再等近一整圈**。

**核心结论**：对策——**同一盘面的扇区采用交替编号**，让逻辑相邻的块在物理布局上**保持适当间隔**，处理完一个扇区后下一个目标扇区正好转到磁头下方。

教材图示：[[王道教材/27 王道操作系统/pictures/5-3-image-032.jpg]]（图 5.28(a) 连续编号）、[[王道教材/27 王道操作系统/pictures/5-3-image-033.jpg]]（图 5.28(b) 交替编号，盘面 8 个扇区）

**易错点**：交替编号解决的是**旋转延迟**，不是寻道时间。它没让磁头少走路，只是让扇区「按时到站」。

**易错点**：交替编号发生在**同一个盘面内部**。跨盘面的对应问题用错位命名（KP84）。

## KP84 减少旋转延迟之二：盘面的错位命名

**核心结论**：所有盘面**同步旋转**，同一柱面内的块按盘面顺序连续存放：

```
盘面0扇区0, 盘面0扇区1, …, 盘面0扇区7,
盘面1扇区0, …, 盘面1扇区7,
盘面2扇区0, …
```

读完盘面 0 扇区 7 后仍需处理时间，期间盘面继续转，下一个目标块（盘面 1 扇区 0）**已被磁头错过**，只能等下一圈。

**核心结论**：对策——不同盘面**错位命名**（在已采用交替编号的基础上），使处理完盘面 0 扇区 7 后，盘面 1 扇区 0 **恰好或即将**到达磁头位置，首次经过即可读取。

教材图示：[[王道教材/27 王道操作系统/pictures/image-034.jpg]]、[[王道教材/27 王道操作系统/pictures/image-035.jpg]]（图 5.29(a) 普通命名，0 号 / 1 号盘面）、[[王道教材/27 王道操作系统/pictures/5-3-image-036.jpg]]、[[王道教材/27 王道操作系统/pictures/image-037.jpg]]（图 5.29(b) 错位命名，0 号 / 1 号盘面）

**核心结论（易错重点）**：三部分时间的性质划分——**寻道时间和旋转延迟属于「找」的时间**，可用调度算法或布局优化降低；**传输时间由磁盘本身特性决定**，软件手段难以减少。

**易错点**：错位命名的前提是**盘面同步旋转 + 已做交替编号**，两个盘面之间是「整体转过一个角度」，不是把扇区号随便打乱。

## KP85 提高磁盘 I/O 速度的七种方法（真题）

**真题**：2012、2018 考过改善磁盘 I/O 性能的方法。

**核心结论**：文件访问速度是文件系统性能最重要的因素，可从三方面优化：① 改进目录结构和检索方法（第 4 章）；② 选好文件存储结构（第 4 章）；③ **提高磁盘 I/O 速度**（本节）。

| # | 方法 | 要点 |
| --- | --- | --- |
| 1 | **磁盘高速缓存** | 见 KP40（5.2.2） |
| 2 | **调整磁盘请求顺序** | 即各种磁盘调度算法 |
| 3 | **提前读** | 读当前块的同时，把逻辑上紧随其后的下一个（或多个）块**预读**到内存缓冲区 |
| 4 | **延迟写** | 修改缓冲区数据时不立即写盘，只设**延迟写标志**；等该缓冲区**被替换**时才真正写入，从而合并多次写、减少 I/O 次数 |
| 5 | **优化物理块的分布** | 扇区编号优化（KP83、KP84）；链接/索引文件的块尽量安排在**同一磁道或相邻磁道**；若干连续扇区组成**簇**并以簇为单位分配 |
| 6 | **虚拟盘（RAM 盘）** | 用内存空间仿真磁盘，存临时文件或对 I/O 延迟敏感的数据 |
| 7 | **磁盘阵列 RAID** | 某些 RAID 级别支持**交叉存取**，大幅提高 I/O 速度 |

**核心结论（易错重点）**：**虚拟盘 vs 磁盘高速缓存**——虚拟盘的内容**完全由用户程序控制**；磁盘高速缓存的内容由**操作系统透明管理**。

**易错点**：延迟写是在**缓冲区被替换时**才写盘，不是「定时写」也不是「关机才写」。

**易错点**：提前读的依据是**逻辑上紧随其后**（顺序访问局部性），不是「最近最常访问」。

## KP86 固态硬盘的组成：闪存芯片与闪存翻译层（真题）

**真题**：2025 考过机械磁盘与固态硬盘的对比。

**核心结论**：SSD 基于**闪存**技术，介质与 U 盘类似但容量更大、性能更优。一个 SSD = **一个或多个闪存芯片 + 闪存翻译层**。

| 部件 | 对应机械磁盘中的 | 职责 |
| --- | --- | --- |
| 闪存芯片 | **机械驱动器** | 存数据 |
| **闪存翻译层** | **磁盘控制器** | 把 CPU 发来的**逻辑块**读/写请求转换为对底层**物理闪存**的读/写控制信号 |

教材图示：[[王道教材/27 王道操作系统/pictures/fig-5-30.jpg]]（图 5.30 固态硬盘（SSD））

**易错点**：闪存翻译层替代的是**磁盘控制器**，不是驱动程序、也不是文件系统。这个对应关系是选择题原句。

## KP87 SSD 的块/页参数与「读写以页、擦除以块」

**核心结论（易错重点）**：一个闪存芯片由 **B 块**组成，每块含 **P 页**。**读/写以页为单位，擦除以块为单位**；**只有整块被擦除后，才能向其中的页写入新数据**；一旦某块被擦除，其所有页均可**重新写入一次**。

| 参数 | 范围 |
| --- | --- |
| 页大小 | 512B ～ 4KB |
| 每块页数 | 32 ～ 128 页 |
| 块大小 | 16KB ～ 512KB |

**核心结论**：每个块的**擦写次数有限**，重复写入若干次后该块因磨损而失效。

**易错点**：**页可写、块才可擦**。答「擦除以页为单位」直接错。

**易错点**：写不能原地覆盖——要改一个已写过的页，必须走整块搬移流程（KP88）。

## KP88 SSD 随机写慢的两个原因与相对磁盘的优势（真题）

**真题**：2025 考过机械磁盘与固态硬盘的对比。

**核心结论（易错重点）**：SSD **随机写入速度较慢**，两个原因：

| # | 原因 |
| --- | --- |
| ① | **擦除操作耗时长**，通常比页访问**慢一个数量级** |
| ② | 若要修改一个**已含有效数据**的页 $P_i$，必须先把该块中**所有有效页复制到一个新的（已擦除的）块**，再执行对 $P_i$ 的写入 |

**核心结论**：相比机械磁盘的优势——由半导体器件构成、**无机械运动部件**，因此：**随机访问延迟极低、无噪声、无振动、功耗更低、抗震性强、安全性更高**。

**易错点**：SSD 慢的是**随机写**，随机**读**很快。混成「SSD 随机访问慢」就把优势说反了。

**易错点**：原因 ② 是「**先搬走整块的有效页，再写**」，这是写放大的来源。答「直接覆盖」是错的。

## KP89 磨损均衡：动态与静态

**核心结论**：SSD 的主要缺点是闪存**擦写寿命有限**（通常几百至几千次）。若不加管理，读/写会集中在少数物理块上迅速磨损，**一块 256GB 的 SSD 可能仅因几兆字节的闪存损坏而报废**。对策是**磨损均衡**：

| 类型 | 时机 | 做法 |
| --- | --- | --- |
| **动态**磨损均衡 | **写入数据时** | 优先选择**擦写次数较少的空闲块**，把写入负载分散到更多物理块 |
| **静态**磨损均衡 | **即使没有新数据写入**，控制器**定期扫描**并自动迁移 | 把**高磨损块中的有效数据迁到低磨损块**，使高磨损块转为**以读为主**，低磨损块承担更多写入 |

**核心结论**：效果——256GB 的 SSD、擦写寿命 500 次，理论总写入量 125TB；即使每天写 10GB，也需三十多年才到寿命极限。

**易错点**：**动态看「写的时候挑块」，静态看「不写也搬数据」**。判据是「有没有新写入」。

**易错点**：静态磨损均衡搬的是**有效数据**，目的是让高磨损块空出来只读，不是为了整理碎片。

## KP90 本节小结

**核心结论**：回答本节开头两个问题。

**1）磁盘一次读/写操作包含哪几部分时间？其中哪部分最长？** 三部分：

| 时间 | 含义 |
| --- | --- |
| **寻道时间** | 把磁头臂移动到指定磁道 |
| **旋转延迟** | 等目标扇区旋转到磁头下方 |
| **传输时间** | 实际读出或写入数据 |

由于磁头臂是**机械运动**、较慢，**寻道时间通常最长**。

**2）一个磁道容纳不下时，剩余数据放同一盘面的不同磁道，还是同一柱面的不同盘面？** 放**同一柱面的不同盘面**。

```
同一柱面的各磁道半径相同
   → 切换盘面只需选择对应磁头
   → 无须移动磁头臂
   → 寻道开销为 0
换成同一盘面的不同磁道
   → 必须移动磁头臂 → 产生显著寻道延迟
```

**核心结论（易错重点）**：整节一句话——**寻道最贵，所以调度算法围着它转（KP74～KP82），布局也围着它转（同柱面优先、簇分配、相邻磁道）；旋转延迟靠编号优化（KP83、KP84）；传输时间只能靠硬件。**

**易错点**：「同柱面优先」的根因是**所有磁头同步移动、装在同一磁头臂上**（KP65），不是因为柱面容量大。
