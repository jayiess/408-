## 2026-08-31｜11｜动态重定位依赖的部件（3.1）

| 项目 | 内容 |

| 题型 | 单项选择题 |
| 正确答案 | C |
| 我的选择 | B |
| 错误类型 | 概念不清 |

**原题：动态重定位的过程依赖于（）。**

I. 可重定位装入程序　II. 重定位寄存器　III. 地址变换机构　IV. 目标程序

| 选项 | 内容 |
| --- | --- |
| A | I 和 II |
| B | II 和 III |
| C | I、II 和 III |
| D | I、II、III 和 IV |

错误原因：<span style="color: red;">只想到运行时那套硬件（重定位寄存器存基址 + 地址变换机构做加法），漏了 I——动态重定位是「动态运行时装入」这种装入方式的配套机制，装入程序是它的前提。</span>

复盘结论：按「三件事凑齐」来数：谁把程序搬进内存（**可重定位装入程序**）、谁存基址（**重定位寄存器**）、谁做加法与越界判断（**地址变换机构 / MMU**）。只有 **IV 目标程序是被重定位的对象，不是手段**，所以排除含 IV 的 D，答 C。对应 KP5。

## 2026-08-31｜12｜静态与动态重定位和程序移动（3.1）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | B |
| 我的选择 | A |
| 错误类型 | 概念不清 |

**原题：为保证一个程序在主存中被改变存放位置后仍能正确执行，应采用（）。**

| 选项 | 内容 |
| --- | --- |
| A | 静态重定位 |
| B | 动态重定位 |
| C | 动态分配 |
| D | 静态分配 |

错误原因：<span style="color: red;">被「可重定位装入」这个名字带跑，以为「能重定位就是能移动」。静态重定位是装入时把指令里的地址一次性改死，程序一搬家全部地址失效。</span>

复盘结论：见到「改变存放位置后仍能正确执行」「紧凑 / 拼接」「进程可在内存中移动」这三种说法，一律答**动态重定位**。判据是转换时机：**执行时才算（程序里留的仍是逻辑地址）才能移动**，装入时算完就钉死。C、D 是内存分配方式，和地址转换不是一个维度，属于干扰项。对应 KP5、KP11。

## 2026-08-31｜28｜页表段表本身占用物理空间（3.1）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | C |
| 我的选择 | A |
| 错误类型 | 概念不清 |

**原题：采用分页或分段管理后，提供给用户的物理地址空间为（）。**

| 选项 | 内容 |
| --- | --- |
| A | 分页支持更大的物理地址空间 |
| B | 分段支持更大的物理地址空间 |
| C | 不能确定 |
| D | 一样大 |

错误原因：<span style="color: red;">把「用户能用的物理空间」等同于「物理地址位数决定的寻址范围」，忘了页表和段表自己也住在内存里，要从总量里扣掉。</span>

复盘结论：王道口径——**提供给用户的物理空间 = 总物理内存 − 页表/段表占用**。表的长度取决于进程数、页面大小、段数，都不确定，所以只能答**不能确定**。顺带钉死一句：**页表、段表都存放在内存中**（这也是分页要两次访存、要 TLB 的根）。对应 KP19、KP26。

## 2026-08-31｜41｜主存的访问单位与分配单位（3.1）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | B |
| 我的选择 | C |
| 错误类型 | 审题错 |

**原题：对主存储器的访问，（）。**

| 选项 | 内容 |
| --- | --- |
| A | 以块（页）或段为单位 |
| B | 以字节或字为单位 |
| C | 随存储器的管理方案不同而异 |
| D | 以用户的逻辑记录为单位 |

错误原因：<span style="color: red;">把「访问」看成了「分配 / 管理」，于是觉得答案随管理方案变化。王道解析开头就点明「这里是指主存的访问，不是主存的分配」。</span>

复盘结论：**分配单位 ≠ 访问单位**。分配以页框（或分区、段）为单位，**访存永远以字节或字为单位**——这正是逻辑地址除了页号还必须带页内偏移的原因。题干出现「访问 / 存取主存」一律答字节或字，与管理方案无关。对应 KP16、KP20。

## 2026-08-31｜45｜段页式无快表的访存次数（3.1）

| --- | --- |

| 正确答案 | B |
| 我的选择 | C |
| 错误类型 | 记忆遗漏 |

**原题：在段页式分配中，CPU 每次从内存中取一次数据需要（）次访问内存。**

| 选项 | 内容 |
| --- | --- |
| A | 1 |
| B | 3 |
| C | 2 |
| D | 4 |

错误原因：<span style="color: red;">按分页的「查页表 + 取数 = 2 次」套了上去，漏掉段页式要先查段表拿到页表始址这一步。</span>

复盘结论：无快表时按「**查几张表 + 最后 1 次取数**」数：

| 方式 | 访存次数 |
| --- | --- |
| 单级页表 | 2 |
| 二级页表 | 3 |
| 分段 | 2 |
| **段页式** | **3**（段表 → 页表 → 数据） |
| $n$ 级页表 | $n+1$ |

## 2026-08-31｜48｜页表驻留内存与页表寄存器（3.1）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | A |
| 我的选择 | B |
| 错误类型 | 概念不清 |

**原题：操作系统采用分页存储管理方式，要求（）。**

| 选项 | 内容 |
| --- | --- |
| A | 每个进程拥有一张页表，且进程的页表驻留在内存中 |
| B | 每个进程拥有一张页表，但只有执行进程的页表驻留在内存中 |
| C | 所有进程共享一张页表，以节约有限的内存空间，但页表必须驻留在内存中 |
| D | 所有进程共享一张页表，只有页表中当前使用的页面必须驻留在内存中 |

错误原因：<span style="color: red;">把「只有一个页表寄存器 PTR、只把当前进程的页表始址装进 PTR」误推成「只有当前进程的页表留在内存」。</span>

复盘结论：三样东西分清楚——

| 东西 | 在哪 | 有几份 |
| --- | --- | --- |
| **页表本身** | **内存** | 每进程一张，**都驻留** |
| 页表**始址 + 长度** | 进程不运行时在 **PCB** | 每进程一份 |
| **页表寄存器 PTR** | CPU | 单 CPU **通常只有一个**，装当前进程的 |

**寄存器只有一个，不代表内存里只留一张页表**。C、D 的「所有进程共享一张页表」直接违背「每个进程有独立逻辑地址空间」，一眼排除。对应 KP19、KP20。

**原题：下列关于段式存储管理的叙述中，错误的是（）。**

| 选项 | 内容 |
| --- | --- |
| A | 段是逻辑结构上相对独立的程序块，因此段是可变长的 |
| B | 按程序中实际的段来分配主存，所以分配后的存储块是可变长的 |

| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | C |
| 我的选择 | D |
| 错误类型 | 概念不清 |

**原题：【2011 统考真题】在虚拟内存管理中，地址变换机构将逻辑地址变换为物理地址，形成该逻辑地址的阶段是（）。**

| 选项 | 内容 |

| C | 链接 |
| D | 装载 |

复盘结论：**编译**产生的是各模块内部各自从 0 起的**相对地址**；**链接**把各模块拼成整个程序统一的、从 0 开始的**逻辑地址空间**（`file1.o` 原来 0～1023，接在 `main.o` 后面就变成 1024～2047）——所以「形成逻辑地址」在链接。装入及运行时才做逻辑→物理。跟 KP2 笔记那条「预处理 编译 汇编 链接 装入」正好对齐：**可执行文件在链接完成后就已带着完整逻辑地址躺在磁盘上**。对应 KP2、KP3。

## 本次共同错因

9 道题分两条线，都是「地址」这条主线上的：

**线一（11、12、41、48、63）：地址在哪个阶段形成、由谁转换、谁只是被转换的对象。** 编译给相对地址、链接给统一逻辑地址、装入或执行时转物理地址；转换靠重定位寄存器（连续分配）或页表（离散分配），执行者是硬件 MMU；目标程序、页表本身都只是对象或数据，不是执行者。41 混的是「分配 / 访问」两种单位，48 混的是「寄存器一个 / 页表多张」，本质同样是分不清角色。

**线二（28、45、50、51）：段和页各管哪一侧，以及表本身的代价。** 段面向用户（可见、变长、二维），页面向系统（透明、定长、一维）；两张表都住在内存里，既要从用户可用物理空间里扣掉，也要按「查几张表 + 1 次取数」算访存次数。

下次做 3.1 选择题，先在题干上圈出两个词：**阶段 / 角色**（谁在什么时候做）和**方向**（段管哪边、页管哪边）。这两处一圈，本次 9 道错题至少 7 道能自己排掉。

## 2026-09-04｜02｜页面尺寸与缺页次数的关系（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | B |
| 我的选择 | D |
| 错误类型 | 概念不清 |

**原题：请求分页存储管理中，若把页面尺寸增大一倍而且可容纳的最大页数不变，则在程序顺序执行时缺页中断次数会（）。**

| 选项 | 内容 |
| --- | --- |
| A | 增加 |
| B | 减少 |
| C | 不变 |
| D | 可能增加也可能减少 |

错误原因：<span style="color: red;">把这题跟 **Belady 异常**搞混了——记得「资源变多缺页反而可能变多」这种反常，于是认定不单调，选了 D。但 Belady 异常的自变量是**页框数**，本题变的是**页面尺寸**，而且页框数明确不变，两回事。</span>

复盘结论：**三个「反直觉」结论必须分开记，自变量各不相同。**

| 结论 | 自变量 | 前提 | 结果 |
| --- | --- | --- | --- |
| **Belady 异常** | 页框数 ↑ | 只发生在 **FIFO** 等非栈算法（LRU、OPT 不会） | 缺页次数**可能反而增加** |
| 页面大小与缺页率的 **U 形关系** | 页面尺寸 ↑ | **驻留内存总量固定**（页变大则页框数变少）+ 随机访问 | 太小则缺页频繁、页表大；太大则页内浪费 → **不单调** |
| **本题** | 页面尺寸 ↑ | **页框数不变** ⇒ 驻留内存量翻倍；**顺序执行** ⇒ 页内数据全用得上 | 缺页次数**单调减少** |

本题两个条件（页数不变、顺序执行）恰好把 U 形关系的两个前提都推翻了，所以答 B。以后看到「页面 / 页框 + 缺页次数」的题，先问一句：**变的是页框数还是页大小？总驻留内存量变没变？访问是顺序还是随机？算法是不是 FIFO？** 四问答完再看选项。对应 KP34、KP42、KP47。

## 2026-09-04｜09｜存储保护的基本含义（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | C |
| 我的选择 | B |
| 错误类型 | 概念不清 |

**原题：通常所说的“存储保护”的基本含义是（）。**

| 选项 | 内容 |
| --- | --- |
| A | 防止存储器硬件受损 |
| B | 防止程序在内存丢失 |
| C | 防止程序间相互越界访问 |
| D | 防止程序源码被人偷窃 |

错误原因：<span style="color: red;">把「保护」当成日常语义里的「别丢数据」，其实 OS 里的存储保护是**地址空间的隔离**，保护的是「谁能碰哪段内存」，不是「内容会不会丢」。</span>

复盘结论：存储保护 = 每次访存前，硬件拿地址跟这个进程的合法范围比一次，越界就产生**越界中断**。实现手段就是那两组东西：连续分配用**重定位寄存器 + 界地址寄存器**；离散分配用**页表 / 段表里的段长和存取权限位**。一句话记：存储保护是**访问控制**，不是**数据可靠性**。A 是硬件维护，B 是持久化，D 是加密与知识产权，都不是 OS 内存管理的事。对应 KP7、KP26。

## 2026-09-04｜18｜虚存最大容量由地址结构决定（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | D |
| 我的选择 | B |
| 错误类型 | 概念不清 |

**原题：设主存容量为 1MB，外存容量为 400MB，计算机系统的地址寄存器有 32 位，那么虚拟存储器的最大容量是（）。**

| 选项 | 内容 |
| --- | --- |
| A | 1MB |
| B | 401MB |
| C | $1\mathrm{MB}+2^{32}\mathrm{MB}$ |
| D | $2^{32}\mathrm{B}$ |

错误原因：<span style="color: red;">用了「虚存 = 内存 + 外存」这个错误直觉，把 1MB 和 400MB 加起来选 B。这是把「虚存的上限」跟「当前实际能装多少」混为一谈。</span>

复盘结论：分清三个量——**最大容量由地址结构（地址寄存器位数）唯一决定**，本题 32 位 ⇒ $2^{32}\mathrm{B}$；**实际容量**受内存 + 外存之和限制；**运行时装了多少**由驻留集决定。所以 401MB 是「实际容量」的量级，不是「最大容量」。反例记牢：64 位机上进程虚拟地址空间 $2^{64}\mathrm{B}$，外存根本不可能这么大。看到「虚拟存储器最大容量」，眼睛只需要找地址位数。对应 KP33。

| D | 需维护访问历史并遍历查找 |

错误原因：<span style="color: red;">因果倒置。记住的是「LRU 需要硬件支持」这句话，就顺手选了 A；但硬件支持是**为了消掉软件开销才引入的手段**，不是开销高的原因。</span>

复盘结论：把这条因果链摆正：**LRU 语义要求知道每页最后一次被访问的时刻 → 纯软件实现就得给每个驻留页维护访问历史，缺页时还要遍历所有页框挑最旧的，O(n) → 开销高 → 所以才加硬件（访问时间戳寄存器 / 栈 / 引用位）**。A 在链条的下游，D 在链条的上游，题问「直接原因」就取上游。顺带对照：CLOCK 就是为了绕开这个开销而生的近似 LRU，只用一个访问位。凡是题干带「直接原因 / 根本原因」，先把因果链写出来再看选项落在哪一环。对应 KP47、KP48。

## 2026-09-04｜29｜驻留集与工作集的包含关系（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | B |
| 我的选择 | C |
| 错误类型 | 概念不清 |

**原题：下列关于驻留集和工作集的表述中，正确的是（）。**

I. 驻留集是进程已装入内存的页面的集合　II. 工作集是某段时间间隔内，进程运行所需要访问页面的集合　III. 工作集是驻留集的子集

| 选项 | 内容 |
| --- | --- |
| A | I |
| B | I、II |
| C | II、III |
| D | I、II、III |

错误原因：<span style="color: red;">选了 C，等于既漏判 I 又误判 III。III「工作集是驻留集的子集」被当成定义了，其实那是**不缺页的理想状态**，不是恒成立的关系。</span>

复盘结论：两个集合住在不同世界：**驻留集是「现在内存里实际有哪些页」（物理事实，由 OS 分配决定）；工作集是「这段时间里我要用哪些页」（访问行为，由程序局部性决定）**。所以工作集里完全可以有还没调入或已被换出的页——那正是缺页的来源。正确说法是反过来的因果：**当且仅当工作集 ⊆ 驻留集时，进程才不缺页**，这是抖动判据，也是「驻留集大小应约等于工作集大小」这条分配原则的由来。III 把结论当定义，所以错，答 B。对应 KP38。

## 2026-09-04｜44｜抖动的有效应对措施（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | A |
| 我的选择 | D |
| 错误类型 | 概念不清 |

**原题：【2011 统考真题】当系统发生抖动时，可以采取的有效措施是（）。**

I. 撤销部分进程　II. 增加磁盘交换区的容量　III. 提高用户进程的优先级

| 选项 | 内容 |
| --- | --- |
| A | 仅 I |
| B | 仅 II |
| C | 仅 III |
| D | 仅 I、II |

错误原因：<span style="color: red;">多选了 II。以为「换页换不过来」是交换区不够大，于是扩容能缓解；实际抖动的瓶颈是**物理内存装不下大家的工作集**，交换区再大也不改变这一点。</span>

复盘结论：抖动的病因只有一个——**驻留集 < 工作集**，页刚换出就又要用。所以有效措施只走两条路：**减少并发进程数（撤销 / 挂起部分进程，让活着的进程拿到够用的页框）** 或 **增加物理内存**。交换区在外存，扩容只是给换出的页多留地方，页面置换的频率一点没降，反而可能因为能容纳更多进程而加剧抖动。III 提高优先级只改变谁先跑，总的页框需求不变，同样无效。判据一句话：**能把「每个进程的页框数」抬上去的措施才有效**。对应 KP49。

## 2026-09-04｜60｜最少页框数由寻址方式决定（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | D |
| 我的选择 | C |
| 错误类型 | 记忆遗漏 |

**原题：【2025 统考真题】在页式虚拟存储管理系统中，确定进程正常运行所需的最少页框数时，下列因素中需要考虑的是（）。**

| 选项 | 内容 |
| --- | --- |
| A | 代码段长度 |
| B | 进程的虚拟地址空间大小 |
| C | 物理内存大小 |
| D | 指令系统支持的寻址方式 |

错误原因：<span style="color: red;">「最小页框数由指令系统的寻址方式决定」这条结论没提取出来，退回到常识去猜，选了物理内存大小。物理内存决定的是**最多**能给多少，不是**最少**得给多少。</span>

复盘结论：最少页框数的定义是「**能让最复杂的那条指令跑完所需的页面数**」，所以只看一条指令一次执行最多同时碰几个页面：**取指 1 页；直接寻址再 +1 页（操作数）；间接寻址再 +1 页（先取形式地址所在页，再取真操作数所在页）**。给不够就会出现「指令永远执行不完」——缺页调入把自己需要的另一页挤掉，死循环。所以答 D。A、B 决定的是进程总共多少页，C 决定的是系统能同时养多少进程，都跟「单条指令的瞬时需求」无关。对应 KP39（最小页框数表）、KP37（一条指令最多引发 6 次缺页，同一模型的另一种问法）。

## 2026-09-04｜61｜内存映射文件机制的功能边界（3.2）

| 项目 | 内容 |
| --- | --- |
| 题型 | 单项选择题 |
| 正确答案 | A |
| 我的选择 | D |
| 错误类型 | 概念不清 |

**原题：【2025 统考真题】下列关于内存映射文件（memory-mapped files）机制的叙述中，正确的是（）。**

I. 可实现进程之间的通信　II. 可实现页到磁盘块的映射　III. 将文件映射到进程的虚拟地址空间　IV. 将文件映射到系统的物理地址空间

| 选项 | 内容 |
| --- | --- |
| A | 仅 I、III |
| B | 仅 I、IV |
| C | 仅 II、III |
| D | 仅 I、II、III |

错误原因：<span style="color: red;">多选了 II。看到「文件按页换入换出」就以为「页到磁盘块的映射」是这个机制提供的功能，其实那是**虚拟存储管理本身**（页表 + 缺页中断）早就在做的事，跟有没有 mmap 无关。</span>

复盘结论：分清「这个机制做什么」和「它借用了什么」。**内存映射文件只做一件事：把文件内容挂到进程的虚拟地址空间上（III），从此读写文件变成读写内存，省掉 read/write 系统调用和一次内核缓冲区拷贝**；两个进程映射同一文件就共享同一份内核页缓存，于是顺带得到一种 IPC（I）。而「页 ↔ 磁盘块」的映射、按需调入、换出，是虚存机制的通用能力，mmap 是**使用者**不是**提供者**（II 错）。IV 更直接错：映射目标永远是**虚拟**地址空间，物理地址由 OS 动态分配且对进程透明。答 A。做这类「机制功能边界」题，先问一句「没有它的时候这件事也在发生吗」，答「是」的就不是它的功能。对应 KP53。

## 本次共同错因（2026-09-04，3.2 虚拟内存）

8 道题几乎全踩在同一类坑上：**把某个概念的「理想状态 / 配套手段 / 借用能力」当成了它的定义**。

**A 组｜因果与定义搞反（23、29、61）。** 23 把「加硬件」（下游对策）当成「开销高」（上游原因）；29 把「工作集 ⊆ 驻留集」（不缺页的理想状态）当成两者的定义关系；61 把「页到磁盘块映射」（虚存的通用能力）当成 mmap 自带的功能。统一解法：**先把因果链或依赖链写出来，再看选项落在链条的哪一环**；题干问「原因 / 含义 / 该机制提供的功能」，取的都是最上游那一环。

**B 组｜量的归属搞混（18、44、60）。** 都是「谁决定谁」。虚存**最大**容量只看地址位数（18），不是内存 + 外存；抖动只看**每进程页框数**（44），不是交换区大小；最少页框数只看**单条指令的瞬时页面需求**（60），不是物理内存或程序长度。统一解法：在题干上圈出「最大 / 最少 / 有效」这类限定词，然后问**「这个量的上限（或下限）是被哪一层硬约束卡住的」**。

**C 组｜结论张冠李戴、术语按日常语义理解（02、09）。** 02 把 **Belady 异常**（自变量是页框数）套到了「页面尺寸」上，还顺带盖过了题干锁死的「顺序执行 + 页数不变」；09 把「存储保护」按日常语义理解成「别丢数据」，而 OS 里它固定指**地址空间隔离 / 越界检查**。这两道提醒同一件事：**每条反直觉结论都要连着它的自变量和前提一起背，光记「不一定」等于没记**。

下次做 3.2 选择题，落笔前做两件事：**（1）圈限定词**——最大 / 最少 / 直接原因 / 顺序执行 / 不变；**（2）对每个「正确」的选项反问一句「没有这个东西时它也成立吗」**，成立的就划掉。这两步做到，本次 8 道至少 6 道能自己排掉。
